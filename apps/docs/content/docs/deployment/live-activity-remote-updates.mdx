title: Live Activity remote updates
description: Configure server-side updates for iOS Live Activities and Dynamic Island.
---

Live Activity remote updates let Happier update or end an existing iOS Live Activity after the app has registered a remote target with the selected server.

This is optional. Without remote updates, Live Activities still work locally while the app can update them directly.

## What this feature does

Remote updates support:

- updating an existing Live Activity
- ending an existing Live Activity
- sending an optional interruptive alert for important updates
- coalescing duplicate updates by snapshot fingerprint
- throttling background-wake fallback pushes

Remote updates do **not** currently support:

- push-to-start
- broadcast channels
- opaque hosted-relay target capability fields
- per-user APNs key storage in the database

The server configuration is environment-variable based. There is no Live Activity-only settings file or database settings model for APNs credentials.

## Modes

### Local only

`local_only` keeps Live Activity updates on the device. This is the default user preference and the safe fallback when a remote mode is unavailable.

Use this when you do not want your server to send APNs or background wake pushes.

### Direct APNs

`direct_apns` makes your Happier Server send ActivityKit updates directly to Apple APNs.

Use this when:

- you own the iOS app bundle
- you can provide an Apple APNs token-auth `.p8` key
- you want the selected server to deliver updates without another relay service

### Hosted Happier relay

`hosted_happier_relay` makes the selected server forward ActivityKit update requests to a hosted relay endpoint. The hosted relay then sends the APNs request.

Use this when:

- the selected server should not hold APNs credentials
- you operate a separate relay service with APNs credentials
- the selected server can authenticate to that relay with an access key

The selected server stores the ActivityKit update token encrypted, decrypts it only for outbound relay dispatch, and forwards the update to the configured relay.

### Background wake best effort

`background_wake_best_effort` sends an Expo push notification to wake the app, then the app applies the Live Activity update locally when iOS allows it.

Use this as a fallback when ActivityKit remote update tokens are unavailable or when you do not want direct APNs delivery from the selected server.

This mode is best effort. iOS may delay, coalesce, or drop background execution.

## User and device controls

Users can control remote Live Activity behavior from notification/activity-surface settings:

- enable or disable Live Activity remote updates
- choose a preferred mode
- allow or disallow background-wake fallback
- set local device overrides

The server advertises diagnostics for each mode. If the preferred mode is unavailable, Happier falls back only when fallback is enabled; otherwise it returns to local-only behavior.

## Selected-server configuration

Set these variables on the Happier Server that stores sessions and receives Live Activity target registrations.

| Variable | Purpose |
| --- | --- |
| `HAPPIER_LIVE_ACTIVITY_REMOTE_UPDATES_ENABLED` | Enables remote Live Activity target registration and update delivery. Defaults to disabled. |
| `HAPPIER_LIVE_ACTIVITY_REMOTE_UPDATE_MODE` | Preferred server mode: `local_only`, `hosted_happier_relay`, `direct_apns`, `background_wake_best_effort`, or `disabled`. |
| `HAPPIER_LIVE_ACTIVITY_REMOTE_UPDATE_ALLOW_FALLBACK` | Allows the server to choose the first available remote fallback mode. Defaults to disabled. |
| `HAPPIER_LIVE_ACTIVITY_REMOTE_UPDATE_DEDUPE_WINDOW_MS` | Coalesces duplicate update payloads with the same snapshot fingerprint. Defaults to 30000 ms. |
| `HAPPIER_LIVE_ACTIVITY_BACKGROUND_WAKE_ENABLED` | Enables background-wake target registration and delivery. |
| `HAPPIER_LIVE_ACTIVITY_BACKGROUND_WAKE_MIN_INTERVAL_MS` | Minimum interval between background-wake pushes to the same target. Defaults to 60000 ms. |
| `HAPPIER_LIVE_ACTIVITY_EXPO_WIDGETS_PUSH_NOTIFICATIONS_ENABLED` | Advertises whether Expo push notifications are available for widget/Live Activity fallback modes. Defaults to enabled. |

## Direct APNs configuration

Direct APNs and hosted relay APNs delivery use Apple token authentication.

| Variable | Purpose |
| --- | --- |
| `HAPPIER_LIVE_ACTIVITY_APNS_TEAM_ID` | Apple Developer team id. |
| `HAPPIER_LIVE_ACTIVITY_APNS_KEY_ID` | APNs Auth Key id. |
| `HAPPIER_LIVE_ACTIVITY_APNS_PRIVATE_KEY` | Inline `.p8` private key in PKCS#8 PEM format. |
| `HAPPIER_LIVE_ACTIVITY_APNS_PRIVATE_KEY_FILE` | File path to the `.p8` private key. Used when the inline variable is unset. |
| `HAPPIER_LIVE_ACTIVITY_APNS_BUNDLE_IDS` | Comma- or newline-separated bundle id allowlist. Required. |
| `HAPPIER_LIVE_ACTIVITY_APNS_ACTIVITY_NAMES` | Optional allowlist of ActivityKit activity names. Defaults to Happier's focus activity. |
| `HAPPIER_LIVE_ACTIVITY_APNS_ENVIRONMENT` | `sandbox` or `production`. Defaults to `sandbox`. |
| `HAPPIER_LIVE_ACTIVITY_APNS_REQUEST_TIMEOUT_MS` | APNs HTTP/2 request timeout. |
| `HAPPIER_LIVE_ACTIVITY_APNS_RECONNECT_BACKOFF_MS` | APNs reconnect backoff after transport failures. |

The private key must be an APNs token-auth `.p8` private key. Certificates are rejected.

For production, prefer `HAPPIER_LIVE_ACTIVITY_APNS_PRIVATE_KEY_FILE` or a secret manager injection over committing inline secrets to a shell profile or compose file.

## Hosted relay client configuration

Set these on the selected server when it should forward to a hosted relay service:

| Variable | Purpose |
| --- | --- |
| `HAPPIER_LIVE_ACTIVITY_HOSTED_RELAY_ALLOWED` | Allows selected-server forwarding to a hosted relay. Defaults to disabled. |
| `HAPPIER_LIVE_ACTIVITY_HOSTED_RELAY_BASE_URL` | Hosted relay base URL. |
| `HAPPIER_LIVE_ACTIVITY_HOSTED_RELAY_ACCESS_KEY` | Bearer key used by the selected server when calling the hosted relay. |

Hosted relay mode still requires `HAPPIER_LIVE_ACTIVITY_REMOTE_UPDATES_ENABLED=1` and `HAPPIER_LIVE_ACTIVITY_REMOTE_UPDATE_MODE=hosted_happier_relay` on the selected server.

## Hosted relay service configuration

If you run the relay endpoint itself, configure:

| Variable | Purpose |
| --- | --- |
| `HAPPIER_LIVE_ACTIVITY_HOSTED_RELAY_SERVICE_ENABLED` | Enables `POST /v1/live-activity-hosted-relay`. Defaults to disabled. |
| `HAPPIER_LIVE_ACTIVITY_HOSTED_RELAY_ACCESS_KEYS` | Comma- or newline-separated bearer keys accepted by the relay. |
| `HAPPIER_LIVE_ACTIVITY_HOSTED_RELAY_MAX_SKEW_MS` | Maximum accepted timestamp skew. Defaults to 5 minutes. |
| `HAPPIER_LIVE_ACTIVITY_HOSTED_RELAY_DUPLICATE_TTL_MS` | TTL for duplicate request coalescing. Defaults to 10 minutes. |
| `HAPPIER_LIVE_ACTIVITY_HOSTED_RELAY_DUPLICATE_CACHE_MAX_ENTRIES` | Maximum in-process duplicate cache entries before reset. |

The hosted relay also needs the direct APNs variables listed above because it is the process that sends to Apple.

The duplicate cache is process-local. If you run multiple relay replicas, use sticky routing or accept that duplicate replay protection is per process until a shared store is introduced.

## Registration flow

1. The iOS app starts or reconciles a Live Activity.
2. The app checks account settings, device overrides, and server capability diagnostics.
3. If a remote mode is available, the app registers a target at `POST /v1/live-activity-targets`.
4. The server verifies the session belongs to the account.
5. The server stores the target, encrypting ActivityKit update tokens when present.
6. The CLI or runtime sends update/end requests to `POST /v1/live-activity-remote-updates`.
7. The server sends through direct APNs, hosted relay, or background wake depending on the target mode.

When the ActivityKit token rotates or the mode changes, Happier marks the old target ended and registers the new one.

## Diagnostics

The server exposes mode diagnostics through its feature payload. Common reasons include:

- `direct_apns_not_configured`
- `apns_team_id_missing`
- `apns_key_id_missing`
- `apns_private_key_missing`
- `apns_private_key_must_be_p8_token_key`
- `apns_bundle_id_allowlist_missing`
- `hosted_relay_not_allowed`
- `hosted_relay_capability_missing`
- `background_wake_disabled`
- `expo_widgets_push_notifications_disabled`

If diagnostics show the preferred mode is unavailable, either fix the missing configuration or choose a different mode in settings.

## Minimal direct APNs example

```bash
HAPPIER_LIVE_ACTIVITY_REMOTE_UPDATES_ENABLED=1
HAPPIER_LIVE_ACTIVITY_REMOTE_UPDATE_MODE=direct_apns
HAPPIER_LIVE_ACTIVITY_APNS_ENVIRONMENT=sandbox
HAPPIER_LIVE_ACTIVITY_APNS_TEAM_ID=TEAMID1234
HAPPIER_LIVE_ACTIVITY_APNS_KEY_ID=KEYID1234
HAPPIER_LIVE_ACTIVITY_APNS_PRIVATE_KEY_FILE=/run/secrets/happier-live-activity-apns.p8
HAPPIER_LIVE_ACTIVITY_APNS_BUNDLE_IDS=dev.happier.app
```

## Minimal hosted relay example

On the selected server:

```bash
HAPPIER_LIVE_ACTIVITY_REMOTE_UPDATES_ENABLED=1
HAPPIER_LIVE_ACTIVITY_REMOTE_UPDATE_MODE=hosted_happier_relay
HAPPIER_LIVE_ACTIVITY_HOSTED_RELAY_ALLOWED=1
HAPPIER_LIVE_ACTIVITY_HOSTED_RELAY_BASE_URL=https://relay.example.com
HAPPIER_LIVE_ACTIVITY_HOSTED_RELAY_ACCESS_KEY=change-me
```

On the hosted relay service:

```bash
HAPPIER_LIVE_ACTIVITY_HOSTED_RELAY_SERVICE_ENABLED=1
HAPPIER_LIVE_ACTIVITY_HOSTED_RELAY_ACCESS_KEYS=change-me
HAPPIER_LIVE_ACTIVITY_APNS_ENVIRONMENT=production
HAPPIER_LIVE_ACTIVITY_APNS_TEAM_ID=TEAMID1234
HAPPIER_LIVE_ACTIVITY_APNS_KEY_ID=KEYID1234
HAPPIER_LIVE_ACTIVITY_APNS_PRIVATE_KEY_FILE=/run/secrets/happier-live-activity-apns.p8
HAPPIER_LIVE_ACTIVITY_APNS_BUNDLE_IDS=com.example.happier
```
