Every installed or packed plugin is described to no-execute discovery by the
generated cold projection:

```text
.happier-plugin/plugin.json
```

Happier reads and validates this file before importing plugin code. It is
projected from the code-defined `definePlugin(...)` author module during pack
and development preparation; authors do not maintain a second manifest source.
The cold host/install envelope and the public author boundary are related but
not identical: the host validates the retained Protocol schema, while
`definePlugin(...)`, the public `PluginManifest` type, and public manifest
parsing apply the current author-availability fences before projection.

In 0.3 development source, authoring remains strict: `definePlugin`, pack and
doctor reject unknown behavior keys with a path-specific diagnostic. Host load
skips an invalid contribution or unknown contribution family and reports it in
plugin diagnostics, while admitting healthy siblings. An unknown field anywhere
inside a contribution skips that whole contribution; ignoring a newer restriction
could widen authority. Invalid known values are never coerced. Dependencies
on a skipped declaration are also invalidated. A skipped declaration cannot be
registered during activation.

Unknown or invalid manifest envelope fields, plugin identities, source integrity, runtime ABI,
and incompatible declared `engines.happier` ranges still refuse the plugin.
The host-range check applies to every source kind, including local and bundled
plugins. Use a range that excludes older hosts when ignoring a new field would
change required behavior. See [versioning and compatibility](/plugins/packaging/versioning-compat).

Manifest admission has no generic public byte, node, depth, string, array, or
record quota matrix. Happier decodes UTF-8 JSON once and uses one canonical
normalization path for the admitted source custody and process-local occurrence, validating the strict
schemas, references, identity, and ownership rules. Field-specific limits still
apply where a real owner or external contract declares one; they are not a
universal manifest-size ceiling.

The canonical publication URL for the cold host/install envelope is the
[Plugin Manifest v2 JSON Schema](https://happier.dev/schemas/plugin-manifest-v2.json).
The repository's website artifact is generated from the same Protocol owner,
so it may include retained host-private or deferred declarations and is not an
author-availability catalog. Public authors use `definePlugin(...)` or the
public `PluginManifest` type; the package's generated capability matrix records
which families are currently available. Deployment of the schema route remains
a preview release gate. Until it is live, host tooling may use a
Protocol-generated local schema artifact from the same owner; the scaffold
does not create a second hand-maintained schema or manifest source.

## Localized labels (0.3 development source)

A label can be a literal string or a keyed `{ key, fallback }` descriptor. In
unreleased 0.3 source, keyed labels also accept optional `params` containing
strings or numbers for the fallback's `{name}` placeholders. Translation text
keeps the same placeholders; the host selects the locale before substituting
the values as plain text.

```ts
import { resolvePluginLocalizedStringV2Text } from '@happier-dev/plugin-sdk/manifest';

const label = {
  key: 'review.continue',
  fallback: 'Continue {count} more · {pullRequest}',
  params: { count: 7, pullRequest: 'example/repository#1' },
};

// An immutable display uses the authored fallback.
resolvePluginLocalizedStringV2Text(label);
// A live presenter supplies text selected by its existing translation owner.
resolvePluginLocalizedStringV2Text(label, '{pullRequest} : encore {count}');
```

Literal strings stay literal. Missing or malformed parameters retain the
authored fallback, and a translation that drops a supplied placeholder falls
back to the complete authored wording. Older strict hosts reject `params`;
require a supporting host through `engines.happier` when targeting a released
artifact. This development-source example establishes no released version floor.

## Minimal shape

The default scaffold projects one action and two executable entrypoints from
its `definePlugin(...)` source:

{/* public-toolchain-compatibility:manifest-example:start */}
```json
{
  "schemaVersion": 2,
  "id": "com.example.plugin",
  "version": "0.1.0",
  "displayName": "Example plugin",
  "description": "Local Happier plugin scaffold for Example plugin.",
  "runtime": { "apiVersion": 1 },
  "entrypoints": {
    "daemon": "./dist/index.js",
    "development": "./src/index.ts"
  },
  "contributes": {
    "actions": [
      {
        "id": "save-note",
        "title": "Save note",
        "description": "Returns the supplied note from one minimal plugin action.",
        "scopes": ["global"],
        "surfaces": ["agent", "cli", "mcp"],
        "execution": { "target": "daemon" },
        "placementBindings": ["commandPalette"],
        "dangerLevel": "safe",
        "inputSchema": {
          "type": "object",
          "additionalProperties": false,
          "properties": { "note": { "type": "string" } },
          "required": ["note"]
        },
        "resultSchema": {
          "type": "object",
          "additionalProperties": false,
          "properties": { "note": { "type": "string" } },
          "required": ["note"]
        }
      }
    ]
  }
}
```
{/* public-toolchain-compatibility:manifest-example:end */}

The JSON above is the cold installed projection. Ordinary contributions bind
their executable handlers through the generated named `activate(api)` export
on demand; it is not an author-maintained second declaration.

## Authority and identity

In 0.3 development source, the optional `executionTarget.autoPick` boolean defaults
to `true`. Declare `executionTarget: { autoPick: false }` only when the plugin's
work depends on a particular Machine: a sole eligible Machine is selected
automatically, while several ask. Omission lets Happier choose among compatible
Machines on this Home. An explicit user pin never falls back. See
[Choose where a plugin runs](/plugins/api/actions-tools-commands#choose-where-a-plugin-runs)
for ordering and Action access. `executionTarget.default: 'installation'` remains
an optional source preference; neither field grants execution authority.

- Authors declare a plugin id and contribution-local ids.
- Happier owns structured `{ pluginId, localId }` identity.
- Use `<pluginId>/<localId>` only at global CLI, wire, and display boundaries.
- Do not dot-concatenate the two ids or repeat the plugin id inside a local id.

Contribution-local ids share one namespace across a plugin's contribution
families. For example, a Resource named `notes` and an Action named `notes`
collide; use distinct ids such as `notes` and `save-note`. Nested ids, such as
Settings field ids, follow their owning family's rules.

`entrypoints.daemon` names the compiled, self-contained installed module.
`entrypoints.development` names the TypeScript source module selected by
`hdev plugins dev`. Static discovery, review, and catalog projection do not
import either module.

## TypeScript

`PluginManifest` is exported from `@happier-dev/plugin-sdk/manifest` for typed
fixtures and tools. External discovery still reads the generated JSON; the
supported author path is the executable `definePlugin(...)` module, whose cold
projection is serialized for discovery.
