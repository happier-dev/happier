Every installed or packed plugin is described to no-execute discovery by the
generated cold projection:

```text
.happier-plugin/plugin.json
```

Happier reads and validates this file before importing plugin code. It is
projected from the code-defined `definePlugin(...)` author module during pack
and development preparation; authors do not maintain a second manifest source.
The cold host/install envelope and the public author boundary are related but
not identical: the host validates the retained Protocol schema, while
`definePlugin(...)`, the public `PluginManifest` type, and public manifest
parsing apply the current author-availability fences before projection. Unknown
behavior keys reject with a path-specific diagnostic; only an explicitly
documented metadata extension point may accept unknown JSON.

Manifest admission has no generic public byte, node, depth, string, array, or
record quota matrix. Happier decodes UTF-8 JSON once, normalizes it once for the
immutable generation, and validates the strict schemas, references, identity,
and ownership rules. Field-specific limits still apply where a real owner or
external contract declares one; they are not a universal manifest-size ceiling.

The canonical publication URL for the cold host/install envelope is the
[Plugin Manifest v2 JSON Schema](https://happier.dev/schemas/plugin-manifest-v2.json).
The repository's website artifact is generated from the same Protocol owner,
so it may include retained host-private or deferred declarations and is not an
author-availability catalog. Public authors use `definePlugin(...)` or the
public `PluginManifest` type; the package's generated capability matrix records
which families are currently available. Deployment of the schema route remains
a preview release gate. Until it is live, host tooling may use a
Protocol-generated local schema artifact from the same owner; the scaffold
does not create a second hand-maintained schema or manifest source.

## Minimal shape

The default scaffold projects one action and two executable entrypoints from
its `definePlugin(...)` source:

{/* public-toolchain-compatibility:manifest-example:start */}
```json
{
  "schemaVersion": 2,
  "id": "com.example.plugin",
  "version": "0.1.0",
  "displayName": "Example plugin",
  "description": "Local Happier plugin scaffold for Example plugin.",
  "runtime": { "apiVersion": 1 },
  "entrypoints": {
    "daemon": "./dist/index.js",
    "development": "./src/index.ts"
  },
  "contributes": {
    "actions": [
      {
        "id": "save-note",
        "title": "Save note",
        "description": "Returns the supplied note from one minimal plugin action.",
        "scopes": ["global"],
        "surfaces": ["agent", "cli", "mcp"],
        "execution": { "target": "daemon" },
        "placementBindings": ["commandPalette"],
        "dangerLevel": "safe",
        "inputSchema": {
          "type": "object",
          "additionalProperties": false,
          "properties": { "note": { "type": "string" } },
          "required": ["note"]
        },
        "resultSchema": {
          "type": "object",
          "additionalProperties": false,
          "properties": { "note": { "type": "string" } },
          "required": ["note"]
        }
      }
    ]
  }
}
```
{/* public-toolchain-compatibility:manifest-example:end */}

The JSON above is the cold installed projection. Ordinary contributions bind
their executable handlers through the generated named `activate(api)` export
on demand; it is not an author-maintained second declaration.

## Authority and identity

- Authors declare a plugin id and contribution-local ids.
- Happier owns structured `{ pluginId, localId }` identity.
- Use `<pluginId>/<localId>` only at global CLI, wire, and display boundaries.
- Do not dot-concatenate the two ids or repeat the plugin id inside a local id.

`entrypoints.daemon` names the compiled, self-contained installed module.
`entrypoints.development` names the TypeScript source module selected by
`hdev plugins dev`. Static discovery, review, and catalog projection do not
import either module.

## TypeScript

`PluginManifest` is exported from `@happier-dev/plugin-sdk/manifest` for typed
fixtures and tools. External discovery still reads the generated JSON; the
supported author path is the executable `definePlugin(...)` module, whose cold
projection is serialized for discovery.
