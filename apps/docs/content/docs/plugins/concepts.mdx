---
title: Plugin concepts
description: Ownership boundaries used by Happier plugins and agent runtimes.
---

## Plugin

A plugin is an installable package with a manifest and optional daemon executable code. It is the unit of trust, projection, reload, permissions, and executable registration.

## Manifest

The manifest declares stable projected facts:

- plugin identity and version
- `uses` runtime families
- enforced permissions and declared metadata capabilities
- actions, tools, commands, hooks, settings, UI surfaces, events, MCP descriptors, agents, and managed dependencies
- agent runtime capabilities and surface declarations

Manifest data is validated before executable code runs.

## Activation

Activation is daemon-side executable binding through `activate(host)`. The activation API is registration-only. It registers handlers for manifest-declared ids and disposables for runtime cleanup.

Activation does not receive `ctx.exec`, `ctx.fetch`, `ctx.sessions.current`, or other runtime services. Agent runtime factories receive `PluginContextV1`; action/tool/command/hook handlers receive handler-scoped `storage`, `settings`, `logger`, and `events` on their existing request/context parameter.

## Runtime context

`PluginContextV1` is the host-provided runtime capability object. It exposes focused services instead of raw host read models:

- process and managed-server execution
- MCP and local services
- settings, secrets, storage, auth, account, and projects
- sessions, transcripts, session-scoped services, permissions, and runtime auth
- events, hooks, notifications, actions, reviews, progress, timeout, retry, abort, and diagnostics

## Agent runtime

`AgentRuntime` is the executable integration point for AI agents. It is registered with `registerAgentRuntime({ agentId, create })` and can expose:

- `runtimeCore` for sessions and execution-runs
- `facets` for lower runtime integrations
- agent runtime surfaces such as terminal runtime, external sessions, attach, handoff, fork, and checkpoints
- message metadata enrichment

## Runtime core

`runtimeCore` is intentionally small. It creates a session runtime and an execution-run runtime. The host bridge and session loop own product lifecycle and durable state around those created objects.

## Surfaces

Agent runtime surfaces are user/product capability families exposed by an agent runtime, such as external session browsing, terminal runtime transcript binding, attach, handoff, fork, or checkpoint restore.

## Facets

Facets are lower runtime integration contracts attached to an engine, such as transcript source, transcript dispatch, session state, and runtime identity publication.

## Agent leaf

An agent leaf is the plugin-owned code that knows a specific agent CLI, protocol, or runtime behavior. It maps native commands, events, permissions, transcripts, and auth into Happier contracts. Model providers are a separate domain.

## Runtime host

The runtime host is Happier-owned code that resolves agents, constructs plugin context, creates session runtimes, executes session loops, handles execution-runs, publishes runtime identity, routes permissions, and projects transcript/state changes.
