Plugin compatibility has four independent axes:

| Axis | Author field | Meaning |
| --- | --- | --- |
| Manifest schema | `schemaVersion` | Selects the strict JSON manifest contract. |
| Happier host | Optional `engines.happier` | Restricts compatible host releases when the plugin requires a particular host contract. |
| Runtime API | Host-derived `runtime.apiVersion` | The host/plugin ABI generation, defaulted by authoring and manifest ingestion. |
| SDK package API | Package SemVer plus its API inventory and declaration report | Selects the public API contract of a published SDK package. |

Package SemVer does not replace the manifest, host, or runtime compatibility fields. A package version can change without a wire-epoch or runtime-ABI change, and vice versa.

Ordinary `definePlugin` declarations omit `runtime` and `engines`. Set
`engines.happier` only when your plugin needs a specific compatible host range;
`'^0.0.0'` is not a useful placeholder. Hook API versions and hook catalog facts
are host-owned and need no author declaration.

The 0.3 development host follows **strict author, tolerant load**. Authoring,
pack and doctor retain strict manifest validation. At load, an invalid
contribution or unknown family is skipped with a plugin diagnostic. An unknown
field anywhere inside a contribution skips the entire contribution, since it
may carry a restriction. Healthy declarations continue loading; skipped
declarations cannot register executable handlers. Unknown envelope fields, identity, integrity
and runtime ABI failures remain fatal. An incompatible declared `engines.happier`
range refuses the whole plugin with `plugin_manifest_engine_incompatible` for
all source kinds, including local development and bundled plugins. An omitted
range creates no version requirement. Declare a narrower range when an older
host cannot safely ignore new semantics.

## SDK package SemVer after publication

No package in the current private-workspace, `0.0.0` source state has a
released SemVer contract. When an SDK package is prepared for publication, its
package API is
reviewed separately from the manifest schema, host range, and runtime ABI. The
release preparation compares the release source's public API inventory and
reachable declaration report with the previous published release, rather than
with Git history or an unrelated prior source-tree record.

That comparison reports mechanical facts—added, removed, changed, deprecated,
or unchanged declarations—and a human classifies the SemVer impact. Removing a
public declaration is breaking; any changed declaration needs review. A patch
release must not intentionally break the package API. An intentional breaking
change to a `0.x` package uses a minor version, requires explicit human
approval, and includes migration notes. These package decisions do not alter a
wire epoch or the host/runtime ABI by themselves.

Representative final paths include:


Use the maintained [SDK entrypoint map](/plugins/api/sdk-entrypoints) for the
current route set. Do not import internal source files or rely on an
undocumented package subpath.
