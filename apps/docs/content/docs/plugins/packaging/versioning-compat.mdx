Plugin compatibility has three independent axes:

| Axis | Author field | Meaning |
| --- | --- | --- |
| Manifest schema | `schemaVersion` | Selects the strict JSON manifest contract. |
| Happier host | `engines.happier` | Selects compatible host releases. |
| Runtime API | `runtime.apiVersion` | Selects the host/plugin ABI generation; every manifest must declare the generated current value. |
| SDK package API | Package SemVer plus its API inventory and declaration report | Selects the public API contract of a published SDK package. |

Package SemVer does not replace the manifest, host, or runtime compatibility fields. A package version can change without a wire-epoch or runtime-ABI change, and vice versa.

## Current Developer Preview source contract

The SDK is one package-level **Developer Preview** source contract. The
workspace package is private at `0.0.0` on a prepublication hold, so this
documentation does not claim that an external package can be installed or that
a released semver policy is already in effect. The source inventory identifies
public routes; it does not assign a different stability tier per export. No
public version is established by the current source tree.

- Author-owned `index.public.ts` sources and the package export map define the
  current intended import paths. The API inventory records that public surface;
  it is not a parallel authoring authority.
- Author imports use the root or the final capability domain path. Public
  author specifiers do not use `experimental/*` or `internal/*`.
- Do not infer a future release's semver or compatibility promise from a source
  path resolving inside this workspace.
- Preview status never relaxes correctness, install safety, lifecycle behavior,
  documentation, or evidence requirements.

## SDK package SemVer after publication

No package in the current private `0.0.0` source state has a released SemVer
contract. When an SDK package is prepared for publication, its package API is
reviewed separately from the manifest schema, host range, and runtime ABI. The
release preparation compares the exact candidate's public API inventory and
reachable declaration report with the previous published tarball, rather than
with Git history or a prior source-tree record.

That comparison reports mechanical facts—added, removed, changed, deprecated,
or unchanged declarations—and a human classifies the SemVer impact. Removing a
public declaration is breaking; any changed declaration needs review. A patch
release must not intentionally break the package API. An intentional breaking
change to a `0.x` package uses a minor version, requires explicit human
approval, and includes migration notes. These package decisions do not alter a
wire epoch or the host/runtime ABI by themselves.

Representative final paths include:

```text
@happier-dev/plugin-sdk
@happier-dev/plugin-sdk/actions
@happier-dev/plugin-sdk/http
@happier-dev/plugin-sdk/interactions
@happier-dev/plugin-sdk/agents/runtime
@happier-dev/plugin-sdk/ui
@happier-dev/plugin-sdk/ui/client
@happier-dev/plugin-sdk/ui/build
@happier-dev/plugin-sdk/testing
```

Use the maintained [SDK entrypoint map](/plugins/api/sdk-entrypoints) for the
current route set. Do not import internal source files or rely on an
undocumented package subpath.

## Current publication status

The workspace package is private at `0.0.0` on a prepublication hold.
Publication requires the consolidated public API, packed external consumer,
platform, compatibility, and human approval gates. This guide does not promise
when that work will make an artifact available.

Source declarations and host wiring establish source readiness, not external
availability. Tool and Command declarations both remain deferred until an exact
packed external plugin proves invocation through the canonical host catalog,
replacement, disable, and uninstall currentness. Only the capability matrix in
a proven published artifact may advertise them as available.
