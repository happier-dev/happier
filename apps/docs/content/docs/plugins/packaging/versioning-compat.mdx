Plugin compatibility has three independent axes:

| Axis | Author field | Meaning |
| --- | --- | --- |
| Manifest schema | `schemaVersion` | Selects the strict JSON manifest contract. |
| Happier host | `engines.happier` | Selects compatible host releases. |
| Runtime API | `runtime.apiVersion` | Selects the host/plugin ABI generation; every manifest must declare the currently supported value, `1`. |

Package semver does not replace the host and runtime compatibility fields.

## `0.1.0` Developer Preview policy

The entire `@happier-dev/plugin-sdk` package is Developer Preview until
`1.0.0`.

- The eight normal package paths are the candidate supported-preview author
  surface pending the consolidated G5 approval.
- `experimental/*` is a separate incubation tier for APIs with incomplete
  consumer proof or a higher expectation of redesign/removal.
- Patch releases should not intentionally break authored plugins.
- Documented `0.x` minor releases may make breaking public API changes and
  include migration notes.
- Developer Preview relaxes long-term compatibility promises. It does not
  relax correctness, install safety, lifecycle behavior, documentation, or
  evidence requirements.

The normal paths are:

```text
@happier-dev/plugin-sdk
@happier-dev/plugin-sdk/manifest
@happier-dev/plugin-sdk/runtime
@happier-dev/plugin-sdk/agent-runtime
@happier-dev/plugin-sdk/ui
@happier-dev/plugin-sdk/ui/client
@happier-dev/plugin-sdk/ui/build
@happier-dev/plugin-sdk/testing
```

Normal and `experimental/*` paths are disjoint. Do not import internal source
files or rely on an undocumented package subpath.

## Current publication status

The workspace package is still private at `0.0.0` on a prepublication hold.
That current implementation fact does not change the approved policy for its
first public `0.1.0` release. Publication requires the consolidated public API,
packed external consumer, platform, compatibility, and human approval gates.
