---
title: Request interceptors
description: Mediate plugin-authored fetch requests through declared policy handlers.
---

Request interceptors are policy hooks for plugin-authored
`context.services.fetch` calls. They are not general HTTP middleware for all
Happier traffic.

## Declaration

Declare interceptors in the manifest with stable ids, order, and target constraints.

The manifest owns:

- interceptor id
- ordering
- target scope
- allowed URL origins
- required permission capability

The activation handler binds executable policy only.

## Binding

```js
export async function activate(api) {
  api.interceptors.register('audit-plugin-fetch', async (request) => ({
    decision: 'continue',
    request
  }));
}
```

## Result model

An interceptor returns either `{ decision: 'continue', request }` or
`{ decision: 'deny', code }`. A continue result carries the complete bounded
request shape accepted by the public SDK.

## Security model

Interception cannot launder network access. The original plugin caller still needs permission for the destination it requests, and interceptor plugins need their own interception permission.

## Recursion

An interceptor's own fetch work must not create an unbounded recursive policy
loop. Keep interceptor behavior local, deterministic, and free of unrelated
network side effects.
