---
title: Invocation context
description: Use operation-scoped services and UI intent from invoked plugin handlers.
---

Action, hook, event, MCP, notification, SCM, and interceptor handlers receive a
bounded `PluginInvocationContext` for the current operation:

```ts
import type { ActionHandler } from '@happier-dev/plugin-sdk/actions';

export const publish: ActionHandler = async (input, context) => {
  const confirmation = await context.services.interactions.confirm({
    kind: 'confirmation',
    title: 'Confirm publish',
    message: 'Publish this result?',
  }, { signal: context.signal });
  if (confirmation.status !== 'approved') return;

  return publishWith(context.services.http, input);
};
```

The context contains structured plugin/contribution identity, optional surface
and session identity, an `AbortSignal`, `services`, and an optional `ui`
presentation facade.

## `context.services.interactions`

Present-user requests and approval-queue operations live on
`context.services.interactions`. The host owns the target, request identity,
correlation, cancellation, currentness, reconnect state, and present-user custody.
Authors supply only typed intent; host request stamps (`requestId`, `sessionId`,
`requester`, `createdAtMs`, and `expiresAtMs`) are not author inputs.

| Operation | Author-visible result |
| --- | --- |
| `requestApproval({ kind: 'approval', … })` | `InteractionTransientApprovalResultV1` |
| `askQuestions({ kind: 'questions', … })` | `InteractionTransientQuestionsResultV1` |
| `confirm({ kind: 'confirmation', … })` | `InteractionTransientConfirmationResultV1` |
| `approvals.request/get/list/watch` | host-stamped access to the canonical approval queue |

Every transient result has the host-generated `requestId` and its matching
`kind`. Approval and confirmation decisions are `approved` or `declined`;
only an approved approval may additionally carry `persistence: 'once' | 'session'`.
Questions return `answered` and an answer map. Each operation can instead return
exactly one terminal status:

```ts
type InteractionTerminalStatusV1 =
  | 'userCancelled'
  | 'requesterAborted'
  | 'timedOut'
  | 'sessionEnded'
  | 'generationRetired'
  | 'hostRestarted'
  | 'unavailable';
```

These terminal outcomes are returned as the result; confirmation is not a
boolean, and cancellation or unavailability is not remapped into a legacy
`PluginError` contract.

The host decides whether a request carries a deadline, and an interactive prompt
in the exact current Session carries none — it waits for the person, so it stamps
no `expiresAtMs` and cannot return `timedOut`. `timedOut` is reachable only where
the host binds a deadline, such as a present-user application invocation that
carries its own invocation budget.

Tool approvals use the exact `InteractionTransientApprovalAuthorRequestV1`
input shape:

```ts
const approval = await context.services.interactions.requestApproval({
  kind: 'approval',
  title: 'Publish result',
  description: 'This sends the current result to its selected destination.',
  subject: {
    kind: 'tool';
    name: 'publish',
    input: { operation: 'publish' },
  },
  allowSessionPersistence: true,
}, { signal: context.signal });

if (approval.status === 'approved') {
  // `approval.persistence` is `once`, or `session` when it was allowed.
}
```

`allowSessionPersistence` is a ceiling, not a request for a particular decision.
Without it, the host can approve only once. With it, the host may still approve
once, decline, or return a terminal status. Workspace/account persistence,
provider request/session/turn identifiers, correlation, replay, currentness, and
cancellation plumbing remain host-owned. Provider-specific decisions such as
OpenCode `always` are translated at the provider boundary.

`askQuestions` takes `InteractionTransientQuestionsAuthorRequestV1`: an explicit
`kind: 'questions'` and a non-empty `questions` array. The author-level question
shape has optional `required`, `allowCustom`, and choice labels:

```ts
const questions = await context.services.interactions.askQuestions({
  kind: 'questions',
  title: 'Choose a destination',
  questions: [{
    id: 'destination',
    prompt: 'Where should this publish?',
    type: 'singleChoice',
    required: true,
    allowCustom: false,
    choices: [
      { id: 'staging', label: 'Staging' },
      { id: 'production', label: 'Production' },
    ],
  }],
}, { signal: context.signal });

if (questions.status === 'answered') {
  const answer = questions.answers.destination;
  if (answer?.kind === 'singleChoice' && answer.answer.kind === 'choice') {
    await publishTo(answer.answer.choiceId);
  }
}
```

Text answers are `{ kind: 'text', value }`. A single-choice answer is
`{ kind: 'singleChoice', answer }`; a multiple-choice answer is
`{ kind: 'multipleChoice', answers }`. Each choice selection is either
`{ kind: 'choice', choiceId }` or `{ kind: 'custom', value }`.

## `context.ui`

When present, `context.ui` is presentation-only. It provides `notify`, `status.set`,
`widget.set`, `title.set`, and `composer.replace` for the current invocation's
present user. It contains no approval, question, confirmation, or interaction
forwarding methods. When it is absent, the invocation has no present-user
presentation path; it does not fall back to the notification service.

## Services

Use `context.services.availability(serviceId)` when a host or lifetime may not
provide a service. The normal roster includes logging, storage, settings,
secrets, HTTP, execution, managed services, sessions, MCP, notifications,
connected accounts, actions, and interactions. Events, filesystem, Providers,
and Resources remain declared but deferred invocation services in the current
capability matrix. Import each service contract from its final domain path, such as
`@happier-dev/plugin-sdk/actions`, `@happier-dev/plugin-sdk/http`, or
`@happier-dev/plugin-sdk/interactions`.

Agent runtime factories receive an immutable `AgentRuntimeFactoryContext`, not
invocation services. Session and execution-run operations receive their own
bounded native runtime contexts from `@happier-dev/plugin-sdk/agents/runtime`.
