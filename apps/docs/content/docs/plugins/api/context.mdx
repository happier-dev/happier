---
title: Invocation context
description: Use operation-scoped services and UI intent from invoked plugin handlers.
---

Action, hook, event, MCP, notification, SCM, and interceptor handlers receive a
bounded `PluginInvocationContext` for the current operation:

```ts
import type { ActionHandler } from '@happier-dev/plugin-sdk/runtime';

export const publish: ActionHandler = async (input, context) => {
  const confirmed = await context.ui.confirm('Publish this result?', {
    title: 'Confirm publish',
  });
  if (!confirmed) return;

  await context.ui.status.set('publish', 'Publishing…');
  try {
    context.signal.throwIfAborted();
    return await publishWith(context.services.fetch, input);
  } finally {
    await context.ui.status.set('publish', null);
  }
};
```

The context contains structured plugin/contribution identity, an optional
surface and session identity, `AbortSignal`, `services`, and `ui`.

## `context.ui`

The supported-preview UI-intent facade provides tool approval, structured questions,
confirmation, notification, status, widget, title, and composer operations. The host
owns the target, request identity, correlation, cancellation, currentness, reconnect
state, and present-user custody. Authors supply UI intent and typed answers rather
than transport or provider-specific interaction metadata.

| Operation | Author-visible result |
| --- | --- |
| `requestApproval(request)` | `approved` with `once` or `session` persistence, `denied`, `cancelled`, or `unavailable` |
| `askQuestions(questions, { title? })` | `answered` with typed answers, `cancelled`, or `unavailable` |
| `confirm(message, { title? })` | resolves to `boolean`, or rejects with `PluginError` code `plugin_ui_cancelled` or `plugin_ui_unavailable` |
| `notify(message, { severity? })` | completion or `PluginError` |
| `status.set(key, textOrNull)` | completion or `PluginError` |
| `widget.set(key, widgetOrNull)` | completion or `PluginError` |
| `title.set(titleOrNull)` | completion or `PluginError` |
| `composer.replace(text)` | completion or `PluginError` |

Tool approvals use exactly this author-visible contract:

```ts
type PluginUiApprovalRequest = Readonly<{
  title: string;
  description?: string;
  subject: Readonly<{
    kind: 'tool';
    name: string;
    input: JsonValue;
  }>;
  allowSessionPersistence?: boolean;
}>;

type PluginUiApprovalResult =
  | Readonly<{ status: 'approved'; persistence: 'once' | 'session' }>
  | Readonly<{ status: 'denied'; rationale?: string }>
  | Readonly<{ status: 'cancelled'; diagnostic?: PluginDiagnosticData }>
  | Readonly<{ status: 'unavailable'; diagnostic: PluginDiagnosticData }>;
```

`allowSessionPersistence` is a ceiling, not a request for a particular decision.
Without it, the host can approve only once. With it, the host may still approve
once, deny, cancel, or report unavailability. Workspace/account persistence,
provider request/session/turn identifiers, correlation, replay, currentness, and
cancellation plumbing are not author inputs. Provider-specific decisions such as
OpenCode `always` are translated at the provider boundary.

`askQuestions` accepts a non-empty question tuple. A question is exactly one of:

```ts
type PluginUiQuestion =
  | Readonly<{
      id: string;
      prompt: string;
      type: 'text';
      required?: boolean;
    }>
  | Readonly<{
      id: string;
      prompt: string;
      type: 'single' | 'multiple';
      required?: boolean;
      choices: readonly [
        Readonly<{ id: string; label?: string; description?: string }>,
        ...Readonly<{ id: string; label?: string; description?: string }>[],
      ];
      allowCustom?: boolean;
    }>;

type Questions = readonly [PluginUiQuestion, ...PluginUiQuestion[]];
```

Text answers are `{ type: 'text', value }`. A single-choice answer is
`{ type: 'single', answer }`; a multiple-choice answer contains a non-empty
`answers` tuple. Each choice answer is either
`{ type: 'choice', choiceId }` or `{ type: 'custom', value }`. The latter is
the provider-neutral “Other” answer.

An answered result is
`{ status: 'answered', answers: Readonly<Record<string, PluginUiQuestionAnswer>> }`,
keyed by question `id`. Cancellation is
`{ status: 'cancelled', diagnostic?: PluginDiagnosticData }`; unavailability is
`{ status: 'unavailable', diagnostic: PluginDiagnosticData }`.

Some one-shot effects can fail with `PluginError` when the host cannot know
whether an effect was applied. Do not blindly replay them.

## Services

Use `context.services.availability(serviceId)` when a host or lifetime may not
provide a service. The normal roster includes logging, storage, settings,
secrets, events, fetch, filesystem, execution, managed dependencies, sessions,
resources, MCP, notifications, and connected accounts. Exact methods
and availability come from `@happier-dev/plugin-sdk/runtime`.

Agent runtime factories receive an immutable `AgentRuntimeFactoryContext`, not
invocation services. Session and execution-run operations receive their own
bounded native runtime contexts from `@happier-dev/plugin-sdk/agent-runtime`.
