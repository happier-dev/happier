---
title: Runtime context
description: Runtime services available to plugin handlers and agent runtimes.
---

`PluginContextV1` is the host-provided capability object for agent runtime factories. It is not passed to `activate(host)`.

Action, tool, command, and hook handlers receive handler-scoped services on their existing handler context:

- action, tool, and command handlers use `request.context.storage`, `request.context.settings`, `request.context.logger`, and `request.context.events`
- hook handlers use `context.storage`, `context.settings`, `context.logger`, and `context.events`

Those fields are the `PluginHandlerServicesV1` subset of the same plugin-scoped service instances used by `PluginContextV1`.

## Focused read model

Context services expose focused methods and subscriptions. They should not expose full host read models or raw database/session internals.

## Capability ownership

Use the nearest host service instead of duplicating host behavior. For example:

- use `ctx.exec` rather than spawning raw binaries yourself
- use `ctx.managedServer` for agent-owned loopback servers
- use `ctx.settings` and `ctx.secrets` rather than reading files directly
- use `ctx.events` rather than inventing a side channel
- use `ctx.sessions.current`, `ctx.sessions`, and `ctx.transcripts` rather than reading Happier storage directly

## Cancellation

Handlers should honor `AbortSignal` when a context method or request context provides one. Long-running runtime work should clean up agent resources when aborted or disposed.
