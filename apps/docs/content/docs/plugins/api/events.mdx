---
title: Events
description: Publish and observe manifest-declared plugin events.
---

The public events service is live daemon pub/sub for declared plugin events. It is not a hook, transcript store, history API, or Agent session event stream.

## Declare events

Declare published events and subscriptions in the cold manifest. Each event has a plugin-local id and an optional payload schema. The host combines the trusted plugin id and local id into structured `{ pluginId, localId }` identity.

## Emit an owned event

`emit` accepts the current plugin's local event id:

```ts
await context.services.events.emit('build.completed', {
  status: 'ok'
});
```

The event must be declared by the current plugin. Reserved host names, undeclared ids, and payloads that fail the declared schema are rejected.

## Subscribe

Dynamic subscriptions use a structured contribution reference:

```ts
const subscription = context.services.events.subscribe(
  { pluginId: 'com.example.build', localId: 'build.completed' },
  async (event) => {
    const payload = event.payload;
  }
);

subscription.dispose();
```

The target event and the caller's subscription must be declared. Cross-plugin observation also requires scoped `events.plugin.subscribe` host access for the target plugin.

Manifest-declared subscription handlers bind during activation with `api.events.register(subscriptionLocalId, handler)`. The registered id is the subscription contribution's local id, not the publisher's event id.

## Agent session events

Agent session evidence uses `AgentSessionRuntime.watch(...)` and its native strict event union. Do not publish raw Agent protocol messages on the general plugin event service.

## Delivery

The event service has bounded live delivery. It does not promise replay, history, global ordering across publishers, or transcript persistence. Dispose dynamic subscriptions with their owner and isolate subscriber failures from publisher correctness.
