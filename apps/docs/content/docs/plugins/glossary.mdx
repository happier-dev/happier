---
title: Plugin glossary
description: Public terms used by the Happier Plugin SDK.
---

| Term | Meaning |
| --- | --- |
| Plugin | An installable package with a cold manifest and optional executable daemon and client code. The package is the unit of installation and trust. |
| Cold manifest | The generated `.happier-plugin/plugin.json` projection, parsed without importing plugin code. `definePlugin(...)` is the authoring source; the cold file declares identity, entrypoints, access requests, and contributions. |
| Catalog | A host projection of admitted cold-manifest facts, used to discover contributions without loading daemon code. A catalog does not prove that executable code is active. |
| Contribution | A manifest-declared capability such as an action, hook, Agent, setting, or UI surface. |
| Surface | The user or host integration where a declared contribution is exposed, such as CLI, MCP, an Agent/tool client, or a supported client UI. A surface is not a second handler or lifecycle owner. |
| Action | The canonical executable operation. Its handler is the only implementation; tools and commands declare presentation and routing over that Action rather than separate handlers. |
| Tool | A manifest descriptor that exposes an Action to a tool-capable Agent or MCP surface. |
| Command | A manifest descriptor that exposes an Action in a CLI-facing command surface. |
| Hook | A host-invoked extension point for one named workflow. It observes or applies the hook contract; it does not take ownership of the host workflow. |
| Service | A bounded host capability on `PluginInvocationContext`, available only while a handler is invoked and only when its declared resource is available. Services are not exposed during activation. |
| Admission | The daemon-owned decision to validate, review when required, and adopt a candidate's declared/executable behavior. It is distinct from a package being visible in a cold catalog. |
| Generation | One immutable, daemon-owned accepted plugin revision. The daemon routes new work to the current accepted generation and retains the last known good generation when a replacement fails. It is not an author-managed version counter. |
| Realm | The execution environment for an API or contribution, such as daemon, build, browser/client, or React Native. A declaration can project across realms without making its executable code portable; do not rely on a process-global singleton across them. |
| Cross-plugin contribution protocol | A feature-owned, versioned contract that lets a target declare contribution points and a contributor bind existing Actions to operation roles. The host owns admission, currentness, and execution. |
| Contribution point | A target plugin's named acceptance point for one or more protocol epochs, declared with a feature protocol's `.point()` helper. |
| Operation declaration | The immutable `.declaration` beside a protocol operation's `.bind(localId)` helper. It supplies the role's input mode, result schema, Action surfaces, and danger level; it is not a second Action registry. |
| Plugin API | `PluginApi`, consumed by the named `activate(api)` export generated by `definePlugin(...)`. It registers implementations only for the same projected contribution ids. |
| Invocation context | `PluginInvocationContext`, passed when the host invokes a contribution. It contains identity, cancellation, services, and `context.ui`. |
| Agent | An executable coding backend contributed under `contributes.agents`. An Agent owns provider-native behavior at its leaf; it is not a model Provider. |
| Agent runtime | Native `AgentRuntime` registered for a custom Agent. It supplies session and/or execution-run factories while the host owns shared lifecycle and persistence. |
| Runtime host | Happier-owned orchestration for sessions, turns, execution runs, transcripts, activity, persistence, and process-terminal facts. A plugin runtime adapts to it; it does not replace it. |
| Provider | A model source such as OpenRouter, Ollama, or LM Studio. Provider contribution metadata and account-owned Provider connections are separate from Agents. |
| Host access | Required disclosure/cooperative service configuration or optional access to an independently host-owned resource. Ambient local process powers are not sandbox grants. |
| Declarative UI | A host-rendered surface described by public data rather than arbitrary client code. |
| Hosted web UI | An isolated web surface whose runtime availability each host reports for itself — either the one frame adapter it constructed or a typed unavailable reason. It does not sandbox other code in the package. |
| React Native UI | Trusted package code loaded in a supported client realm. It is the default native-feeling executable UI model, not a sandbox. |
| UI artifact | A build output described by `ui-artifacts.json` and verified by the host before use. |
| Plugin testkit | `createPluginTestkit` from `@happier-dev/plugin-sdk/testing`, used to activate a module and invoke registered contributions in tests. |
| Developer Preview | The package-level posture for the current `@happier-dev/plugin-sdk` source contract. It is not a per-export label, a published artifact promise, or a released-semver compatibility guarantee while the package remains on its prepublication hold. |
