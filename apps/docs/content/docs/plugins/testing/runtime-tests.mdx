---
title: Agent runtime tests
description: Test native AgentRuntime session, execution-run, event, and cleanup contracts.
---

Agent runtime tests should prove that the Agent-specific leaf maps its native behavior into the host-owned runtime contract.

## Registration and creation

Cover the factory registered by `api.agents.register` and the native `AgentRuntime` it returns. A runtime supplies `sessions`, `executionRuns`, or both.

For session-backed Agents, exercise `AgentSessionRuntimeFactory.open(...)` and the resulting `AgentSessionRuntime`:

- `send(...)` admission and results
- `watch(...)` events and subscription disposal
- optional `cancel(...)`, `updateConfiguration(...)`, and `compact(...)`
- continuation, rollback, goals, catalog, and other controls only when the Agent declares them
- runtime and session disposal during startup, active work, failure, and host shutdown

For execution-run Agents, test the `executionRuns` factory through the same public boundary. Reuse a shared session-backed adapter when that is the canonical implementation rather than duplicating an Agent-specific run loop.

## Ownership assertions

Assert Agent-native evidence and caller-visible outcomes. Do not give the test or Agent leaf authority over host-owned session state, transcript persistence, pending input, effective activity, or process-terminal facts.

Mock only genuine boundaries such as the Agent executable, operating system process adapter, network service, clock, or persistent database. Run real internal parsers, reducers, normalization, and lifecycle logic.
