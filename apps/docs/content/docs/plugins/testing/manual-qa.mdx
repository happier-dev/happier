---
title: Manual QA
description: Manually validate plugin behavior through the app, CLI, daemon, and agent runtime.
---

Manual QA should exercise real user flows:

- review and **Install & Trust** a local or packed plugin
- configure it, invoke an action, and inspect current Diagnostics
- run `happier plugins dev` and verify an edit replaces the current surface
- run `happier plugins install . --dev` followed by `happier plugins reload`
  from the package root and verify the same valid replacement path works
  without a watcher; when resolution is ambiguous or runs elsewhere, use
  `happier plugins reload <developmentPluginId>` to select one
- update, roll back, disable/enable, and uninstall; verify stale generations
  cannot act and focus returns safely after each transition
- disconnect the daemon while an executable surface is mounted; verify the
  visual snapshot remains, every control and host mutation is unavailable, and
  a screen reader announces the localized read-only summary
- reconnect; verify generation/policy/context are revalidated without another
  trust prompt, controls work again, and prior focus returns only when safe
- start an agent session, send a normal prompt, reject unsupported structured
  input explicitly, cancel a turn, stop/dispose the session, and start an
  execution-run
- test permission prompts and external-session browsing/import when supported
- inspect logs for redaction and cleanup

## Executable UI accessibility matrix

Run the applicable rows on every advertised web, iOS, Android, and distinct
desktop host:

| Area | Validate |
| --- | --- |
| Keyboard and focus | Complete keyboard operation, visible focus, logical order, inert offline controls, safe focus return after reconnect/update/rollback/uninstall |
| Screen reader | Localized names/roles/state/order, polite status changes, offline static summary, no actionable descendants in the stale snapshot |
| Scale and layout | 200% web/desktop zoom or native Dynamic Type, no lost content/actions, narrow/wide/rotated layouts, safe areas |
| Contrast and meaning | Light/dark/high contrast, 4.5:1 text and 3:1 large/UI contrast, no color-only status |
| Locale | RTL reading/focus order, long translated strings, selectable labelled technical IDs |
| Motion | Reduced-motion behavior and no essential state conveyed only by animation |
| Targets | At least 44×44 points on iOS and 48×48 dp on Android; applicable web targets remain keyboard accessible |
| Lifecycle | Install/review/configure/diagnose/update/rollback/uninstall plus offline/reconnect on the exact current generation |

Record the client/platform and loaded artifact identity, exact commands and
actions, expected behavior, actual behavior, accessibility technology used,
and log or screenshot evidence. Source tests do not replace a real
screen-reader/device run.
