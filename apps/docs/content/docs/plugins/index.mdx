Happier plugins extend the local runtime without changing Happier core source code. A plugin can contribute actions, tools, commands, hooks, UI surfaces, settings, MCP integrations, SCM integrations, and AI Agents.

The plugin system is manifest-first. Static facts live in `.happier-plugin/plugin.json` so Happier can project catalogs, settings, requested host access, installation review, and UI surfaces without executing plugin code. Executable plugin code is trusted code, not sandboxed code.

## Core model

- **Manifest**: cold JSON declaring identity, entrypoints, host access, and contribution descriptors.
- **Activation API**: `activate(api)` binds executable handlers through nested capability families.
- **Invocation context**: action and hook handlers receive bounded identity, cancellation, and services.
- **Agent runtime**: a plugin-owned `AgentRuntime` registered with `api.agents.register(agentId, factory)`.
- **Runtime host**: Happier-owned session and execution-run orchestration. Agent leaves map Agent-specific behavior into shared runtime contracts.

## Preview authoring rules

- The candidate public surface uses eight normal paths: the package root,
  `/manifest`, `/runtime`, `/agent-runtime`, `/ui`, `/ui/client`, `/ui/build`,
  and `/testing`. This checkout remains on prepublication hold pending the
  consolidated API approval.
- Do not import Happier internal packages from a plugin.
- Keep static projected facts in the manifest.
- Bind executable code through `activate(api)` and manifest-declared ids.
- Use host-provided invocation and Agent runtime contexts. Do not shell out or read host internals directly when a service exists.
- Keep Agent-specific behavior inside the plugin-owned Agent runtime leaf.
- Do not write Happier transcript rows, session rows, or execution-run state directly from agent code.

Every public path is Developer Preview until 1.0. Patch releases should not intentionally break documented contracts. A documented 0.x minor may break them when accompanied by migration notes. Preview status does not waive correctness, installability, lifecycle cleanup, security disclosure, or documentation.

## Where plugin code runs

Daemon plugin code runs through `entrypoints.daemon` or, in the development loop, `entrypoints.development`. React Native plugin UI runs as trusted code in a supported client realm. Hosted web UI runs behind an isolated public bridge. Declarative UI is rendered by the host. Installation is a whole-package trust decision across these surfaces.
