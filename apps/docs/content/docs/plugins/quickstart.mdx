The default scaffold contains one code-defined plugin module, one action, one
focused test, and the package metadata needed by the current author tools.

For every authoring command and the exact review-decision lifecycle, see the
[Plugin authoring CLI](/plugins/packaging/authoring-cli) reference.

> Release status: the author packages are not publicly installable yet. The
> empty-directory flow remains a packed/live release gate until an approved
> Preview artifact is published. Source and schema checks in this repository do
> not prove public installation; do not substitute workspace resolution or a
> locally served registry for that release proof.

## Create and develop

```bash
happier plugins create my-plugin
cd my-plugin
happier plugins dev
```

`plugins create` derives the display name and a local plugin id from the
directory name. Use `--id com.example.my-plugin` when you need a durable
publisher-owned id.

For an executable UI, keep the same journey and choose one mode:

```bash
happier plugins create my-native-plugin --ui reactNative
happier plugins create my-hosted-plugin --ui hostedWeb
```

The React Native scaffold declares web, iOS, and Android artifacts through the
public build contract. The hosted scaffold emits its isolated artifact and
bootstrap client, but its packaged browser/desktop, iOS, and Android runtime
paths remain unavailable until their respective frame adapters are verified.

`plugins dev` is the automatic watcher flow: after trust, the CLI observes the
source closure and submits each captured batch to the daemon. After submission,
the daemon-owned candidate lifecycle materializes declared development
dependencies, builds declared UI artifacts, evaluates the selected author
module, and validates its projected manifest before adoption. The daemon imports
the development module only as the activation entry and calls its generated
`activate(api)` export.

This normal create-to-dev loop prepares dependencies automatically; do not run
`happier plugins dev install .` first. That command prepares an
external-author fixture. If the SDK must resolve through an approved registry
origin, use `happier plugins dev --sdk-registry <origin>`. Installed SDK
packages include copyable public patterns under
`node_modules/@happier-dev/plugin-sdk/examples/`; choose the smallest matching
example and verify imports against the maintained
[SDK entrypoint map](/plugins/api/sdk-entrypoints). Before selecting a
contribution or service family, read the installed
`node_modules/@happier-dev/plugin-sdk/capability-matrix.json`: it is the sole
availability authority. A `deferred` row remains conformance-only reference
material even when its declaration or example is present; it is not a
supported product lifecycle. This does not change the current prepublication
hold.

For a custom Session Agent, that activation entry is not the runner entry. The
runner imports only the exact named factory leaf in the Agent's
`sessionRunnerFactory` locator; it never calls `activate`. Keep that leaf
separate and import-safe, because activation and runner execution can be
different realms with no shared process-global singleton.

The first use asks you to **Install & Trust** the local source. Normal edits
under that approved source identity do not create a new trust prompt. A source
root, plugin identity, executable realm, or required-access change is reviewed
again.

## Generated layout

```text
my-plugin/
  src/
    index.ts
  test/
    index.test.mjs
  package.json
  tsconfig.json
```

During development, `src/index.ts` is the authoring source of truth. Packing
evaluates that module once, validates the canonical projection, and writes
`.happier-plugin/plugin.json` into the archive. Installed and marketplace
discovery read that generated JSON without executing author code.

The generated entry uses the code-defined authoring helper and exports the
ordinary named `manifest` and `activate` ABI:

```ts
import { definePlugin } from '@happier-dev/plugin-sdk';
import {
  defineProtocolObject,
  defineProtocolString,
} from '@happier-dev/plugin-sdk/protocol';

export const { manifest, activate } = definePlugin({
  id: 'com.example.my-plugin',
  version: '0.1.0',
  entrypoints: { daemon: './dist/index.js' },
  displayName: 'My plugin',
  actions: {
    'save-note': {
      title: 'Save note',
      execution: { target: 'daemon' },
      inputSchema: defineProtocolObject({
        note: defineProtocolString(),
      }, { policy: 'closed' }),
      resultSchema: defineProtocolObject({
        note: defineProtocolString(),
      }, { policy: 'closed' }),
      async run(input) {
        return { note: (input as Readonly<{ note: string }>).note };
      },
    },
  },
});
```

The action id is local to the plugin. Happier owns its structured global
identity and renders it as `com.example.my-plugin/actions/save-note` only where
a global CLI, wire, or display boundary needs qualification.

## Test, build, and pack

The normal test command runs the generated daemon-independent suite. The
lower-level author commands remain available for focused checks:

```bash
happier plugins dev typecheck .
happier plugins dev build .
happier plugins test .
happier plugins pack .
```

You can also use `npm run typecheck`, `npm test`, `npm run build`, and
`npm run pack:plugin` from the scaffold. `plugins test .` runs the generated
`test/index.test.mjs` suite through Happier's managed JavaScript runtime. It
loads `dist/index.js`, passes its exported `manifest` and `activate` through the
public testkit, and invokes the declared
`save-note` action without starting a daemon or mutating installed plugin
state. The reserved
`happier plugins test . --packed` mode packs the project, installs and trusts
it through an authenticated disposable daemon home, invokes a safe CLI action
that accepts empty input when one is declared, restarts the daemon, and invokes
the action again. It never reads or mutates the user's installed plugin state.

`plugins pack` writes an npm-compatible `.tgz` and a SHA-256 sidecar. Install
the emitted archive through the same reviewed daemon path used by other plugin
sources:

```bash
happier plugins install ./happier-plugin-com-example-my-plugin-0.1.0.tgz --kind archive
```

In an interactive terminal, Happier shows the exact package, manifest,
executable realms, contributions, requested host integration, and source facts
before asking for **Install & Trust**. Use the archive path printed by
`plugins pack`; the example filename above is illustrative.

## Development without a watcher

`plugins dev` is the normal automatic edit loop. For an intentional
watcher-free update, install the package-root development source and reload
from that root:

```bash
happier plugins install . --dev
happier plugins reload
```

The `--dev` installation and reload use the same daemon-owned trust,
validation, generation replacement, and cleanup path as the watcher. When the
current directory has more than one development plugin, or when you reload from
another directory, select one explicitly: `happier plugins reload
com.example.my-plugin`. An invalid reload leaves the last accepted generation
serving.

## Next steps

- Add declarations and their handlers or runtimes to the matching
  `definePlugin(...)` family.
- Use `PluginInvocationContext.services` and `context.ui` inside invoked
  handlers.
- Choose the smallest [task guide](/plugins/guides): Agent mode, Provider,
  SCM, Voice, background service, or invocation service.
- For a feature-owned integration, use the
  [cross-plugin contribution guide](/plugins/guides/cross-plugin-contributions).
  Ordinary contributors import the feature protocol, derive role facts from an
  operation's `.declaration`, and bind their existing Action with `.bind()`;
  they do not create a generic protocol or scan Actions.
- Use native `AgentRuntime` factories only for custom executable Agents; the
  host retains session, turn, input, transcript, activity, persistence, and
  process lifecycle ownership.
- Choose React Native for trusted cross-platform plugin UI, hosted web for its
  isolated artifact source contract, or declarative settings/status/actions for
  UI rendered entirely by Happier. Hosted runtime availability is reported per host,
  so read it from the host rather than advertising it as a global capability.
