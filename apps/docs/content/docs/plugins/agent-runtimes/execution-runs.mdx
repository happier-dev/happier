---
title: Execution-runs
description: Reuse session runtime logic for bounded and long-lived agent runs.
---

Execution-runs are host-owned product runs that use agent execution. They cover one-shot tasks, review engines, voice turns, automation, and other task-like AI execution flows.

## Execution-run creation

Agent runtimes expose execution-run support through `runtimeCore.createExecutionRunBackend(...)`.

```ts
runtimeCore: {
  createExecutionRunBackend: (params) => createExampleExecutionRunBackend({ ctx, params })
}
```

## Execution-run result forms

An agent runtime can return:

- `ExecutionRunBackendV1`: direct `run(input)` interface
- `ExecutionRunHostBackendV1`: host-compatible session-backed interface

Use the shared SDK adapter when an execution-run can be backed by a normal session runtime. This avoids maintaining separate session and execution-run implementations.

## Host-owned state

The execution-run host bridge owns:

- public run state
- markers and activity state
- permission routing
- cancellation
- bounded run loops
- run lifecycle hooks
- status publication
- session provisioning and resume when supported

Agent runtime leaves should not maintain a parallel public run state system.

## Validation expectation

If normal sessions and execution-runs use the same native protocol, tests should prove both flows converge through the same runtime leaf or shared adapter.
