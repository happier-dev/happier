ACP has two deliberately different authoring modes. Choose one; do not add a
custom factory or locator to a declarative ACP contribution.

> This page describes the current plugin-preview contract in development
> source. Published SDK availability may differ until that preview ships.

| | Declarative ACP | Custom ACP composition |
| --- | --- | --- |
| Choose it when | Transport plus static ACP behavior completely describes the Agent | The plugin must adapt Agent-specific behavior before opening ACP |
| Manifest runtime | `runtime.kind: 'acp'` with `transport` and optional data-only `definition` | `runtime.kind: 'custom'` |
| Factory / registration | None | One `AgentRuntimeFactory` supplied as `agents.<id>.factory`; generated activation registers it |
| Session runner locator | None | Required for a Session-capable custom Agent; names a distinct exact leaf |
| ACP opening | Host-owned | Leaf calls `context.protocols.acp.open(...)` |

## Declarative ACP

Declare `runtime.kind: 'acp'`, the transport, Session primary, and capabilities
in the code-defined Agent declaration. This has no `factory`, generated
registration, `sessionRunnerFactory`, or runner module. The host constructs the
runtime directly from the declaration.

The optional `runtime.definition` is strict data, not a second runtime API. It
can contain only `modelConfigOptionId`, data-only `stderrRules`, and an MCP
input policy (`pass_through` or `drop`). Transport continues to own the
executable, arguments, environment, endpoint, headers, and transport timeouts.
Agent title and description remain top-level Agent fields, and Session
capabilities remain on the Agent capability declaration.

The host classifies authentication failures consistently across ACP Agents.
Set `stderrRules.authenticationErrorDetail` only to replace the status message
shown after that host-owned classification; it does not add plugin-specific
matching. Keep `suppress` and `statusErrors` for other bounded, data-only stderr
rules.

Omitting `mcp` keeps MCP input out of the ACP launch. Declare
`mcp: { policy: 'pass_through' }` only when the Agent should receive the
host-provided MCP servers.

The manifest schema is the canonical public definition and the host normalizes
that definition once before opening ACP; plugins do not register another ACP
definition object at activation time. Kiro is the current positive consumer:
its `definePlugin(...)` declaration supplies `modelConfigOptionId`, bounded
stderr suppression rules, and `mcp: { policy: 'pass_through' }` beside its
stdio transport, with no runtime factory or runner locator.

## Custom ACP composition

Use a custom Agent only when a plugin-owned leaf must compose ACP with
Agent-specific rules. The `agents.<id>.factory` entry generates the daemon
registration; a distinct import-safe runner leaf exports the exact same factory
and is named by the locator. That leaf, not `activate`, calls the composer.

The `AgentSessionRuntimeContext` exposes protocol composers through `context.protocols`:

```ts
import type { AgentRuntime } from '@happier-dev/plugin-sdk/agents/runtime';

export const runtime: AgentRuntime = {
  sessions: {
    async open(request, context) {
      return context.protocols.acp.open(request, {
        transport: {
          // Supply the declared ACP transport for this Agent.
        },
        definition: {
          mcp: {
            // Supply the Agent's supported MCP input policy.
          }
        }
      });
    }
  }
};
```

Use the exact transport and definition types exported by the installed SDK version; the abbreviated values above show ownership, not a copy-paste-complete transport.

Agent-specific authentication, dynamic model projection, verified image input,
tool-name shaping, function-valued extensions, and other executable behavior
belong in custom ACP composition. Happier still owns session and turn lifecycle,
input custody, transcript persistence, activity, and terminal process facts.

### In-flight steering

In 0.3 development source, contribute `definition.delivery.steer` to adapt a
native steering method. The host admits the input against the active turn and
keeps custody; the plugin only supplies the wire codec:

```ts
import type { AgentAcpInFlightSteerDefinition } from '@happier-dev/plugin-sdk/agents/runtime';

const steer: AgentAcpInFlightSteerDefinition = {
  method: 'my-agent/steer',
  isSupported: caps => caps !== null && typeof caps === 'object'
    && !Array.isArray(caps) && caps.myAgentSteering === true,
  buildParams: ({ providerSessionId, inputIds, input }) => ({
    sessionId: providerSessionId, inputId: inputIds[0], text: input.text,
  }),
  isAccepted: response => response === 'absorbed',
  isRejected: response => response === 'dropped',
};
```

Require the native advertised capability in `isSupported`. Return `null` from
`buildParams` for content the native method cannot represent, before any write.
`isRejected` is for a definite refusal: the host surfaces it through its existing
retry/resend contract without ending the running turn. Other unaccepted replies
or transport failures leave custody unknown; they must not trigger a blind resend.
Live user-message echoes remain observations, rather than duplicate transcript
writes. These callbacks require matching development host and SDK source; an
older host cannot safely ignore their capability or custody decisions.

## Configuration catalogs

In unreleased 0.3 development source, declare `modelConfigOptionId` when your
Agent has a dedicated model selector. The host uses that exact id for both
preflight discovery and running Sessions. Categories are optional UX hints;
multiple options may have category `model`, and their advertised array order
sets display priority. A Provider selector remains a separate setting that can
change the model catalog. The observed model's controls appear with that model.
The optional catalog-root `modelConfigOptionId` carries the resolved selector id
to clients; absence means unresolved and does not authorize client inference.

The composer preserves the full config catalog, including native ids, category,
labels, descriptions, flat choices and groups. Initial snapshots, successful
setter responses and config notifications use the same owner. A full returned
snapshot replaces previous choices and values, including removed controls;
failed setters retain the last observed catalog. Select values remain strings
when the native Agent sends strings, including `"true"` and `"false"`.
Native model ids are nonblank opaque strings. The development model Action,
Session selection references and transition coordinator preserve their bytes;
Provider-connection model ids retain their separate validation rules.

In 0.3 development source, a custom ACP definition can delegate validation of
explicit unlisted model choices to the native Agent:

```ts
import type { AgentAcpRuntimeDefinition } from '@happier-dev/plugin-sdk/agents/runtime';

const definition: AgentAcpRuntimeDefinition = {
  modelConfigOptionId: 'model',
  allowExplicitUnlistedModels: true,
};
```

The host supplies `configuration.model.selectionSource` as `explicit` for a
qualified user or Action choice and `inherited` for inherited state. Omission
remains inherited. Only an explicit choice plus this opt-in bypasses catalog
membership; the native Agent must accept it or return its visible refusal.
An inherited unlisted startup choice clears to the native default, while an
already-current model is retained. This does not add a freeform picker or
another model catalog. It requires matching development host and SDK source.

Custom preflight callbacks forward the draft's `configOptionOverrides` and
declared model selector id to `probeDeclaredAcpSessionControls`. The host applies
standalone overrides to its temporary Session before deriving dependent model
choices. A failed native setter returns the last accepted observations with
`refreshError` and optional `refreshErrorMessage`; preserve that guidance rather
than presenting the requested value as accepted.
An accepted model snapshot, including an empty catalog, survives a later setter
failure instead of being replaced by an older cached catalog for that scope.

Custom Session runtimes can publish the same observation through their existing
event stream. For example, this event advertises a native configuration choice:

```ts
import type { AgentSessionRuntimeEvent } from '@happier-dev/plugin-sdk/agents/runtime';

const catalog: AgentSessionRuntimeEvent = {
  kind: 'config-options',
  sequence: 1,
  sessionId: 'host-session-id',
  emittedAtMs: Date.now(),
  configOptions: [{
    id: 'reasoning', name: 'Reasoning effort', category: 'thought_level',
    type: 'select', currentValue: 'high',
    options: [{ value: 'high', name: 'High' }, { value: 'low', name: 'Low' }],
  }],
};
```

Use the opened host Session id and your runtime's ordered event sequence when
publishing. The event has no turn id and grants no mutation authority. Its
envelope, options, choices and groups reject undeclared fields. This new event
requires matching development host and SDK source; it does not promise support
from an older SDK binary.

## Native update metadata

In 0.3 development source, custom ACP composition can supply a thin
`sessionUpdates.project` codec in its runtime definition. Decode only your
Agent's extension namespace. Leave standard session titles and tool names to
the host, which preserves an existing Session title and retains tool identity
across partial updates.

```ts
import type { AgentAcpRuntimeDefinition } from '@happier-dev/plugin-sdk/agents/runtime';

function record(value: unknown): Readonly<Record<string, unknown>> | null {
  return value !== null && typeof value === 'object' && !Array.isArray(value)
    ? value as Readonly<Record<string, unknown>> : null;
}

const sessionUpdates: NonNullable<AgentAcpRuntimeDefinition['sessionUpdates']> = {
  project(update) {
    const input = record(update);
    const native = record(record(input?._meta)?.myAgent);
    if (!input || !native) return null;
    if (input.sessionUpdate === 'tool_call'
      && typeof native.server === 'string' && typeof native.tool === 'string') {
      return { toolMetadata: { mcp: { server: native.server, tool: native.tool } } };
    }
    if (input.sessionUpdate === 'session_info_update' && native.retrying === true) {
      return { diagnostic: { code: 'provider_retry', severity: 'info',
        message: 'The model provider is retrying this response.' } };
    }
    return null;
  },
};
// Pass sessionUpdates in the definition supplied to context.protocols.acp.open.
```

The host merges tool provenance through its existing accumulator and publishes
diagnostics through the Session's informational event owner. A diagnostic
does not complete, pause, or retry a turn. Keep retries with their existing
Agent or host owner, and do not filter ordinary assistant chunks using text
heuristics. This optional executable contract requires the matching development
host; it is separate from the ACP wire epoch and a declarative manifest's
data-only definition.

If your Agent temporarily emits a nonstandard prompt stop reason, the same
codec object can implement `projectStopReason(raw)`. Return an equivalent ACP
v1 value, or `null` when there is no equivalent. Unknown reasons end safely with
the raw value in diagnostics and an unclassified outcome; do not guess success
or failure from a vendor string.

If the custom Agent also supports execution-runs, no second registration is
needed: a session-capable Agent's finite Execution Runs are host-derived from
its registered `sessions` factory, and `AgentRuntime` never carries both
factories. Only a genuinely execution-only Agent registers a standalone
`executionRuns` factory. Do not create a second
public session or run state machine. [Add an Agent](/plugins/guides/agent-modes)
maps the four valid Agent modes.

## Native background continuations

In development source, a custom ACP composition can supply a
`providerTurnSource` when the Agent exposes exact native task and turn
correlation outside its ACP stream. The source registers each continuation
against an admitted parent tool call, supplies ordered updates through the
returned turn sink, and finishes with the native terminal outcome. A late
assistant chunk alone cannot open a turn.

Use the source host's `followJournal` method for the exact native journal
validated by the adapter. It uses the existing transcript follower with a path
grant that ends with the ACP source lifetime. Resolve the journal from the
source host's composed launch environment: inheritance, explicit overrides and
removals are already applied, including the selected home directory. This frozen
snapshot precedes runner-private credential substitution, so managed credential
slots retain their markers; only the native child receives the substituted values.
Release parent tool contexts after
their registration boundary and dispose the observer with its Session. Historical replay cannot establish a new live continuation.
The composer and host retain permission authority; the source supplies
correlation evidence only. Kimi's journal observer is the current consumer.

This seam requires matching development host and SDK versions. It does not
change the declarative ACP manifest or authorize a plugin to create its own
permission or activity owner.
