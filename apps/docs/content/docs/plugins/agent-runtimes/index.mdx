---
title: Agent runtime plugins
description: Add AI agents through manifest-declared agent contributions and executable agent runtimes.
---

An agent runtime plugin adds one or more selectable AI agents to Happier. Agents can run normal sessions, execution-runs, external session browsing, terminal transcript binding, handoff, fork, checkpoint, or other agent runtime surfaces depending on their manifest declaration and `AgentRuntime`.

## Runtime layers

1. The manifest declares `contributes.agents[]` entries. The declaration key is `id`.
2. Activation registers an agent runtime factory with `api.registerAgentRuntime({ agentId, create })`.
3. The factory returns `AgentRuntime`.
4. The host resolves that runtime for sessions, execution-runs, and agent runtime surfaces.
5. Host bridges run the product lifecycle.

## What agent leaves own

Agent runtime leaves own agent-specific facts:

- agent CLI flags and environment encoding
- agent auth materialization quirks
- agent protocol clients
- agent permission-mode translation
- native transcript parsing
- native event mapping into `RuntimeEventV1`
- agent-specific external session source logic

## What Happier host owns

The host owns:

- agent runtime resolution
- plugin context construction
- session and execution-run bridges
- prompt/pending queue lifecycle
- permission request lifecycle
- transcript and session state persistence
- runtime identity publication
- UI and status projection
- process supervision services

Agent leaves should not reimplement those host behaviors. Model-provider selection is a separate domain.
