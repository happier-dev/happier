---
title: Agent runtimes
description: The executable object that binds agent code to Happier runtime contracts.
---

`AgentRuntime` is the executable integration object for a custom
manifest-declared Agent. A declarative ACP Agent has no plugin-owned runtime
factory; start with [the Agent-mode guide](/plugins/guides/agent-modes) to
choose the correct shape.

An `AgentRuntime` owns at least one of `sessions` or `executionRuns`. Optional
typed capabilities expose only behavior declared by that Agent. Separately owned
auxiliary features do not move into the primary runtime. The `/agents/runtime`
entrypoint is projected from one exact owner inventory; new useful capabilities
are added there without a fixed public-name quota or compatibility aliases.

## Code-defined runtime binding

```ts
import { definePlugin } from '@happier-dev/plugin-sdk';

export const { manifest, activate } = definePlugin({
  id: 'com.example.runtime',
  version: '0.1.0',
  entrypoints: { daemon: './dist/index.js' },
  agents: {
    example: {
      declaration: {
        title: 'Example runtime',
        runtime: { kind: 'custom' },
        primary: 'sessions',
        capabilities: {
          sessions: {
            open: ['create'],
            delivery: ['newTurn'],
            cancel: true,
          },
        },
      },
      factory: createExampleAgentRuntime,
      sessionRunnerFactory: {
        module: './agentRuntime.js',
        export: 'createExampleAgentRuntime',
        runtimeApiVersion: 1,
      },
    },
  },
});
```

The `agents.example` local id projects the matching
`manifest.contributes.agents[]` entry and generated activation binding. For a
Session-capable custom Agent, it also needs a distinct named
`sessionRunnerFactory` leaf; execution-run-only custom Agents must not declare
one.

For a complete minimal custom Session package rather than this shape-only
excerpt, start with
[`session-agent`](https://github.com/happier-dev/happier/tree/main/packages/plugin-sdk/examples/session-agent).
From its package root, its maintained author loop is:

```bash
happier plugins dev typecheck .
happier plugins dev build .
happier plugins test .
happier plugins pack . --out ../session-agent.tgz
happier plugins install ../session-agent.tgz --kind archive
```

It demonstrates a custom Session Agent, its distinct runner leaf, a public host
interaction, and cancellation. For an External Sessions companion, managed
Provider, Connected Account purpose, or generation-scoped background work, use
the composite
[`advanced-package-root`](https://github.com/happier-dev/happier/tree/main/packages/plugin-sdk/examples/advanced-package-root)
reference instead.

The final two commands exercise the ordinary selected-file archive and
reviewed install path. Archive installation requires present-user trust
approval; do not add `--trust` to that flow.

## Runtime contents

A runtime can expose session execution through `sessions`, execution-run
behavior through `executionRuns`, and adjacent Agent behavior through optional
typed capabilities.

Not every Agent needs every optional field. It must expose `sessions`,
`executionRuns`, or both; additional surfaces remain separate capabilities.

When one Agent offers both Sessions and finite Execution Runs, its
`executionRuns.open` opens an `AgentSessionRuntime` and returns
`createExecutionRunHostBackendFromSessionRuntime({ request, openSession })`.
That adapter owns Run ordering, terminalization, cancellation, replay, and
cleanup. The plugin leaf opens the Session and may project a provider checkpoint;
it does not author a second Run lifecycle.

## Example pattern

```ts
import type { AgentRuntimeFactory } from '@happier-dev/plugin-sdk/agents/runtime';

export const createExampleAgentRuntime: AgentRuntimeFactory = () => {
  return {
    sessions: {
      open: async (request, context) => createExampleSessionRuntime({ request, context })
    }
  };
};
```

## Focused host policies

Optional fields on the same `definePlugin({ agents: { <id>: ... } })` entry
adapt Agent-specific decisions while preserving host ownership:

- `cliSessionCommand` declares static forwarding, resume, directory, version,
  info-command, runtime-id, and settings-id facts for `happy <agent>`. Its
  optional `buildSessionOptions(input)` receives parsed Agent arguments plus
  host-resolved `settings`, `environment`, and `startOrigin` (`terminal` or
  `daemon`), and returns bounded JSON Session options. It does not receive raw
  argv, a settings store, a dispatcher, or process custody.
- `preflightSessionControls` lets the Agent interpret bounded model, mode,
  configuration, or passive-realtime probes. Happier resolves declared tools,
  materializes settings and environment, owns process/JSON-RPC lifecycles,
  cancellation, caching, dispatch, and result projection. Antigravity, Codex,
  OpenCode, and Pi are positive consumers in current source.
- `sessionStartup.shouldUseDeferredBootstrap(input)` decides only whether that
  Agent is eligible for Happier's existing deferred bootstrap. Claude and Codex
  use this seam; Happier still owns buffering, attachment, cancellation, and
  cleanup.
- `vendorResumeSupport.supportsVendorResume(input)` is consulted only when the
  manifest's `catalog.vendorResume.support` is `experimental`. It receives a
  bounded Agent runtime-selection snapshot, and the host fails closed without
  a positive result. Codex is the current positive consumer.

These fields generate the one activation registration. Do not reproduce the
host ABI registrations in an ordinary author module.

## Design rule

The runtime is an agent leaf. It should adapt agent-specific behavior into Happier contracts. It should not own host session lifecycle, durable transcript writes, execution-run public state, or UI status rules.
