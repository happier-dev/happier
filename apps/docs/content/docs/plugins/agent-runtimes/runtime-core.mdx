---
title: Runtime core
description: The small executable lifecycle seam shared by sessions and execution-runs.
---

`runtimeCore` is the shared executable seam for an agent runtime.

```ts
type RuntimeCoreV1 = Readonly<{
  createSessionRuntime(params): SessionRuntimeV1 | Promise<SessionRuntimeV1>;
  createExecutionRunBackend(params): ExecutionRunBackendV1 | ExecutionRunHostBackendV1;
}>;
```

The object is intentionally small. It creates the executable runtime pieces; it does not run the whole product lifecycle.

## Session creation

`createSessionRuntime(...)` creates a agent runtime leaf. That runtime exposes methods such as `send`, `cancel`, `updateConfig`, `dispose`, permission response behavior, runtime events, and provider session identity.

## Execution-run creation

`createExecutionRunBackend(...)` creates the executable object that can run a bounded or long-lived execution-run. It can return a direct `ExecutionRunBackendV1` or a host-compatible execution-run object built from a session runtime.

## Explicit opt-out

If an agent is selectable but does not support execution-runs, it should declare `contributes.agents[].capabilities.executionRun.supported: false`. Missing `createExecutionRunBackend` without an explicit opt-out is an agent runtime convergence problem.

## Host lifecycle

The host bridge owns:

- starting and executing the session loop
- pending queue delivery
- ready notifications
- permission orchestration
- transcript projection
- runtime identity/facet publication
- durable session state
- cleanup on shutdown, dispose, and failures

Agent leaves emit runtime facts and implement native wire behavior.
