`AgentSessionRuntime` is the public live-session contract from
`@happier-dev/plugin-sdk/agents/runtime`.

```ts
interface AgentSessionRuntime extends Disposable {
  send(request, options?): Promise<AgentSessionSendResult>;
  cancel?(request, options?): Promise<AgentSessionCancelResult>;
  updateConfiguration?(request, options?): Promise<AgentSessionConfigurationResult>;
  compact?(request, options?): Promise<AgentSessionCompactResult>;
  watch(listener): Disposable;
}
```

The session factory receives a typed create, resume, or fork request plus a
bounded `AgentSessionRuntimeContext`. The host supplies authorized launch
environment, timestamped scalar configuration, connected-account references,
MCP launch data, and supported session services when applicable.

`send` receives the canonical host delivery request. Publish strict canonical
events through `watch`; keep raw provider payloads inside the Agent adapter.
Unsupported optional operations return the documented typed unsupported or
unavailable result rather than silently dropping behavior.

`dispose` is idempotent and releases only Agent-owned session resources. It
does not delete host session state, queued input, or transcript state.

## Selected-session terminal preparation

In the current Developer Preview source, `prepareTerminalPresentation` replaces
`prepareProviderCliAttach`. Migrate the factory and Session consumers together;
the host does not fall back to a bare terminal surface when this operation is
missing. Independent terminal surface authoring is unchanged.

The opened Session owns native identity, hooks, and runtime selection. Return
`provider_attach` with the exact native attach metadata for an optional client,
`terminal_launch` with the exact Session's prepared launch plan, or
`managed_terminal` with the handle returned by the existing Session terminal
owner. A managed conversation terminal is not an optional detachable client.

The factory's asynchronous `resolveTerminalPresentation` selects placement and
captures the runtime descriptor before Session creation. The opener consumes
that captured choice rather than reselecting from changed account settings.
Resuming an existing Session retains its accepted choice; capture never bypasses
current feature admission.

The host automatically derives finite Execution Runs from this Session
contract. The host-owned adapter maps Session events and cancellation into the
Run lifecycle, so the plugin must not register a second execution-run path.

For a custom Session Agent, this runtime is created from a distinct named
runner leaf identified by `sessionRunnerFactory`. The `agents.<id>.factory`
author field generates the binding for the same factory object, while the
runner imports only the leaf and never calls `activate`. Do not rely on
process-global singleton state across those realms.

After the generic scaffold, the minimal executable
[`session-agent`](https://github.com/happier-dev/happier/tree/v0.3/packages/plugin-sdk/examples/session-agent)
reference shows this boundary with a public host confirmation and cancellation.
It exercises create and exact-provider-id resume, reasoning and assistant
messages, a tool call/result, one settled terminal event, cancellation during an
interaction, and a truthful unsupported native-fork capability. Its README
contains the maintained install/reload/restart/update/disable/revoke/uninstall
journey and the shared UI selectors.
Use `advanced-package-root` only when the Agent also needs one of its composite
capabilities, such as External Sessions or a managed Provider.

## Idle compaction (0.3 development)

Declare `sessions.compaction.idle.mode: 'host'` when the runtime implements
`compact({ compactionId, trigger: 'idle' })`. Add `manual: true` only when the
same control also accepts manual requests. The host owns the per-Agent defaults
and reads them once when a Session starts; host mode receives no native idle
configuration operand.

Report `usage-observed.promptCache: { lastUseAtMs, ttlMs? }` from the last
provider request. A clock alone is valid: a person's cache-window override can
supply the window. Omit `ttlMs` unless the request's route and cache lifetime
are known. The strict public runtime and Usage capture schemas accept this
field; it does not create another accounting observation.

```ts
import {
  PROMPT_CACHE_DURATIONS,
  resolvePromptCacheLastUseAtMs,
} from '@happier-dev/plugin-sdk/agents/runtime';

const lastUseAtMs = resolvePromptCacheLastUseAtMs({
  turnStartedAtMs,
  lastNonModelItemCompletedAtMs,
});
// Use a duration only after observing the applicable request lifetime class.
const oneHourMs = PROMPT_CACHE_DURATIONS.anthropic.longTtlMs;
```

The helper selects the last non-model item's completion, otherwise the turn's
start, otherwise no clock. Usage receipt and model completion are later than
cache use and cannot supply this fact. A runtime with a genuine provider
request-start event uses that clock directly.

The host retains the latest cache and context-size facts independently, so they
can arrive on separate usage events. A changed fact replaces the Session's one
timer when the pair qualifies; an event carrying neither leaves it alone. The
timer consumes its cache fact and reads live work only when it fires.
Busy or unknown work skips that attempt; disposal
clears the timer. Publish the admitted compaction lifecycle with `trigger:
'idle'` and the same `compactionId` so it folds into one quiet transcript row.
Completed events may include measured `tokenCountBefore` and
`tokenCountAfter` with `tokenCountSource: 'providerReported'`. Idle maintenance
starts no foreground turn or ready
notification. New ordinary input keeps its existing lifecycle.
