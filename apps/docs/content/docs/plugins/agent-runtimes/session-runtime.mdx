---
title: Agent session runtime
description: Implement native Agent sessions with AgentSessionRuntime.
---

`AgentSessionRuntime` is the public live-session contract from
`@happier-dev/plugin-sdk/agents/runtime`.

```ts
interface AgentSessionRuntime extends Disposable {
  send(request, options?): Promise<AgentSessionSendResult>;
  cancel?(request, options?): Promise<AgentSessionCancelResult>;
  updateConfiguration?(request, options?): Promise<AgentSessionConfigurationResult>;
  compact?(request, options?): Promise<AgentSessionCompactResult>;
  watch(listener): Disposable;
}
```

The session factory receives a typed create, resume, or fork request plus a
bounded `AgentSessionRuntimeContext`. The host supplies authorized launch
environment, timestamped scalar configuration, connected-account references,
MCP launch data, and supported session services when applicable.

`send` receives the canonical host delivery request. Publish strict canonical
events through `watch`; keep raw provider payloads inside the Agent adapter.
Unsupported optional operations return the documented typed unsupported or
unavailable result rather than silently dropping behavior.

`dispose` is idempotent and releases only Agent-owned session resources. It
does not delete host session state, queued input, or transcript state.

The host automatically derives finite Execution Runs from this Session
contract. The host-owned adapter maps Session events and cancellation into the
Run lifecycle, so the plugin must not register a second execution-run path.

For a custom Session Agent, this runtime is created from a distinct named
runner leaf identified by `sessionRunnerFactory`. The `agents.<id>.factory`
author field generates the binding for the same factory object, while the
runner imports only the leaf and never calls `activate`. Do not rely on
process-global singleton state across those realms.

After the generic scaffold, the minimal executable
[`session-agent`](https://github.com/happier-dev/happier/tree/v0.3/packages/plugin-sdk/examples/session-agent)
reference shows this boundary with a public host confirmation and cancellation.
It exercises create and exact-provider-id resume, reasoning and assistant
messages, a tool call/result, one settled terminal event, cancellation during an
interaction, and a truthful unsupported native-fork capability. Its README
contains the maintained install/reload/restart/update/disable/revoke/uninstall
journey and the shared UI selectors.
Use `advanced-package-root` only when the Agent also needs one of its composite
capabilities, such as External Sessions or a managed Provider.
