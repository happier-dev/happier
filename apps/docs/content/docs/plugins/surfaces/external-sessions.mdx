---
title: External sessions
description: Contribute Agent-native discovery and transcript access for sessions created outside Happier.
---

External Sessions is an auxiliary Agent contribution. It is not an
`AgentRuntime.surfaces` member. Ordinary author modules declare
`externalSessions` in the Agent's `capabilities.surfaces`, declare its
`surfaces.externalSession.sources`, and place the implementation on the same
`definePlugin({ agents: { <id>: { externalSessions } } })` entry. Generated
activation binds that exact local id.

Import the authoring contract from its final capability path,
`@happier-dev/plugin-sdk/sessions/external`.

> **Development/preview contract.** This page describes the current source-level
> authoring and host behavior. It does not claim that loaded or packaged
> release artifacts expose this surface.

## Low-level ABI equivalent

The following direct `PluginApi` shape explains the generated binding for host
conformance fixtures. It is not a second ordinary authoring path:

```ts
import type { PluginApi } from '@happier-dev/plugin-sdk';
import type {
  AgentExternalSessionsContribution,
} from '@happier-dev/plugin-sdk/sessions/external';

declare const externalSessions: AgentExternalSessionsContribution;

export function activate(api: PluginApi) {
  api.agents.registerExternalSessions('example', externalSessions);
}
```

The contribution has exactly six required methods:

- `resolveSource`
- `listCandidates`
- `resolveLinkIdentity`
- `resolveLinkedIdentity`
- `pageTranscript`
- `readAfterTranscript`

## Callback invocation services

Each of the six callbacks receives the host's bounded invocation controls
(`signal`, `deadlineAtMs`, and `maxSerializedBytes`) plus two host-provided
services: `managedEndpointRead` and the required existing `exec`
(`ExecService`). `exec` remains governed by the Agent manifest's declared
process/tool host access and the current plugin generation. Reuse its existing
process and protocol-client facilities; this surface does not add a process
subsystem, HTTP bridge, callback, registry, or Agent-id host branch. For
example, the current Codex source reuses its existing app-server JSON-RPC
`thread/list` client through this service for native candidate discovery.

`resolveSource`, `resolveLinkIdentity`, and `resolveLinkedIdentity` may return
optional bounded `transcriptMediaReadRoots` (up to 16 absolute roots, each no
more than 4,096 code units in the current preview contract). The host
normalizes and validates this transient producer evidence, then uses it only to
authorize concrete media files referenced by transcript items through the
existing exact-file media allowance/adoption path. Roots are never copied into
`linkData`, persisted or shared state, or transcript records; they grant no
directory-enumeration or write authority.

Bundled and externally loaded plugins use the same contribution, invocation,
and host-access contract. The six callback methods remain exactly six; the
`exec` service is an invocation input, not a seventh callback or host-service
operation. The contextual `services.sessions.external` surface described below
also remains exactly six operations.

## Transcript records

`pageTranscript` and `readAfterTranscript` return
`AgentExternalSessionTranscriptItem`s. Every item's `raw` must be the canonical
repository-wide transcript record `AgentExternalSessionTranscriptRawRecord` —
the same declaration the host persists and every transcript reader parses:

```ts
import type {
  AgentExternalSessionTranscriptRawRecord,
} from '@happier-dev/plugin-sdk/sessions/external';

const userTurn: AgentExternalSessionTranscriptRawRecord = {
  role: 'user',
  content: { type: 'text', text: 'Review the staged diff.' },
};

const agentTurn: AgentExternalSessionTranscriptRawRecord = {
  role: 'agent',
  content: {
    type: 'acp',
    agentId: 'example',
    data: { type: 'message', message: 'Reviewed the staged diff.' },
  },
};
```

A user record is `{ role: 'user', content: { type: 'text', text } }`. An agent
record wraps the provider-native body in an agent record; `{ type: 'acp',
agentId, data }` is the general form for an Agent without a first-party content
dialect. Both accept additional provider-native fields alongside the required
ones.

Decode source rows into that record rather than returning a provider-native
envelope. The host admits the contract once, when it accepts the transcript
result, so a non-record `raw` fails the whole page with the `agent_error`
contribution failure instead of reaching a reader that cannot render it. Keep
source-derived routing facts such as `messageRole` and `localId` beside `raw`,
never inside it, so `raw` never has to be loosened to carry routing.

`raw` is the Agent-direction producer facet. A consuming plugin reading
`SessionsService.external.readTranscript` receives
`ExternalSessionTranscriptItem`, whose recipient-safe projection of this record
is named `data` and typed as plain JSON, because the projection is free to omit
host-private facts. Reading `.raw` off a consumer item yields `undefined`.

## Contextual host service

The contribution above is the Agent-to-host direction. It is distinct from
the host service available to an authorized plugin invocation at
`context.services.sessions.external`. That service exposes exactly six
operations:

- `capabilities`
- `list`
- `attach`
- `readTranscript`
- `followTranscript`
- `takeover`

Import its public DTOs from the same final capability path. Plugins pass only
an opaque `ExternalSessionRef`; they never choose a machine, plugin generation,
resolved source, storage path, link record, or runtime lease.

```ts
import type { PluginInvocationContext } from '@happier-dev/plugin-sdk';
import type {
  ExternalSessionTranscriptFollowEvent,
} from '@happier-dev/plugin-sdk/sessions/external';

export async function inspectExternalSessions(
  context: PluginInvocationContext,
) {
  const external = context.services.sessions.external;
  const page = await external.list(
    { limit: 20 },
    { signal: context.signal },
  );
  const candidate = page.items[0];
  if (!candidate) return;

  const transcript = await external.readTranscript(
    candidate.ref,
    { mode: 'page', direction: 'newer', limit: 50 },
    { signal: context.signal },
  );

  const follow = await external.followTranscript(
    candidate.ref,
    { signal: context.signal },
    async (event: ExternalSessionTranscriptFollowEvent) => {
      // Settle this callback only after the event is durably consumed.
      void event;
    },
  );
  if (follow.status === 'following') {
    await follow.subscription.dispose();
  }

  return transcript;
}
```

`list`, `attach`, transcript reads, public follow, and `takeover` resolve the
current configured Agent/source authority for each new call. A cursor or
subscription from a superseded public generation fails stale rather than
silently invoking replacement callbacks. The private exact-generation follow
used by an already-running native Agent session is host composition and is not
part of this public service.

`takeover(ref, request, options)` starts a durable operation. The request
selects `targetStorageMode: 'external-linked' | 'persisted'` and includes a
caller-stable, nonempty `idempotencyKey`. Reuse the same key after timeout,
cancellation, or an unknown response for the same intent. The result is the
operation reference `{ sessionId, operationId, revision }`, not a claim that
the takeover has already finished. Use the public External Sessions Actions
for status and recovery; plugins do not call the private raw Start RPC or read
complete operation records.

Public candidates, transcript items, operation references, and the strict
shared operation presentation omit machine/account/generation identity,
qualified sources, link metadata, runtime descriptors, private progress,
credentials, claims, and staging paths.

An auxiliary-only Agent may register this contribution without a primary
runtime factory. When an Agent also has a native runtime, both registrations
use the same manifest-declared local ID. The Agent leaf owns source-native
discovery, identity translation, and transcript decoding. The host owns
qualified identity, generation fencing, cancellation, deadlines, result
bounds, link records, selection, transcript projection, and takeover
lifecycle.

## Optional session-hook facet

An Agent with the six-method contribution may register one session-hook
contribution on the same Agent aggregate. It declares a bounded immutable set
of installation variants and exactly two callbacks:

```ts
import type {
  PluginApi,
  PluginInvocationContext,
} from '@happier-dev/plugin-sdk';
import type {
  AgentExternalSessionHooksContribution,
  AgentExternalSessionHookResolveInstallationRequest,
  AgentExternalSessionsContribution,
} from '@happier-dev/plugin-sdk/sessions/external';

declare const externalSessions: AgentExternalSessionsContribution;
declare function resolveAgentSettingsPath(): string;

const hooks = {
  installationVariants: [{
    variantId: 'example-hooks-v1',
    targets: [{
      targetId: 'user-settings',
      format: 'hook_event_json_arrays_v1',
      collectionId: 'hooks',
    }],
    events: [{
      eventId: 'session-start',
      targetId: 'user-settings',
      nativeEventName: 'SessionStart',
      command: {
        kind: 'happier_observation_v1',
        shellDialect: 'posix',
      },
    }],
  }],

  async resolveInstallation(
    request: AgentExternalSessionHookResolveInstallationRequest,
    context: PluginInvocationContext,
  ) {
    if (request.signal.aborted || context.signal.aborted) {
      return {
        ok: false,
        code: 'cancelled',
        message: 'Hook installation resolution was cancelled.',
      };
    }
    return {
      ok: true,
      value: {
        kind: 'supported',
        variantId: 'example-hooks-v1',
        targets: [{
          targetId: 'user-settings',
          absolutePath: resolveAgentSettingsPath(),
        }],
        readiness: { kind: 'ready' },
      },
    };
  },

  async mapHookEvent(request) {
    if (request.signal.aborted) {
      return {
        ok: false,
        code: 'cancelled',
        message: 'Hook event mapping was cancelled.',
      };
    }
    return {
      ok: true,
      value: { kind: 'ignored' },
    };
  },
} satisfies AgentExternalSessionHooksContribution;

export function activate(api: PluginApi) {
  api.agents.registerExternalSessions('example', externalSessions);
  api.agents.registerExternalSessionHooks('example', hooks);
}
```

`externalSessionHooks` is optional, duplicate-rejecting, and may accompany
other same-Agent author fields in any order. The same `definePlugin` Agent entry
must provide the exact-six External Sessions contribution and have its existing
`externalSessions` manifest right. Hook registration adds no capability,
manifest declaration, or separate contribution family. The direct ABI binding
shown above is for conformance only.

`installationVariants` is the complete registration-time snapshot. Each
variant declares its configuration targets and every event the host must
install. Every command selects the closed `posix` or `windows_cmd` shell
dialect; plugins do not supply raw command fragments. The Agent leaf owns
installed-version selection, concrete configuration paths, native event names,
payload parsing, and source-native correlation. The host owns preview and
consent, safe command serialization, configuration writes, durable custody,
credentials, listener lifecycle, and cleanup—even when the plugin is no
longer available.

`resolveInstallation(request, context)` is read-only and is the only callback
that receives `PluginInvocationContext`. It selects a declared variant,
returns every concrete absolute target path, and reports either `ready`,
generic `needs_attention`, or a typed unsupported result. On an installed
configuration, the request may contain a host-derived `custody` projection.
Each owned event-array occurrence includes its verified zero-based
`entryIndex`; immediately before invoking the callback, the host rereads every
target and rejects stale custody whose current input identity differs from the
last verified post-install identity. Plugins cannot supply or persist that
projection. Passive activation, daemon boot, and reload do not invoke
readiness or launch an Agent.

`mapHookEvent(request)` remains request-only. It receives one bounded,
authenticated native JSON payload for the current installation and generation,
then returns `ignored` or source-native identity plus content-free qualified
facts. It never chooses a Happier session or link target. The host drops the
raw payload after the call, resolves the source and linked identity through the
six-method contribution, and admits only a current qualified result. Hook
facts are observations: they do not authorize Agent control, transcript
uploads, follow, takeover, sharing, or configuration changes.

## Optional takeover launch facet

An Agent with the six-method contribution may register one takeover launch
facet on the same Agent aggregate. This facet derives only the Agent-native
launch values needed to resume the freshly resolved linked session:

```ts
import type { PluginApi } from '@happier-dev/plugin-sdk';
import type {
  AgentExternalSessionsContribution,
  AgentExternalSessionTakeoverContribution,
} from '@happier-dev/plugin-sdk/sessions/external';

declare const externalSessions: AgentExternalSessionsContribution;

const takeover = {
  async resolveLaunch(request) {
    if (request.signal.aborted) {
      return { ok: false, code: 'cancelled' };
    }
    if (!request.linkedDirectory) {
      return {
        ok: false,
        code: 'unavailable',
        message: 'This linked session has no working directory.',
      };
    }
    return {
      ok: true,
      value: { directory: request.linkedDirectory },
    };
  },
} satisfies AgentExternalSessionTakeoverContribution;

export function activate(api: PluginApi) {
  api.agents.registerExternalSessions('example', externalSessions);
  api.agents.registerExternalSessionTakeover('example', takeover);
}
```

`externalSessionTakeover` is optional, duplicate-rejecting, and may accompany
the other same-Agent author fields in either order. It uses the existing
`externalSessions` manifest right: there is no takeover capability,
contribution family, or additional manifest declaration. The same code-defined
Agent entry must also provide that Agent's exact-six External Sessions
contribution or the complete activation is rejected. A primary runtime factory
is not required for the declaration, so auxiliary-only and declarative ACP
Agents can provide the facet; an actual takeover still requires a current
spawnable primary runtime immediately before spawn. The direct ABI binding
shown above is for conformance only.

Immediately before `resolveLaunch`, the host calls the same current
generation's `resolveLinkedIdentity` and uses that fresh successful result.
The callback receives:

- the host-owned `signal`, `deadlineAtMs`, and `maxSerializedBytes` invocation
  controls;
- `linkedSessionId` correlation, limited to 2,000 code units;
- the freshly resolved `source`, `remoteSessionId`, and `linkData`; and
- optional `linkedDirectory` context, limited to 10,000 code units.

Persisted session metadata alone is never launch authority. The wrapper binds
the call to the current Agent generation, combines caller cancellation with
generation retirement, enforces a 15-second deadline and a 262,144-byte
settled-result limit, and rejects malformed, oversized, cancelled, retired, or
late results instead of truncating or admitting them. Cancellation is
cooperative, so callbacks must honor `request.signal` and
`request.deadlineAtMs`. `remoteSessionId` is limited to 2,000 code units, and
`resolveLaunch` takes exactly this one request argument—there is no
`PluginInvocationContext` second argument or plugin-controlled deadline.

A successful callback returns the normal External Sessions result envelope
with exactly:

```ts
{
  ok: true,
  value: {
    directory: string;
    backendModeHint?: string;
    environmentVariables?: Readonly<Record<string, string>>;
  };
}
```

`directory` is required and limited to 10,000 code units.
`backendModeHint`, when used, is the Agent's existing narrow backend-mode
vocabulary and is limited to 256 code units. Environment variables are limited
to 64 entries, 128 code units per key, and 16,384 code units per value. Every
key must also pass that Agent's existing process-environment authorization and
the host's reserved/custody-key denial; one invalid key rejects the whole plan.

This callback does not choose the target Agent, existing/resume identity,
transcript storage or authority, directory admission, Connected Services,
Pending/admission behavior, runtime services, or spawn/control lifecycle. Do
not return `SpawnSessionOptions`, `BackendSessionLaunchHintsV1`,
`resumePlanOptions`, session-state updates, source/session identities,
metadata, or other launch hints. The host privately maps the accepted fields,
then rechecks both the originating generation and a current spawnable primary
runtime immediately before the spawn effect. Retirement or replacement fails
closed with no spawn.

Takeover is a sibling facet, not a seventh External Sessions method. There is
no alias, method-presence fallback, broader launch carrier, or plugin-selected
takeover mode: the host retains quiescence, admission, transcript, and lifecycle
authority for both linked and persisted takeover flows.

Registering the facet does not by itself advertise external-linked takeover.
That mode also requires the Agent manifest's
`surfaces.externalSession.externalLinkedTakeover.writerSafety` to be
`native_prevention`. Use `unsupported` when the native Agent cannot prove that
another writer to the same native session is excluded. These are the only
accepted values. Observation, quiet files, process presentation, and the
defensive `external_writer_conflict` error are not writer-safety capability
evidence; a future detection-based mode would require a separately approved
contract and consumed host fence.

## Optional observation facet

An Agent with the six-method contribution may also provide one
`externalSessionObservation` facet on the same `definePlugin` Agent aggregate.
The direct ABI equivalent is:

```ts
import type { PluginApi } from '@happier-dev/plugin-sdk';
import type {
  AgentExternalSessionObservationContribution,
  AgentExternalSessionsContribution,
} from '@happier-dev/plugin-sdk/sessions/external';

declare const externalSessions: AgentExternalSessionsContribution;
declare const observation: AgentExternalSessionObservationContribution;

export function activate(api: PluginApi) {
  api.agents.registerExternalSessions('example', externalSessions);
  api.agents.registerExternalSessionObservation('example', observation);
}
```

The observation contribution has exactly three required operations:
`describeResource`, `observeResource`, and `reconcileResource`.
`describeResource` is grouping-only and returns exactly `{ resourceKey,
linkKey }`; it grants no watch, read, or observation authority. The host obtains
the authoritative descriptor set only through
`reconcileResource({ purpose: 'resource_descriptors', ... })`. Those
descriptors carry the required `changeObservation` disposition:
`observe_resource`, `watch_file_changes`, or `reconcile_only`. A
`watch_file_changes` descriptor supplies the strict
`ExternalAgentObservationWatchFileChangesV1` shape.

`observeResource` receives host-owned `requestReconcile()` and
`requestTranscriptRefresh(linkKey)` callbacks. `reconcileResource` receives
and returns the same required `purpose` discriminant:
`observation_evidence` or `resource_descriptors`. There is no fourth
operation, alias, or omitted-purpose default.
