title: ACP Agent runtime example
description: A native AgentRuntime that composes an ACP session.
---

Use ACP in one of two modes; they must not be blended.

## Declarative ACP

Declare `runtime.kind: 'acp'` with the cold transport, optional strict
data-only `definition`, Session primary, and capabilities. The definition can
contain only `modelConfigOptionId`, bounded `stderrRules`, and an MCP policy of
`pass_through` or `drop`; the host normalizes it once and constructs the
runtime. Kiro is the current source example. Do not add a plugin factory,
activation registration, runner locator, or runner module.

## Custom ACP composition

Use a custom Agent when a plugin leaf must adapt protocol behavior before it
opens ACP. Its declaration is `runtime.kind: 'custom'`; its
`agents.<id>.factory` field generates registration, and a Session-capable Agent
provides the exact distinct runner factory leaf/locator.

1. Return an `AgentRuntime` with a `sessions.open(request, context)` method.
2. Inside `open`, call `context.protocols.acp.open(request, options)` and return the resulting `AgentSessionRuntime`.

Put executable Agent-specific authentication, dynamic model projection, tool
shaping, and protocol extensions in the custom ACP options. The host retains
shared session, input, transcript, activity, and persistence ownership.
