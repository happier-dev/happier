---
title: Filesystem service
description: Use typed, scoped paths for plugin runtime files.
---

The `/fs` type entrypoint, `filesystem` HostAccess declaration, and
`context.services.fs` are available in the current source contract. The
[capability matrix](/plugins/manifest/availability) records loaded-platform and
release evidence separately from source availability.

A `PluginPath` names a supported root plus a relative path:

- `pluginData`
- `workspace`
- `project` with a project id

The service exposes `readFile`, `writeFile`, `stat`, `list`, and `remove`. Methods are abortable, reads can be byte-bounded, and listings are cursor-bounded.

In 0.3 development source, the native runtime entrypoint
`@happier-dev/plugin-sdk/fs` also exports `joinNativePath`, `joinPosixPath` and
`isWindowsAbsolutePath`. Native joins use the executing Machine's path rules;
POSIX joins retain remote and container namespaces on every platform. These
string operations do not expand home directories, access files or grant access.

In 0.3 development source, pass `maxBytes` or a page `limit` when the owning
operation needs a budget. The in-process service has no additional read-byte or
page-size ceiling; omitting those options reads or lists the complete result.

## Observe native file metadata in development

The unreleased `observeMachinePath` method is available only inside an admitted
Machine-native invocation with a valid native path. Manifest filesystem
locations disclose intended access; they do not restrict trusted plugin code.
It reports file identity and size changes, not content. Its guarded `read()`
rechecks metadata, and `dispose()` waits for native observer cleanup. Honor the
invocation's cancellation and await disposal when demand ends.

This does not add a Machine root to `PluginPath`, grant writes, or permit a
Machine path as a command working directory. A log reader still needs its own
current-generation admission and redaction. See the
[native log observation example](/plugins/guides/background-services#read-bounded-native-logs-in-development).

Ordinary `PluginPath` operations retain relative portable-path validation,
root-binding availability and operating-system errors. In 0.3 development
source, a selected workspace symlink may resolve outside that root; manifest
path prefixes and read/write declarations do not add per-plugin access fences.
Untrusted native Agent payloads retain their separate root validation.

## Rules

- Do not write Happier session, transcript, daemon, or registry state files directly.
- Do not store secrets in ordinary files or plugin storage.
- Use the owning SDK path type instead of concatenating host filesystem roots.
- Avoid preserving absolute build-machine paths in a package.
- Treat direct ambient filesystem access by trusted code as outside the host-mediated access contract, not as permission granted by a manifest row.
