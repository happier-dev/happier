---
title: Filesystem service
description: Use typed, scoped paths for plugin runtime files.
---

The `/fs` type entrypoint and `filesystem` HostAccess declaration are available
in the current source contract. `context.services.fs` remains deferred in the
[capability matrix](/plugins/manifest/availability) until a maintained external
development-source plugin proves lifecycle and real invocation in the current
loaded development stack, including currentness. It is not supported or
advertised for ordinary author use while deferred.

A `PluginPath` names a supported root plus a relative path:

- `pluginData`
- `workspace`
- `project` with a project id

The service exposes `readFile`, `writeFile`, `stat`, `list`, and `remove`. Methods are abortable, reads can be byte-bounded, and listings are cursor-bounded.

## Rules

- Do not write Happier session, transcript, daemon, or registry state files directly.
- Do not store secrets in ordinary files or plugin storage.
- Use the owning SDK path type instead of concatenating host filesystem roots.
- Avoid preserving absolute build-machine paths in a package.
- Treat direct ambient filesystem access by trusted code as outside the host-mediated access contract, not as permission granted by a manifest row.
