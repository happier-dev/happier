title: Plugin UI
description: Choose a host-rendered, hosted web, or React Native plugin surface.
---

Happier has three public Plugin UI models. Choose the narrowest one that fits the experience:

- **Declarative host-rendered UI** for settings, actions, and other forms the host can render from manifest descriptors.
- **Hosted web UI** for an isolated web application that communicates through the public host API.
- **React Native UI** for a trusted, host-integrated component that needs the app's native UI model.

These models have different trust and isolation properties. A hosted web surface is an isolated UI boundary. React Native plugin code is trusted package code and runs in the client realm; it is not a sandbox.

## Host API

Hosted web constructs its host API from the injected transport bootstrap:

```ts
import { createPluginUiHostApiClient } from '@happier-dev/plugin-sdk/ui/client';

const host = await createPluginUiHostApiClient();
const context = await host.context();
```

React Native does not use that bootstrap client. Its exported
`PluginUiRenderSurface` receives a `PluginUiRenderContext` with `hostApi`,
surface context, plugin/view identity, and cancellation directly:

```tsx
import type { PluginUiRenderSurface } from '@happier-dev/plugin-sdk/ui';

export const renderSurface: PluginUiRenderSurface = ({
  hostApi,
  surface,
  signal,
}) => {
  // Render native UI and call hostApi methods from event handlers.
  return null;
};
```

Authors do not construct or import a Happier-internal transport in either
model.

## Accessibility, currentness, and offline behavior

Executable UI authors own the semantics inside their renderer while it is
interactive. Treat accessibility and environment support as part of the
renderer contract:

- use semantic controls with localized names, roles, state, reading order, and
  visible keyboard focus
- support keyboard operation, screen readers, Dynamic Type or 200% zoom,
  high contrast, RTL and expanded strings, and reduced motion
- keep touch targets at least 44×44 points on iOS and 48×48 dp on Android
- consume `surface.locale`, `direction`, `colorScheme`, `contrast`,
  `textScale`, `reducedMotion`, `screenReaderEnabled`, and `safeAreaInsets`
  instead of guessing host settings

The host owns installed-generation currentness and host API availability.
Authors must not cache a separate “current” generation or implement a
functional offline mode. Handle unavailable host operations and cancellation,
and let a replacement render context or hosted-web `watchContext` update the
environment.

When the daemon disconnects, Happier may keep the last mounted renderer as a
visual, non-interactive snapshot. Its actions, focus, and host mutations are
blocked. Because arbitrary executable subtrees cannot safely expose controls
as read-only semantics, the host announces a localized static summary from the
surface's declared display metadata. Give every executable surface a meaningful
localized title, and keep the last rendered visual state understandable without
requiring an action. Reconnection revalidates generation, policy, and context;
it does not create a second trust prompt.

## Build artifacts

Executable UI is built into `dist/happier-plugin-ui` and described by `ui-artifacts.json`. Use the public build helpers from `@happier-dev/plugin-sdk/ui/build`; the host verifies emitted artifacts before serving or loading them.

Start from a generated UI project when possible:

```bash
happier plugins scaffold ./my-plugin \
  --id com.example.my-plugin \
  --name "My plugin" \
  --ui reactNative
```

Use `--ui hostedWeb` for the hosted web template.

## Boundaries

- Keep placement, identity, compatibility, and requested host access in the cold manifest.
- Use only public SDK paths. Do not import app, daemon, or protocol internals.
- Treat the whole installed package as the trust unit, including client code.
- Use `context.ui` from daemon invocations for host-owned prompts, notifications, status, widgets, title, and composer controls; it is separate from executable surface rendering.
