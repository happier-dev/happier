title: UI artifacts
description: Build, digest, and verify portable plugin UI artifacts.

The daemon-owned UI compiler writes one portable artifact tree:

```text
dist/happier-plugin-ui/
  ui-artifacts.json
  react-native/<artifactId>/entry.cjs.bundle
  hosted-web/<artifactId>/...
```

Each executable artifact is one minified, platform-neutral CommonJS bundle used
unchanged by web, iOS, and Android. The manifest names its `artifactId`, exported
functions, content digest, and compatible Host UI API range. It does not contain
platform-specific entries, framework patch versions, Module Federation module
paths, or author-selected bundler configuration.

The same-realm host map supplies only these exact specifiers:

```text
react
react/jsx-runtime
react/jsx-dev-runtime
react-native
react-native-web
@react-navigation/native
@react-navigation/native-stack
react-native-reanimated
@happier-dev/plugin-ui
@happier-dev/plugin-ui/components
@happier-dev/plugin-ui/hostApi
@happier-dev/plugin-ui/data
@happier-dev/plugin-ui/declarative
@happier-dev/plugin-ui/environment
@happier-dev/plugin-ui/advanced
@happier-dev/plugin-ui/ansi
@happier-dev/plugin-sdk/machine-provisioners
@happier-dev/plugin-sdk/ui/client
```

The build rejects imports from the host-internal `presentation` implementation
and its subpaths. Use the author exports from `components` or the package root.

The loader does not use prefix matching. `zod`, Happier Protocol, AJV,
semver, the Plugin SDK root, and every other plugin dependency are bundled into
the artifact; they are not host-provided modules. Import `react-native`, not
`react-native-web`, from executable plugin source. This fixed map preserves
identity-sensitive singletons; it is a loading contract, not a sandbox.

## Build contract

```bash
happier-plugin-build-ui --project-root .
```

Executable artifacts are discovered from manifest references and exact package
exports named `./happier-plugin-ui/<artifactId>`. For example:

```json
{
  "exports": {
    "./happier-plugin-ui/main-native": "./src/ui/renderSurface.tsx"
  }
}
```

The referenced module exports the function named by the contribution, such as
`renderSurface` or `activate`. There is no `pluginUiBuild.ts`, platform matrix,
container name, or module path to keep in sync.

Hosted web remains a distinct static capability. Put its files under
`.happier-plugin/ui/hosted-web/<artifactId>/`, including a root `index.html`.
Files are copied and digested recursively. If the directory contains
`entry.ts`, the builder compiles it as a browser application to
`assets/app.js`; `index.html` should load that file. Symlinks and non-regular or
empty files are rejected.

## Runtime verification

The daemon verifies every declared file and the complete artifact digest before
making bytes available. Clients request bytes by digest and evaluate executable
artifacts in the app realm through the fixed host-module map. Unknown imports or
missing exports fail only the affected plugin surface; a previously verified
local artifact may remain as the last-known-good visual while current host
operations are unavailable.

Release and availability metadata can arrive before artifact bytes. The client
fetches the exact digest lazily from an eligible cache, app bundle, daemon, or
Account-hosted source and verifies it before adoption. The digest identifies
bytes only: it does not select a release, grant trust, or identify a daemon
occurrence. Account release intent selects portable installed UI, while the
selected daemon projection supplies bundled first-party and trusted
development/drop-in UI.

Artifact paths must be relative, non-traversing, and portable. Authors never
write final digests or select a client-side loader.

## Session visual authoring in development

Caller-authored Session visuals are not installed plugin artifact trees. In the
unreleased 0.3 SDK, use the public producer-derived
`PluginUiActionInputFor<'session.board.item.upsert'>` from
`@happier-dev/plugin-sdk/ui` and the ordinary host `executeAction` API. The input
supports declarative documents, an HTML bundle or a configured widget instance;
new visuals default to transcript. Board/both needs explicit placement. Pin and
Unpin change the same item through the layout Action, not a duplicate widget.

`ArtifactHtmlBundleV1`, `artifactHtmlBundleFromBodyV1` and
`buildArtifactHtmlDocumentV1` are available from that public SDK entry. The
single-body convenience helper produces the same entrypoint/files bundle; do
not send a string as `source`. Include local assets and use the admitted network
policy rather than a remote client bootstrap. No host-internal imports or
invented installed-plugin identity are needed.

Reuse public `@happier-dev/plugin-ui/components` components, including
`StackedSeriesChart`, for trusted native presentation, and
`@happier-dev/plugin-ui/declarative` for the shared declarative rendering
contract. In 0.3 development source, multi-series declarative charts use neutral
long rows with typed `x`, `series` and `value` fields; `bar`, `area` and `line`
styles share that chart renderer. Use the SDK document producer to validate the
document. Live Usage widgets consume ordinary Resources and the
platform's declared input bindings, not copied query implementations.
