Plugin UI artifacts are written to:

```text
dist/happier-plugin-ui/
  ui-artifacts.json
  hosted-web/<contributionId>/...             # one portable Vite graph
  react-native/<contributionId>/...           # ios/android, Re.Pack-built
  react-native-web/<contributionId>/...       # web, Vite + react-native-web-built
```

The hostedWeb scaffold emits the packaged artifact and canonical bootstrap contract; each host then reports the one physical frame adapter it can construct, so packaged runtime availability is per host rather than a single global claim. See [Hosted web UI](/plugins/ui/hosted-web#build-and-runtime-availability) for the derived per-host status. An emitted hosted-web directory is not an advertised runtime contract by itself.

A React Native contribution can emit platform-specific entries distinguished by
`platform` and `builtWith.bundler` (`repack` for iOS/Android and `vite` for
React Native Web). Use the scaffold and public build presets rather than
assuming that one declared contribution automatically targets every client.

## Build contract

The build command emits a manifest and computes content digests from emitted
bytes. Authors do not supply the final digest manually.

```bash
happier-plugin-build-ui --project-root .
```

The command discovers one of these config files at the plugin root:
`pluginUiBuild.mjs`, `pluginUiBuild.js`, `pluginUiBuild.ts`,
`happier-plugin-ui.config.mjs`, `happier-plugin-ui.config.js`, or
`happier-plugin-ui.config.ts`. It also accepts `--config <path>` and prints the
same contract with `--help`.

The React Native scaffold uses the public SDK build surface and declares every
Preview artifact it is responsible for. The managed builder derives its Vite
and Re.Pack configuration for that operation; the package declares source
targets only. Do not replace them with a web-only target or a second hand-run
bundler path:

```ts
import { defineBuildConfig } from '@happier-dev/plugin-sdk/ui/build';

export default defineBuildConfig({
  targets: [{
    rendererId: 'main-native',
    entry: 'src/ui/renderSurface.tsx',
    kind: 'reactNative',
    platforms: ['web', 'ios', 'android'],
    module: {
      containerName: 'com_example_my_plugin_main_native',
      modulePath: './renderSurface',
      exportName: 'renderSurface',
    },
  }],
});
```

The hosted scaffold instead declares one graph with no `platforms` field:

```ts
{
  rendererId: 'main-web',
  entry: 'src/ui/index.ts',
  kind: 'hostedWeb',
}
```

The platform-admission owner, not this build config, decides whether that exact
hosted graph is usable in a browser/desktop frame, iOS WebView, or Android
WebView.

### Client activation artifacts

A React Native build target may contain a client `activate(api)` module without
being a visual renderer. Client Actions and conversation Voice providers use
this shape when their declaration points at an exact client artifact, module,
and `activate` export:

```ts
import { defineBuildConfig } from '@happier-dev/plugin-sdk/ui/build';

export default defineBuildConfig({
  targets: [{
    rendererId: 'client-runtime',
    entry: 'src/clientRuntime.ts',
    kind: 'reactNative',
    platforms: ['web', 'ios', 'android'],
    module: {
      containerName: 'com_example_plugin_client_runtime',
      modulePath: './clientRuntime',
      exportName: 'activate',
    },
  }],
});
```

For this non-renderer target, `rendererId` is the build API's retained name for
the emitted artifact id. It must equal the declaration's `artifactId`; the
`modulePath` and `exportName` must also match. Do not add a
`contributes.ui.renderers` row unless the artifact separately exports a visual
surface that a UI contribution actually mounts.

The one `reactNative` target emits a React Native Web artifact for `web` and
Re.Pack artifacts for `ios` and `android`. The client source exports the normal
`activate(api)` entrypoint and registers its declared local ids there. See
[Actions, tools, and commands](/plugins/api/actions-tools-commands#invocation-surface-and-execution-target)
for the matching Action declaration and handler.

If no config is found, the config is invalid, or it declares no targets, the
command exits non-zero with an actionable error.

## Runtime verification

The daemon re-derives the digest when loading artifacts. Mismatched, missing, unsafe, or schema-invalid artifact trees fail closed.

Artifact kinds may use bundle suffixes such as `reactNativeBundle`. Runtime mode ids do not: use `reactNative`.

The daemon-selected installed generation is the only current artifact
authority. A client cache may preserve a verified last-mounted snapshot during
disconnection, but it does not authorize host calls or select current bytes.
After reconnect, the client revalidates the complete graph, generation,
compatibility, and policy before restoring interaction.

## Path safety

Artifact paths must be relative, non-traversing, and safe to serve. Do not include absolute paths or symlinks.
