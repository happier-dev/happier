Use an isolated web surface for a packaged application, or a self-contained
HTML bundle with a declared entrypoint and local assets.

## Inline HTML in development

The current development SDK also accepts `hostedHtml`. This is a
prepublication author contract, not a released runtime-support claim.

Every inline document must initialize the public SDK client, including a
document that only displays content. In 0.3 development, readiness and SDK
negotiation wait for the host without an implicit timeout; cancellation,
retirement, transport failures and explicit caller budgets still apply. An
HTML string with no client initialization is not a complete surface. Start
with a client entry such as:

```ts
import { createPluginUiRenderContext } from '@happier-dev/plugin-sdk/ui/client';

const context = await createPluginUiRenderContext();
const summary = document.createElement('h1');
summary.textContent = 'Summary';
document.body.append(summary);
context.signal.addEventListener('abort', () => summary.remove(), { once: true });
```

Include that entry and its SDK dependencies in a canonical `ArtifactHtmlBundleV1`.
Export the bundle from your build as `htmlBundle`, then declare it on the surface:

```ts
import { definePlugin, defineUiSurfaceDefinition } from '@happier-dev/plugin-sdk';
import { htmlBundle } from './ui/summaryDocument.js';

const summary = defineUiSurfaceDefinition({
  id: 'summary',
  placement: 'appPage',
  title: 'Summary',
  renderer: {
    kind: 'hostedHtml',
    source: htmlBundle,
  },
});

export const { manifest, activate } = definePlugin({
  id: 'com.example.summary',
  version: '0.1.0',
  entrypoints: { daemon: './dist/index.js' },
  ui: { surfaces: [summary] },
});
```

This form creates no Artifact build target or hosted-asset lookup. The source
has `v: 1`, an `entrypoint`, and a `files` map. Each file
declares its MIME type and canonical padded base64 bytes. Use confined relative
paths; include every referenced local asset. A one-file HTML document uses the
same representation, not a separate string source. There is no independent
1 MiB HTML ceiling or compatibility-projection ceiling.

The shared document builder resolves local scripts, module imports, styles,
images, fonts and runtime resource reads inside the opaque frame. External
network stays closed until the caller's admitted network policy is wired;
declaring an origin alone does not open it. The packaged `hostedWeb` form below
remains the separate installed-asset build workflow.

The host supplies bootstrap configuration, not a second client runtime. Do not
load the client from a remote script or invent a transport. The document uses the same isolated
frame, request, cancellation, and retirement path as packaged hosted web;
inline source does not grant additional host methods or network access.

Browser and native source adapters must be validated in their real hosts.
Passing source and component tests does not establish packaged desktop,
iOS, or Android support; those loaded-runtime checks remain required before
publication.

## Widget operations in development

In 0.3 development / Developer Preview authoring, hosted HTML pages do not
embed host widget areas: the plugin owns the whole iframe. Manage widgets
through ordinary `widgets.*` Actions, subject to the same captured scope,
admission and approval policy as other callers. See the generated
[host Actions](/plugins/api/host-actions) for their current schemas.

There is no hosted widget-area API or embedding helper. Native and declarative
page embedding are described
under [personal widget areas](/plugins/ui/react-native#personal-widget-areas-in-development).

## Scaffold

Create a hosted-web source package with the ordinary beginner command:

```bash
hdev plugins create ./my-hosted-plugin \
  --id com.example.my-hosted-plugin \
  --name "My hosted plugin" \
  --ui hostedWeb

cd my-hosted-plugin
hdev plugins dev
```

The scaffold creates a code-defined plugin declaration, one conventional
`.happier-plugin/ui/hosted-web/<artifact-id>` artifact directory, relative assets,
and the managed author scripts. `plugins dev`, `hdev plugins dev build .`, and
`hdev plugins pack .` use the same UI-build owner. During `plugins dev`, the
daemon observes the selected source and runs the build before candidate
adoption. A failed build prevents adoption and leaves the last accepted
process-local occurrence current for that daemon lifetime.

## Bootstrap boundary

The hosted application gets its bound surface context after the host accepts
its ready message. Use the public client and treat the returned context as the
single source of surface identity, currentness, cancellation, theme, locale,
and host operations:

```ts
import {
  applyPluginUiThemeCssVariables,
  createPluginUiRenderContext,
} from '@happier-dev/plugin-sdk/ui/client';

const context = await createPluginUiRenderContext();
applyPluginUiThemeCssVariables(context.surface.theme, document.documentElement);
await context.hostApi.executeAction('save-note', { note: 'hello' }, { signal: context.signal });
```

Do not construct a bridge, choose an origin, parse `location`, or encode launch
input/subpaths into a URL. Any launch facts come only through the host-issued
context; the host retires `context.signal` when the surface is no longer
current.

The framed transport uses an opaque instance ID and mount nonce. Neither is
plugin, Session, or destination identity, and neither grants authority. The
host binds requests to the admitted mount. Installed-plugin metadata travels
separately in the context so local Action, Resource, and destination references
keep their normal meaning. A replacement document receives a new physical
identity; presentation changes do not create a new plugin lifetime.

## Entity drag bindings (development)

The **0.3 development / Developer Preview** SDK exports
`bindHostedEntityDragSource` and `bindHostedEntityDropTarget` from
`@happier-dev/plugin-sdk/ui/client`. After the ordinary bootstrap, bind an
element to a declared local source or target using the bound `hostApi`, a
mount id and its reference or target-local input. Await the returned `ready`
admission result, and call `dispose()` when the element retires. A source can
receive an intentional Organize `handle` and `onState` feedback; its returned
mount exposes staged keyboard, chooser, commit and cancel operations.
Targets also accept `onState`: it reports that mounted target's current
admission, pending settlement and retirement through the same host watch.
Refused targets stay quiet; show their reason in the carried preview or chooser.

Declare `readEntityDragItem`, `updateEntityDragDrop` and `watchEntityDragDrop`
as required host methods when the renderer depends on this behavior. The
existing method advertisement and renderer admission decide whether it can
mount. Read refusal or failed readiness as unavailable rather than creating
a frame-local fallback. The bindings report current frame geometry to the
host; the host converts coordinates and selects the target through the same
runtime used by React and declarative sources. They do not decode text into
identity or consume ordinary OS file/text drags.

Source/target declarations, pure admission and Action allowlists are described
in the [entity authoring guide](/plugins/ui/react-native#entity-drag-and-drop-development).
Targets declare the same optional bounded `preview.glyph` as native targets;
the host's carried preview renders that mark. The hosted staged-move dock
retains readable outcome words without importing the host's icon pack. Hosted
Plugin UI Organize handles use the shared grip trigger, keyboard input and
focus-visible chrome rather than a separate HTML-button interaction owner.
Mount retirement and Account withdrawal prevent unissued effects; an already
dispatched Action retains its own acknowledged or unknown outcome. These
source contracts do not certify a loaded iframe, desktop child or native
WebView journey.

## Browser-hosted data and withdrawal

If a browser-hosted frame is admitted, it is an online **Plaintext Accounts
only** path; E2EE Account data is unavailable through this runtime. The host
serves only the static packaged artifact through its own HTTPS artifact origin
and scoped bootstrap capability. Authors do not add cookies, an app bearer,
their own origin, a refresh channel, or a revocation endpoint.

On logout or Account switch, the host retires the bridge and controller
immediately, which aborts the bound context and blocks new host operations. It
cannot recall static bytes already downloaded by a browser. Treat the rendered
artifact as ephemeral UI, keep sensitive state out of static assets, and do not
promise an author-controlled immediate recall mechanism.

## Build and runtime availability

`kind: 'hostedWeb'` deliberately declares one portable web graph and does not
accept author-owned `platforms`. The graph never varies by host. What varies is
the physical frame adapter each host can construct, and every host reports that
one fact to runtime admission. Authors never select, branch on, or work around
it, and it is never valid to substitute a dev server, remote URL, blob URL,
source checkout, or URL-encoded launch data for the adapter.

Each row below is derived by the host that owns it — the browser probes a
sandboxed iframe, the packaged desktop shell asks its Artifact frame owner, and
the mobile hosts report the native adapter their renderer already proved. A
host that cannot construct its adapter reports the typed reason instead, so an
unimplemented cell is never presented as a generic "desktop is unsupported"
claim.

| Host | Frame adapter | Reported runtime status |
| --- | --- | --- |
| Browser | DOM iframe | `{ platform: 'web', adapter: 'domIframe' }` |
| Packaged desktop — macOS | Direct Wry child (`WKWebView` subview) | `{ platform: 'desktop', adapter: 'wry' }` |
| Packaged desktop — Windows | Direct Wry child (child `HWND` + WebView2) | `{ platform: 'desktop', adapter: 'wry' }` |
| Packaged desktop — Linux/X11 | Direct Wry child (native X11 container window) | `{ platform: 'desktop', adapter: 'wry' }` |
| Packaged desktop — Linux/Wayland | None | `desktop_hosted_artifact_wayland_gtk_container_unimplemented` |
| Packaged desktop — Linux, no display server | None | `desktop_hosted_artifact_linux_display_unavailable` |
| iOS | `WKWebView` | `{ platform: 'ios', adapter: 'WKWebView' }` |
| Android | `WebViewAssetLoader` | `{ platform: 'android', adapter: 'WebViewAssetLoader' }` |

The macOS, Windows and Linux/X11 direct-Wry children are implemented and
selectable at runtime. This capability fact does not itself prove a loaded
hosted-Artifact product row: a current packaged loaded run is still required
for Preview publication/support claims, and a compiling implementation, a
passing unit test, a CI build matrix, or desktop-browser QA does not stand in
for it.

Linux/Wayland is the one desktop cell with no adapter at all. Wry's
`build_as_child` constructor requires an X11 parent window handle and returns
`UnsupportedWindowHandle` under Wayland, which has no X11-style native
subwindow. Wry's supported Wayland route builds into an application-owned
`gtk::Fixed` that overlays the shell's own webview — a different host widget
topology than the direct child every other desktop cell uses — so the shell
reports the typed reason rather than a frame it cannot construct.

Availability is a transport fact only. It does not attest to Artifact hosting,
Account eligibility, an endpoint, or any other server-owned admission
condition.
