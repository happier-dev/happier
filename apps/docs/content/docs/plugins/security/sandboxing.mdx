---
title: Isolation and boundaries
description: Know which Plugin Platform surfaces are isolated and which are trusted code.
---

Happier plugins are trusted code packages. The Plugin SDK is a supported interface, not a security sandbox.

## Trusted executable code

- Daemon entrypoints run as trusted local code.
- React Native plugin UI runs as trusted client code.
- Dependencies and build outputs belong to the same package trust decision.

Manifest host-access requests constrain host-mediated services. They do not prevent trusted code from using ambient process capabilities, so review package source and dependencies before selecting **Install & Trust**.

## Isolated UI

Packaged hosted web is currently unavailable because no Artifact-backed frame adapter has passed its platform feasibility gate. A future iframe or WebView boundary would limit the UI's direct access to Happier client internals, but it would not sandbox daemon code or other executable code shipped by the same plugin.

## Declarative surfaces

Host-rendered settings and other declarative surfaces contain data the host validates and renders. Prefer them when arbitrary client code is unnecessary.

TypeScript types, manifest validation, artifact digests, and package layout improve correctness and reviewability. They are not substitutes for package trust.
