---
title: Trust model
description: Understand Happier's whole-package Install & Trust boundary.
---

Plugins are trusted code packages, not sandboxed extensions. A plugin can contain daemon code and React Native client code with the privileges of the Happier process or client realm in which it runs.

## Install & Trust

Happier validates and projects the cold manifest before importing executable code. Installing executable code requires an explicit **Install & Trust** decision for the whole package:

```bash
happier plugins install <archive-path> --kind archive
```

The interactive flow presents the exact package facts and records the approving
user's decision. A headless installation that still needs trust stops for
review. A manifest contribution, action, command, or runtime registration
cannot approve or widen package trust.

Trust the package only after reviewing its source, build inputs, dependencies, declared host access, executable entrypoints, and UI artifacts. Updating the package can change any of those surfaces and deserves the same scrutiny.

## Development sources

`happier plugins dev` starts the supported local development loop from the
plugin directory. The CLI inspects the project, observes source changes, and
submits each captured batch to the running daemon. The daemon-owned candidate
lifecycle prepares author dependencies before it validates and adopts a
development generation. Development convenience does not turn untrusted code
into a sandbox.

## Static projection

The host can show identity, contributions, settings, requested access, and installation review information from `.happier-plugin/plugin.json` before activation. Keep that file JSON-only and side-effect free.

## UI isolation

Packaged hosted web renders inside a host-constructed frame adapter where the host reports one, and is unavailable with a typed reason where it does not. React Native UI runs as trusted client code. Neither boundary changes the package-level trust decision, and the hosted-web isolation boundary does not sandbox the plugin's daemon entrypoint.
