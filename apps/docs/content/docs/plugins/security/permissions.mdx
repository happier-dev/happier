---
title: Host access
description: Declare privileged plugin operations through strict Manifest V2 host-access requests.
---

Manifest V2 represents runtime authority under `manifest.hostAccess.required[]` and `manifest.hostAccess.optional[]`. The retired `permissions` and `declares.capabilities` owners are rejected by the current schema.

Each request contains:

- `id`: stable manifest-local identity;
- `capability`: one supported host operation family;
- `reason`: user-readable justification;
- `scope`: the strict, capability-specific boundary.

Optional requests are not active authority until the host trusts a matching grant. Missing or malformed grants fail closed.

## Example

```json
{
  "hostAccess": {
    "required": [
      {
        "id": "git-process",
        "capability": "process",
        "reason": "Runs the declared Git executable.",
        "scope": {
          "executables": [{ "kind": "systemTool", "id": "git-cli" }],
          "envKeys": ["GIT_CONFIG_GLOBAL"]
        }
      }
    ],
    "optional": [
      {
        "id": "service-api",
        "capability": "network",
        "reason": "Connects to the configured service.",
        "scope": {
          "targets": [{ "kind": "fixedOrigin", "origin": "https://api.example.com" }],
          "methods": ["GET"]
        }
      }
    ]
  }
}
```

The `git-cli` reference must resolve to a declared `contributes.systemTools[]` entry. Other capabilities similarly use typed references and scopes; raw wildcard strings and unscoped executable paths are not the current contract.

## Authority versus declarations

Actions, tools, commands, hooks, notifications, Agents, UI, and other contribution families are derived from `contributes`. Declaring or registering one does not create privileged host authority. Contribution-local capabilities describe support only.

## Safety rules

- Request only authority that has a host checkpoint.
- Keep network origins, filesystem locations, executable references, account services, session targets, and other scopes minimal.
- Treat optional access as unavailable until granted.
- Do not infer authority from contribution presence, support flags, settings, or Provider compatibility.
- Use host-mediated services; do not bypass them with ambient process, filesystem, environment, or network access.
