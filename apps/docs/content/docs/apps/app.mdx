The Happier app is the interactive client for people using Happier on desktop, web, and mobile.

## Relay selection

The app can use Happier Cloud, or you can add one or more custom self-hosted Relays.

### Saved Relays + switching

- You can save multiple Relay profiles and switch between them.
- Credentials are stored **per Relay**, so a hosted account and a self-hosted account won’t overwrite each other.
- On different Relays, accounts are independent even if you use the same login provider.
- On web, you can switch the Relay **for this tab** or **make it the device default**.
- Web tabs that use the same browser profile and origin share the same browser storage substrate. Happier separates local records by Relay and account inside that storage, but separate browser profiles are the isolation boundary when you need fully separate local storage.

### Configure-server links (1-click)

Some installers (for example `hstack setup-from-source` and Proxmox) print one-click links/QRs that open the app/web UI with the correct Relay URL prefilled.

## Desktop control panel

On desktop, the app is intended to be the main control panel for your Happier setup:

- start from the in-app **Setup wizard** (desktop can execute tasks; web shows guided handoff commands)
- choose your Relay before signing in
- sign in on that Relay
- set up **this computer**
- add a **remote machine over SSH**
- save **remote hosts** (SSH profiles) and reuse them across setup flows
- repair Relay drift when the background service is pointed at a different Relay
- manage the local self-hosted Relay runtime
- enable private access for a local/self-hosted Relay

This keeps Relay choice, account context, background-service state, and machine setup visible in one place instead of spreading the flow across separate CLI steps.

User guides:

- [Setup wizard](/apps/setup-wizard)
- [Remote hosts (SSH)](/apps/remote-hosts)

Happier supports push notifications for:

## Haptic feedback

<Callout type="info">
  Reorder haptics and the device preference described here are development-build
  changes and have not yet been released.
</Callout>

On iOS and Android, dragging an item gives a light pickup pulse and a soft tick
when its available insertion position changes. A changed move gives a light
confirmation after it is applied. Staying in the same position, cancelling, and
ordinary scrolling stay quiet. Web and desktop do not vibrate.

Turn **Haptic feedback** off under **Settings → Appearance → Motion & effects** to silence touch
feedback for actions and reordering on this device. The preference starts on,
is saved per device, and is independent of visual reduced-motion preferences.
Devices and system settings can suppress physical feedback; the visible
indicators and controls remain available.

## Session read and unread state

The app shows unread state for sessions with committed transcript activity after your last viewed position. Direct sessions can also become unread when Happier observes newer provider-side progress.

You can manually change read state from:

- the session row **...** menu
- the row long-press/context menu on mobile
- the session header action menu
- the Session info quick actions

Use **Mark as unread** to keep a session in your attention list after you have opened it. Use **Mark as read** to clear unread attention for a session.

To keep a session near the top after you have read it, use **Keep in Needs attention** instead: it holds the session in the session list's attention area, whatever its read state, until you remove it.

If you mark the session unread while you are already inside it, Happier keeps it unread for that current focused view instead of immediately marking it read again. Closing and reopening the session is treated as a new viewing intent, so the session can become read again when it is visible and focused.

Full guide: [Session read and unread state](/organize/session-read-state).

## Embedded terminal

The app can show a live session terminal directly inside the session UI.

- On larger layouts, the session's terminals are tabs in the **bottom panel**, with splits, a list view and **Jump to a terminal** (development build; released builds let you place one terminal in the bottom panel, sidebar or details panel).
- On phone-sized layouts, Happier uses a more focused terminal presentation instead of trying to keep multiple desktop-style panels open at once.
- The terminal depends on a connected background service for the current machine/session.

If the background service is connected to the wrong Relay, the app surfaces that mismatch and offers a repair action instead of silently failing later in the flow.

Full guide: [Embedded terminal](/extras/embedded-terminal).

## Local memory search

The app can search a machine-local memory index built by the selected background-service-connected machine.

That lets you:

- search past transcript context from the UI
- switch between machines when you have more than one connected background service
- open matching sessions at the relevant conversation point

Memory search is opt-in and machine-scoped, so you enable and configure it per machine.

Full guide: [Local memory search](/organize/local-memory-search).

## Provider authentication in settings

Provider settings can also open machine-local CLI login flows directly inside the app.

- on larger layouts, Happier uses the shared bottom-pane terminal
- on smaller layouts, Happier uses a more focused terminal presentation
- the provider settings page also shows auth status, auth method, and refresh actions when supported

Full guide: [Provider authentication](/agents/provider-authentication).

## Engine and model picker

When starting a new session, the app's engine picker lets you choose the backend that should run the session and, when supported, the model that backend should use.

The picker supports:

- built-in providers and configured Custom ACP backends
- live model lists from providers that can report them
- static model lists for providers such as Claude
- custom model ids where the provider supports freeform model selection
- favorite model shortcuts in the new-session engine picker

Full guide: [Model and engine selection](/agents/model-and-engine-selection).

## Machines

The Machines page is **0.3 development behavior**, not a stable-release feature.

It has two doors that open the same page:

- the **Machines** icon at the bottom of the desktop and web rail opens a popover; its rows and **All machines** open the page beside the machine list, without the Settings column, and the rail's Machines icon stays selected while you are there
- **Settings → Machines** opens the same machine list and the same machine page beside the Settings column

Nothing else differs between the two doors, and links inside the page stay in the door you came through. Pages that set machines up — adding a machine, machine defaults, this computer, machine pools and machine recipes — live only in Settings. Machine links from elsewhere in the app (Boards, System status, a session's details, runs, Home) open the rail door. The command palette also has a **Machines** command.

A machine's page opens on what it is doing — its project work, runs and recent sessions — followed by **This machine**: **Sharing**, **Agents**, **Terminal**, **Connection**, **Tools**, **Doctor** and **Details** each open their own page with a back arrow, in either door. Old `/machine/<id>` links open the same machine through the rail door.

On a machine running Happier 0.3, its page opens with its resources, live while you look: **CPU** (busy percent of the whole machine, with **Per core** opening each core's load, the user and system split and load averages where the OS reports them), **Memory** (memory pressure first — calm shows what is free; when memory needs a look the pressure level and how long it has held take its place — then what memory holds and swap), **Disk** (every volume, the one that needs you first, with what Happier uses on it) and **Network** (download above, upload below, and today's totals). Choose **1 h**, **24 h** or **7 d** of history; the machine keeps seven days itself and nothing is stored on the server. **Using the most** lists the four things Happier started that use the most memory — a session, a terminal, a service — then **Happier in total** and **Everything else** on the machine; it and its count open the **Processes** tab. **More from** lists the battery, GPU, thermal state and system limits the machine reports, and nothing it cannot report. When the machine stops answering its last figures stay with **As of** and **Retry**; offline, the page shows what it last reported. **Alerts** holds the machine's rules — short on memory, disk nearly full, CPU busy for a long time — each off until you turn it on, with how long a state must hold before it counts. Alert rules are saved on the machine. When a state holds, you get one notification and one line in the Inbox under **Machines** that opens the right tab (Processes for memory and CPU, Storage for a disk); when it recovers, one quiet line says so. **Tell me when &lt;machine&gt; goes offline** is a setting of your account, off by default; on a machine someone shares with you, offline alerts go to its owner. Windows reports no memory pressure, so its Memory tile shows memory in use instead.

The **Processes** tab lists what Happier started on the machine, grouped by what started it — each session, terminal, service or run with its CPU and memory — closed by **Happier in total** and **Everything else**. Open an owner to see its processes; a phone opens it as its own page. Sort by memory or CPU, search by name, and switch to **All processes** where the machine allows it; other apps show their names only, never their command lines. **Stop session** and **Stop service** use those work owners' lifecycle controls; supported work offers **Start again**. **Kill** asks first, and every target is checked again before acting. **Left behind** lists confirmed processes whose owners ended, with **Clean up** for the exact reviewed selection. The machine's owner can stop or kill work a guest started on it after a confirmation that names whose work ends. Processes is new in this development build; the integrated authenticated journey is not yet verified. See [Processes](/accounts/processes) for the ownership evidence, platform limits, privacy and refusal behavior.

The **Storage** tab shows what Happier keeps on the machine without scanning the disk: one sentence (free space, what Happier uses and about how much of it can go), a bar per disk with Happier's share, and Happier's storage by kind (worktrees, plugin and tool caches, model packs, session folders, logs and tool traces, agent homes, temporary files, recordings, Happier's Trash and its own data), each with its size and what can go. On a wide page a ring of the same kinds sits beside the rows, and **Easy to get back** lists the biggest suggestions Happier has checked on the machine. Each kind opens its own page listing what is inside, biggest first, with why each thing can go or stays: **Safe**, **Can delete**, **Caution**, **Keep** or **Forbidden**. **Session folders** groups sessions that stopped long ago (30 days by default) above recent or running ones. **Worktrees** groups every worktree Happier made by project, each with one reason (main checkout, in use, changed files, unpushed commits, unsaved edits, open pull request, can delete, or check first with **Check now**); **Suggestions** groups what can be rebuilt, what is old and unused, and — after a whole-disk scan — what is outside Happier.

Ticking a row collects it into the machine's pile; the disks' bars show what clearing it would free as a hatched part, and a project header collects its Safe worktrees. A **Keep** item — including a Keep folder in a whole-disk scan — asks first and names what is lost; **Forbidden** items (disk roots, system locations, your home folder, Happier's install and data) have no box and are refused for everyone. **Review** checks every item again on the machine, says what goes, what it frees and what stays, and offers one choice: **Trash** (always chosen first — Happier keeps its own Trash on each disk) or **Delete now** (its button says it can't be undone). Untick anything you'd rather keep. When an item is in use by a session, the button reads **Stop the session and remove**: Happier stops that session through the session stop Action first, and removes nothing if it does not stop. Afterwards the pile shows **N items in Trash** with **Undo** and **Empty now**, and lists anything that changed since you looked and was left untouched. The **Trash** page puts items back one at a time or empties them. Moving to Trash, deleting now and emptying the Trash are Actions that ask first by default for agents; you can change that in **Settings → Actions**.

**Whole disk** is off until you scan a disk or choose a folder. A scan shows its real progress, can be cancelled or resumed, names a folder it is stuck on with **Skip this folder**, and never opens file contents or downloads cloud-only files. A scanned folder opens one level at a time as a list (sortable, with the change since the last scan), and on a desktop also as a **Map** (rectangles) or **Rings** (circles) of the same level; the choice is remembered for each machine, and a phone always shows the list. **Large files** and **Old files** list the same scan by size or by when files last changed. When a disk is nearly full, opening Storage from that alert puts the quickest safe items in the pile for you.

Large-file size and old-file age filters also offer **Custom…**: any positive size, or any whole number of days from one. On macOS, Storage separately shows capacity the system may reclaim; it is not counted as free space available now. Opening an already materialized folder reads the saved scan; scanning again is explicit.

In this development build, **Review** starts with only **Safe** items ticked. **Caution**, **Keep** and **Check first** start unticked; **Forbidden** items are listed as staying, without a checkbox. Group and range selection also collect only Safe items; you can choose Caution or Keep individually. On Linux and macOS, a folder another program running as your user holds as its working directory is **Keep** while it is in use. Windows cannot report those other programs' working directories.

The current development build can retire a folder's managed worktrees and restore their registrations with **Undo**. Removing a main checkout or a folder containing one is not yet supported; **Review** explains that limitation and leaves it untouched. Removing part of an owner-managed session folder, model pack or recording also requires choosing the whole item.

**Keeping it tidy** holds the machine's settings — a scheduled whole-disk scan (off; runs only while the machine is on power and agents are idle), the disk-nearly-full alert (the same rule as **Alerts**), how long logs and tool traces are kept (30 days), when Happier's Trash empties (after 7 days), when unused items are suggested (30 days) and **Protected folders** (folders Happier never suggests or clears on its own); each continuous choice ends with **Custom…**. The machine applies log retention and Trash emptying itself. Offline, Storage shows the last sizes and scan read-only. Someone you share the machine with sees its totals only. Storage is new in this development build.

In this development build, automatic cleanup waits while the machine's resources policy is unavailable or locked. Policy-dependent reads and cleanup refuse with `policy_unavailable`, preserving retained files and the last reported sizes. Explicit **Empty now** remains available under the usual Trash permissions; putting back an entry waits for current folder-protection facts. An empty put-back request has no policy dependency.

**Keep logs and tool traces** also determines when inactive logs count as **can go**, based on when they were last modified. The suggestion uses your chosen retention period (30 days by default). Choosing **Forever** disables age-based log suggestions as well as age-based deletion. Current or in-use logs stay **Keep**.

For a machine's **Custom…** duration, enter one number with an explicit unit: `ms`, `s`, `min`, `h` or `d`, such as `5 min` or `1.5 h`. Full unit names and aliases such as `sec`, `mins` and `m` are accepted too. A bare number such as `5` is rejected because its unit would be ambiguous. Each field keeps its stated range and precision, such as whole minutes or whole days; unit conversion does not round a value to make it fit.

The **Guard** tab says what Happier may stop on the machine by itself — only idle things it started, with a warning first and a way back for every action. Every rule is off until you turn it on, except keeping the machine awake while agents work (**On** by default; **On power** keeps it awake only while plugged in). **Memory guard** frees memory when the machine stays short: you choose the pressure level, how long it must last and the wait between steps, and a live list shows what it would do right now — close idle browsers, stop dev servers nobody is using, stop idle sessions that can resume — with the real candidates and how much each frees; each step has its own switch, and sessions that are working or waiting for you, plain terminals and anything that isn't Happier's are never touched. Machines that don't report memory pressure (Windows) say so instead. **Idle sessions** stops finished sessions after a delay you choose, with a warning beforehand and **Keep running**; the warning reaches your phone (with **Keep running** and **Stop now**), a desktop banner, and the session itself, whose composer counts down with **Keep running**; the session list shows **Stops in …** while the warning is open and **Stopped** after. A stopped session's transcript closes with one line saying why, when and what it freed, and your next message wakes it where it left off. **Idle terminals** closes terminals left idle (off by default). **Left-behind processes** cleans up what a session left running after it ended: **Off**, **Ask** or **Automatic** after a grace you choose. **Memory ceiling per session** is Linux only. **Activity** lists everything the guard did with the reason and a way back (**Resume**, **Start again**, **Reopen**, **Undo**, **Empty now**), filtered by **Stopped**, **Cleaned up** or **Needs a look** over today, 7 or 30 days. Durations and amounts end with **Custom…**. Someone you share the machine with sees the rules without changing them; an offline machine shows its last-known settings. This is development-build behavior; the idle-terminal list and automatic left-behind cleanup appear only once the machine's Happier reports them.

The first row of the machine list, **Overview**, compares every machine as a **List** (a table) or a **Grid** (one card per machine). The choice is remembered on this device and is also the searchable setting **All machines view**.

Each online machine that reports its resources shows a **Machine summary**: CPU in use, and the memory and disk it has free, as **Sparklines** (the default: the last five minutes of CPU and memory, plus a disk level), **Bars**, **Numbers** or **Rings**. A metric that needs you takes its colour; healthy figures stay plain. Hover or focus an instrument for its exact reading. Choose the style and which metrics show — CPU, Memory, Disk, Network, or none for names only — from the popover's **⋯ → Customize summary** or **Settings → Appearance → Machine summary**. The choice is saved on this device and applies to the popover, the machine list and All machines at once. Figures are live only while one of those surfaces is open. A machine running an older Happier says so instead of showing figures.

## Machine installables

Each connected machine has an **Installables** screen in **Machine details**.

Use it to manage tools that Happier can install and maintain for that specific machine, such as **Codex ACP**.

This screen lets you:

- see whether an installable is present
- check the installed version and latest known version
- install, reinstall, or update it manually
- control **Auto-install when needed**
- control **Auto-update** (`off`, `notify`, or `auto`)

Installables are managed per machine, so your laptop, desktop, and remote boxes can each have different installed tools and policies.

## Session workspace surfaces

The app includes a repository-aware workspace UI directly inside sessions.

On larger layouts, this is split across:

- a **right sidebar** for **Files** and **Git**
- a **details pane** for file previews, editors, review tabs, historical commit diffs, and stash details

On phone-sized layouts, the same workflows are shown through the **session cockpit** by default. The bottom session tab bar lets you switch between the agent chat, Files, Git, open details tabs, and Terminal when a terminal tab is available.

### What this gives you

- browse and search the current workspace
- open files into preview or edit tabs
- review uncommitted diffs without leaving the session
- leave line-specific review comments and send selected comments to the agent
- open workspace file links from transcript messages
- inspect commit history
- switch between review and editing while keeping your place

Full guide: [Git & Files](/code/git).
Review comments guide: [Review comments](/code/review-comments).

### Mobile session cockpit

The cockpit is the default phone layout for sessions.

The bottom session tab bar can include:

- the current agent tab, named after the backend such as **Claude**, **Codex**, or **OpenCode**
- **Files**
- **Git**
- **Tabs** for file previews, editors, Review, commit/stash details, and other detail surfaces
- **Terminal** when the embedded terminal is enabled and available for that session

Switching cockpit tabs is treated as changing workspace surfaces, not as drilling deeper into browser/native history. Opening a file, Review, a commit, or a transcript file link opens the **Tabs** surface as a detail, so back can return to the list you came from.

You can switch back to the legacy phone layout from **Settings → Session → Mobile session layout → Classic**.

## Projects

The app also includes a **Projects** surface for repository work that happens outside a session.

Use Projects when you want to:

- reopen a repository where you left off
- inspect files or Git before starting a session
- switch between the main checkout and Git worktrees
- keep project details tabs and drafts around between visits
- collect review comments and then launch a new session from that exact checkout

Important behavior:

- the project itself stays anchored to the repository
- selecting a worktree changes the active checkout used by Files, Git, terminals, and new sessions
- reopening a project restores the remembered project state when possible

Full guide: [Projects & worktrees](/organize/projects-and-worktrees).

### Persistent tab/workspace state

The details pane is designed for multi-step work:

- switching between details tabs keeps their local state
- editor tabs preserve in-progress edits while you inspect other files
- review/history tabs preserve scroll position when you come back
- session workspace surfaces are intended to let you continue where you left off instead of rebuilding context each time

### Focused details mode

When you need more room for a diff or file editor, the details surface can switch into a more focused layout instead of permanently compressing the main session area.

This is useful for:

- reviewing large diffs
- editing while keeping Git open
- working on a smaller laptop/browser window

## Session composer

The session composer is where you write the next prompt, add context, and choose how the next turn should be sent.

It supports:

- plain text prompts and longer multi-line instructions
- message attachments from your device
- linked project files from the current workspace
- included review-comment drafts when review comments are available
- provider, permission, model, profile, machine, path, checkout, and resume controls when those options apply

The same composer model is used in active sessions and in the new-session flow. In an active session, it sends the next turn. In the new-session flow, it drafts the first message and holds session-start controls until you create the session.

The composer adapts to the available width. On roomy layouts, common controls can stay visible as chips near the text box. On narrower layouts, chip rows can scroll horizontally or collapse less-used actions into the action menu so the text box remains usable.

### Keyboard behavior

By default, Enter inserts a new line and the send button sends the message.

If you enable **Enter to Send** in [Session settings](/sessions/session-settings), Enter sends the current message when the composer has sendable content. On web, Shift+Enter inserts a new line. On iOS and iPadOS with a physical keyboard, Shift+Enter also continues to insert a new line while Enter sends.

This lets you choose between a chat-style flow and a writing flow:

- use **Enter to Send** for short back-and-forth prompts
- leave it off when you often write paragraphs, code blocks, logs, or step-by-step instructions

Messages can be sent with text, attachments, linked files, or included review comments. If the composer is empty or the current send action is disabled, pressing Enter does not send anything.

### Composer actions

Use the composer action chips to add context before sending:

- **Attachments** add files from your device, such as screenshots, logs, PDFs, and exported artifacts
- **Link file** references files that already exist in the current workspace or selected new-session root
- **Review comments** includes saved review-comment drafts for the current checkout when they are available

Attachments and linked files solve different problems. Attachments bring external files into the session environment. Linked files point the agent at project files that are already in the workspace.

Review comments are path-scoped. If you start from Projects or choose a new-session path with saved review comments, Happier offers those comments for that exact checkout.

For the new-session-specific flow, see [Start a new session](/sessions/start-a-session).

## Linking project files into a prompt

The session composer includes file-linking helpers so you can send file context without manually typing paths.

### Link file chip

Use **Link file** in the composer to open a project-file picker for the current workspace.

This is useful when you want to say things like:

- “Explain this file”
- “Refactor the two files I linked”
- “Compare these configs”

### `@`-style file search

Where supported, you can also use `@`-style file search from the composer to quickly reference workspace files.

The goal of both surfaces is the same:

- quickly find a file
- attach it to your next message
- keep your session grounded in the real workspace instead of hand-written path references

## Message attachments

The app also supports **message attachments** for local files that are not already in the workspace.

This is a separate workflow from **Link file**:

- use **Link file** for files that already exist in the current workspace
- use **Attachments** for files from your device, such as screenshots, exported logs, or documents

Current user-facing behavior:

- images show as thumbnails in the composer
- clicking a thumbnail opens a larger preview before send
- sent image attachments render inline in the transcript
- clicking a sent transcript image opens the same preview modal
- per-file upload progress is shown while files are uploading
- if the selected new-session path already has saved review comments, the composer also offers a **Review comments** switch for that same path
- if **Enter to Send** is enabled, Enter can send an attachment-only message once the attachments are ready

Full guide: [Attachments & image previews](/apps/attachments).

- **Hosted web app**: updates land via deploys; refresh to pick up changes.

## Authentication (keyed vs keyless)

Happier supports both:

- **Device-key accounts (default)**: end-to-end encrypted by default; users must **restore** access on new devices/browsers by using the account restore flow (for example **Add your phone** on a signed-in computer, or **Login with secret key instead**).
- **Keyless accounts (enterprise, activation pending)**: the target flow uses a
  token-only credential with zero Account E2EE material and can sign in seamlessly
  across devices. The complete external-auth/UI/daemon flow remains
  activation-closed until the server's plaintext-account rollout gates pass.

The app discovers available login and signup options from your server via `GET /v1/features` and renders what the server advertises.

### Device linking, restore, and terminal QR flows

In the app, these are different flows:

- **Add your phone** shows a QR code on a signed-in desktop/web app so a phone can join the same account
- **Restore account** is the logged-out flow for joining an existing account on a new device
- **Scan QR to connect terminal** approves a CLI/background-service connection and does not sign a new phone/browser into the UI
- **Enter URL manually** is the fallback when you cannot scan

On phones and mobile-sized web browsers with camera support, Happier opens the account-restore scanner first. On larger web/desktop layouts, Happier shows a QR code that another signed-in device can scan instead.

If you self-host and your current server is `localhost`, Happier may intentionally omit the server URL from mobile QR/deep links. In that case, first configure the phone to a reachable server URL (LAN IP, Tailscale, or a public domain), then retry.

User guide: [Features → Device linking & restore](/accounts/device-linking-and-restore)
