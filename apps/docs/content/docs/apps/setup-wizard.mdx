The Setup wizard is the guided in-app flow for connecting to a Home and getting one or more machines ready.

> **Availability:** Home-aware setup and Personal Home creation are available in the 0.3 development/preview line. Stable 0.2 keeps its released Relay-oriented onboarding.

On desktop it appears as a full-screen onboarding modal. On web and mobile-sized layouts the chrome adapts to the screen size, but the flow stays the same wizard.

Layout notes:
- Phone-sized viewports render a full-screen sheet (no backdrop scrim).
- Desktop-sized viewports render a centered card inside a modal backdrop.

It helps you:

- pick the active Home (discovered through the selected sign-in service, or saved/direct)
- sign in to that Home
- set up a machine (background service)
- create a local or SSH Personal Home (optional)
- enable private access (optional, for example Tailscale)
- set up providers (optional)

Which options you see depends on what your server advertises via `GET /v1/features` (enterprise/self-host policy).
See: [Server → Setup & bootstrap policy](/self-hosting/setup-and-bootstrap-policy).

## Desktop vs web behavior

- **Desktop app (recommended control panel)**: can execute setup actions directly through the shared system-task executor.
- **Web app**: can guide you through setup and show copy/paste commands, but cannot execute local system tasks on your computer.

If you’re using the web app and the wizard shows a “Run this command” step, you can:

- run the command in a terminal on the target machine, or
- continue in the desktop app for one-click execution.

When the wizard shows Home rows, the selected Home stays selected even if it is unreachable. Retry checks that same stable Home identity; you can also choose another saved Home or exit without silently falling back.

## Main entrypoints

### Set up this computer (local machine)

Use this when the background service should run on the same computer as the desktop app.

The wizard will guide you through interactive setup:

```bash
happier setup
```

What it does (high level):

- discovers a Home through the selected sign-in service by default, or uses the currently saved Home when one is already active
- accepts `--home <saved-home>`, `--home-url https://...`, or `--home-descriptor-file <path|->` for a direct target
- asks you to approve sign-in interactively when needed
- installs and enables the background service (unless skipped)
- optionally guides provider setup

`happier setup plan` only previews the steps. `happier setup` is the executor. Public `happier setup --yes` is not unattended sign-in: with an explicit deterministic target it saves that target, reports setup as incomplete, prints the continuation command, and exits nonzero. Without an explicit target it makes no selection change and exits nonzero.

A strict descriptor may contain only an Iroh endpoint; it does not require an HTTPS URL. Manual `--home-url` is the HTTPS compatibility path.

Setup configures this computer. If the computer was already configured and later drifted or broke, use the supported repair path instead:

```bash
happier doctor repair
```

If you log in from the mobile app with **Restore with Recovery Key Instead**, the wizard continues the same onboarding flow after sign-in instead of sending you to a separate settings page.

### Create a Personal Home (optional)

To make this computer the authority for a Personal Home, use:

```bash
happier home create
```

To create the Personal Home on a trusted remote computer through SSH, use:

```bash
happier home create --ssh user@host
```

Both forms install or reuse the same managed runtime and perform the atomic Personal Home bootstrap. An Iroh-only descriptor is sufficient for reachability, so public ingress is optional. Personal Home data is plaintext at rest on its host; choose a computer you trust.

Use `happier home pair-device` to create a new short-lived device invite. Use `happier home link-account` to make the Home discoverable through the sign-in service you are signed in to.

#### What first run looks like

The wizard shows **Preparing your Personal Home** and narrates the two stages it
actually has: *Getting your local Home ready*, then *Your Home is ready. Preparing
this computer in the background* — the Home exists before this computer is finished
being set up, so an interruption after the first stage does not cost you the Home.
It ends on *Your Home is ready*.

In the unreleased 0.3 desktop app, this first-run preparation is centered over
the blurred Home content. Reduced transparency uses a solid background instead.
The sidebar and Settings remain available while Home finishes preparing.

**Use another Home** is offered throughout, not only on failure. That matters on a
second computer: if you already have a Home, you never have to let this one create
another to get past the screen. Its subtitle is explicit — *Leave this local Home
untouched and choose from your Homes.*

If this computer already hosts a local Home, the wizard stops and asks rather than
guessing: *Happier found an existing local Home on this computer. Choose how to
continue.* **Use this local Home** verifies its access and secure signup without
changing your focused Home; **Use another Home** leaves it alone.

When setup cannot continue, it names which of the four situations you are in rather
than showing one generic error: the local Home needs attention before it can start,
Home authentication needs attention, an existing local Home needs a choice, or the
Personal Home was erased. The erased case says so plainly — the data is gone,
nothing here can recover it, and the way forward is a new Personal Home or a
different Home.

### Operate a generic Relay runtime (advanced)

`happier relay host install` and its bind modes remain supported for operators, released compatibility, and custom hosting deployments. Installing that runtime alone does not create a Personal Home or enroll a device.

Advanced local bind options:

```bash
happier relay host install --lan
happier relay host install --expose
happier relay host install --host 192.168.1.25
```

`--lan`, `--expose`, and `--host <ip>` choose where the local Relay listens. They do not configure a share/public URL strategy by themselves; use **Private access** for that.

Local Relay profile aliases:

```bash
happier relay use --local
happier relay add --local
happier relay set --local --use
happier relay auth
happier relay start-daemon
```

Pass `--local-channel stable|preview|dev` when the local Relay you want belongs to a different installed release channel.

### Set up a remote machine over SSH

Use this when you want the background service and providers to run on another machine (VPS, home server, dev box), but you want to control setup from your desktop.

The wizard will either:

- run an SSH bootstrap task from the desktop app, or
- show the equivalent CLI command to run yourself.

CLI example:

```bash
happier machine setup --ssh user@host
```

If you already saved the machine as a Remote host, you can pick it from the wizard instead of retyping the SSH details.

When you enter a new SSH target inline, the wizard shows a **Save this host** toggle inside the SSH form itself. That lets you decide before submitting whether the host should be saved as a reusable Remote host.

## Agent setup (optional)

After a machine is set up, the wizard can guide agent setup. The underlying CLI surface is:

```bash
happier agents setup
```

You can also pass an agent list when you already know what you want:

```bash
happier agents setup --providers codex,claude
```

When you choose agents in the wizard, it can prefill the CLI command with the selected agents for you.

If remote-host persistence is disabled by your server/build policy, the wizard still supports one-time SSH setup. It simply won’t offer long-term saving for the host.

## Public/HTTPS access (optional, advanced)

An Iroh-reachable Personal Home can keep its HTTP listener on `localhost`; it does not need a public URL for native-device sign-in or connection. Operator-managed generic servers and browser-only deployments may still need reachable HTTPS ingress.

The wizard can guide optional access setup using Tailscale when available. After configuration, the resulting HTTPS address is a route to the same Home, not a replacement identity.

CLI equivalent (share URL strategy):

```bash
happier relay access status
happier relay access configure --provider tailscaleServe --upstream-url http://127.0.0.1:53288
```

User guide: [Relay access](/apps/relay-access).

## Troubleshooting

### “Unreachable” Home in the wizard

- Use **Retry** (or the row menu) to re-check reachability.
- If the Home is truly down, choose another saved Home or exit and retry later. Happier does not silently substitute another identity.

If you are using the **web app on HTTPS** and your Relay is `http://...`, your browser may block the probe as mixed-content.
In that case, use the desktop app or expose your Relay over HTTPS (for example via Tailscale Serve/Funnel or a reverse proxy).

The inline **Use a different Home** action always opens the same manual **Home address** step, so you do not have to remember a separate settings page.

### “Restore with Recovery Key Instead”

If you are restoring a device that already has an account, the wizard sends you to the recovery-key step when you choose **Restore with Recovery Key Instead**.
That path is separate from the QR-code login flow and is meant for account/device restoration, not terminal approval.
