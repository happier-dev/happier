---
title: Relay access
description: Configure a reachable Relay URL for other devices (Tailscale, Cloudflare, LAN, or local-only).
---

Relay access is the “share/public URL strategy” for a self-hosted or local Relay.

It answers the question:

> What Relay URL should other devices (phones, browsers, other computers) use to reach this Relay?

This is important when your Relay is only reachable locally (for example `http://127.0.0.1:53288`), because phones and other devices cannot sign in or connect until you expose a reachable URL (often HTTPS).

Note on browsers (web + mobile web):
- `http://localhost` is treated as a secure context by browsers.
- `http://<lan-ip>` / `http://<tailscale-ip>` is **not**, so WebCrypto and login flows may fail or be blocked.
For phone/laptop access, prefer an **HTTPS** Relay URL (for example Tailscale Serve, or a reverse proxy).

## Common methods

Happier supports multiple relay-access providers (availability depends on your server/build policy):

- `localOnly` — no share URL (local-only development)
- `tailscaleServe` — Tailscale Serve HTTPS URL (private, simplest for multi-device)
- `tailscaleFunnel` — Tailscale Funnel public URL (**only** when Funnel is enabled for that Serve target)
- `lan` — a LAN URL you provide (works only on the same network)
- `cloudflareNamed` — a named Cloudflare Tunnel hostname (requires a Cloudflare token + hostname)

### Provider notes

- `tailscaleServe`
  - Best default for multi-device access inside a tailnet.
  - Produces an `https://*.ts.net` URL.
- `tailscaleFunnel`
  - Only usable if Funnel is enabled; otherwise Happier will not infer a public URL.
  - Produces a public URL (internet-reachable).
- `cloudflareNamed`
  - You provide:
    - `--hostname <your.tunnel.hostname>`
    - `--token <cloudflare token>`
  - Use this when you already operate a Cloudflare Tunnel for the host.

## CLI usage

### Relay host bind flags vs Relay access

`happier relay host install --lan|--expose|--host <ip>` controls which network interface the local Relay runtime listens on:

```bash
happier relay host install --lan
happier relay host install --expose
happier relay host install --host 192.168.1.25
```

`happier relay access ...` is a separate share/public URL strategy. Installing with `--lan` can make a LAN URL possible, but it does not configure Tailscale, Cloudflare, or any other access provider.

Inspect current relay access status:

```bash
happier relay access status
```

Configure a provider (example: Tailscale Serve from a loopback upstream):

```bash
happier relay access configure --provider tailscaleServe --upstream-url http://127.0.0.1:53288
```

When a local provider returns a share URL, Happier makes that URL the active Relay address while retaining the local upstream for connections from this computer. Future sign-in links and QR codes therefore use the address your other devices can reach. Disabling that provider switches the same profile back to its local upstream, unless you changed the profile independently in the meantime. Configuring access with `--ssh` changes the remote host only; it does not switch the Relay profile on the computer running the command.

Disable relay access (remove the persisted configuration):

```bash
happier relay access disable
```

### Apply relay access on a remote host (SSH)

You can read/write the relay-access configuration on a remote machine:

```bash
happier relay access status --ssh user@host
happier relay access configure --ssh user@host --provider tailscaleServe --upstream-url http://127.0.0.1:53288
```

Host-key safety notes:

- SSH always uses `StrictHostKeyChecking=yes` (no silent host trust).
- By default, relay-access SSH uses your **system** `known_hosts`.
- If you want Happier to manage host trust prompts for relay-access SSH, pass an app-managed file:

```bash
happier relay access status --ssh user@host --known-hosts-path /tmp/happier_known_hosts --yes
```

You can also pin a host key explicitly:

```bash
happier relay access status --ssh user@host --known-hosts-path /tmp/happier_known_hosts --trusted-host-key "<single known_hosts line>"
```
