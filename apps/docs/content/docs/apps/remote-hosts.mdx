---
title: Remote hosts (SSH)
description: Save SSH host profiles and reuse them across setup flows.
---

Remote hosts let you save SSH connection details for machines you manage (VPS, home server, dev box) and reuse them across setup and repair flows.

> **Availability:** SSH Personal Home creation is available in the 0.3 development/preview line. Stable 0.2 retains its released Relay-host management commands.

Remote hosts are synced to your account so you can reuse them across devices (when allowed by your server/build policy).
That makes them the right place to keep reusable SSH targets for both the wizard and the desktop settings screen.

## What a remote host contains

At minimum:

- host (DNS name or IP)
- port (optional)
- username
- auth method:
  - SSH agent
  - key file
  - password

Optionally:

- a friendly name / notes
- saved secret material (for example an SSH private key or password) when supported by your server/build policy

Device-local overrides are kept separately and can include:

- identity file path
- SSH config file path

If secret material is enabled, Happier can reuse encrypted passwords or private keys across devices. If secret material is disabled, the host can still be saved without those secrets.

## Where to manage remote hosts

In the desktop app, open:

- **Settings → Remote hosts**

From there you can:

- add a new host
- test the SSH connection (including first-time host-key trust prompts)
- reuse a saved host in setup flows
- run safe management actions on that host (no arbitrary shell), for example:
  - install/update the Happier CLI on the host
  - install/update/start/stop/restart the daemon service
  - inspect/install/update/start/stop/restart the managed Relay runtime

When you add a host inline from the setup wizard, the **Save this host** toggle is part of the SSH form itself so you can decide before submitting whether that host should be persisted.
If the policy disables remote-host management, the wizard still supports one-time SSH use; it simply will not offer persistence.
If secret material is disabled, the form can still save the host entry, but passwords/private keys are not persisted.

## How it’s used in setup flows

When a setup step requires SSH (for example “Set up a remote machine”), the wizard can:

- let you pick an existing remote host, or
- let you enter a new host inline and optionally save it (desktop-only).

If saving is disabled by your server/build policy, the wizard still supports one-time SSH use; it simply won’t persist the profile.

If the saved host already has secret material, Happier reuses it automatically during setup; you do not need an extra “use saved password” step.

If you only need a one-off SSH bootstrap, leave **Save this host** off and the app will use the SSH inputs for that run without persisting the profile.

## CLI equivalents

Remote hosts are primarily a UI affordance, but you can always run the underlying SSH bootstraps from the CLI:

Create a Personal Home on a trusted remote host, installing or reusing the same managed runtime and running the atomic Home bootstrap:

```bash
happier home create --ssh user@host
```

This is different from machine setup: `home create --ssh` makes that host the Home authority, while `machine setup --ssh` connects a session-running machine to the selected Home.

Noninteractive creation keeps existing Happier services and the host's default managed release channel unchanged. If the command reports a conflict, inspect the host and rerun with `--replace-services`, `--switch-channel`, or both only when you intend those exact changes:

```bash
happier home create --ssh user@host --replace-services --switch-channel --yes
```

`--replace-services` may remove conflicting Happier service registrations before installing the Home service. `--switch-channel` changes the default managed channel and refreshes its installed shims. For `home create`, plain `--yes` grants neither authority.

Bootstrap a remote machine:

```bash
happier machine setup --ssh user@host
```

Machine setup works differently: in a non-interactive run, `machine setup --yes` also accepts replacing conflicting Happier background services on the remote host. Pass `--service-mode none` if you want its existing services left untouched.

Machine setup uses the current selected Home. To target another saved Home without changing the default, put the global selector before the command:

```bash
happier --server <saved-home> machine setup --ssh user@host
```

The released `--server-url` / `--webapp-url` forms remain advanced HTTPS compatibility aliases. Routine setup should use a saved Home or the strict Home target already selected by `happier setup`.

Bootstrap a remote machine using password auth:

```bash
happier machine setup --ssh-user user --ssh-host host --ssh-port 22 --ssh-auth password
```

Bootstrap a remote machine using a key file:

```bash
happier machine setup --ssh-user user --ssh-host host --ssh-port 22 --ssh-auth keyfile --identity-file /path/to/key
```

Install only the generic managed Relay runtime on a remote host (advanced/operator compatibility):

```bash
happier relay host install --ssh user@host --mode system
```

## Policy notes

Remote host saving and secret-material persistence are controlled by server/build policy and advertised via `GET /v1/features`.
The relevant gates are `remoteHosts.management` and `remoteHosts.secretMaterial`.
See: [Server → Setup & bootstrap policy](/self-hosting/setup-and-bootstrap-policy).

## Security notes

- SSH host-key trust prompts should be reviewed carefully the first time you connect.
- A prompt about a *changed* host key is different: the stored key for that host no longer matches. In the CLI, `--yes` trusts a first-use host but never a changed key — confirm it interactively after you know why it changed, or pin the exact new `known_hosts` line with `--trusted-host-key <line>`.
- When secret material is supported by your server/build policy, saved passwords and private keys
  are private Account data. On an E2EE account they are encrypted on your device before they are sent; on a plaintext
  account they are stored in a form the Happier server can read. See [Encryption](/security/encryption).
- If you don’t want a host saved long-term, keep “Save this host” disabled and use one-time SSH inputs.
- Remote hosts are separate from Homes: they describe how to reach a machine over SSH, not which stable Home identity the CLI targets.
