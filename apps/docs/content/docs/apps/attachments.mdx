---
title: Attachments & image previews
description: Attach local files to a message, preview images before and after sending, and control where uploaded attachments are stored.
---

Happier lets you attach local files directly to a message in both:

- a **new session composer** before the first message, and
- an **existing session composer** inside an active transcript.

This is different from **Link file**:

- **Attachments** send local files from your device into the session
- **Link file** references files that already exist in the current workspace

Use attachments when you want to send things like:

- screenshots
- exported logs
- design assets
- PDFs or docs from outside the repo
- generated output files that are not already in the workspace

Attachment sending stays on Happier’s shared transfer path. The end result is the same whether you are on desktop, web, or mobile:

- your files are uploaded first
- the session receives stable file paths
- the agent reads those files from disk

## Availability (0.3 development)

In unreleased 0.3 development, uploads are on by default in the app and embedded
Sessions. No Experiments switch is needed. Your Home must still advertise upload
support; unavailable or malformed capability information does not enable uploads.
Self-hosters can disable uploads with
`HAPPIER_FEATURE_ATTACHMENTS_UPLOADS__ENABLED=false`. An embed's configured surface
and granted Session permissions can further restrict access.

## How to add attachments

Happier supports several attachment flows depending on platform:

- **All platforms:** pick files with the attachment/file-picker flow
- **iOS and Android (0.3 development):** choose **Take photo** in the attachment menu when the selected agent supports image attachments. Allow camera access when prompted. The photo appears in the composer for review before sending.
- **Web:** drag and drop files into the composer
- **Web:** paste clipboard files/images into the composer when the browser exposes them as files

You can attach both images and non-image files in the same message.

## What you see before sending

Before you send the message, Happier keeps attachments as **drafts** in the composer.

### Inline references (0.3 development)

The following describes unreleased 0.3 development behavior. Adding an attachment
places a reference chip at the caret as well as an item in the attachment tray.
Images have an **Image #N** chip and a matching number on the tray thumbnail;
only images are numbered. Other files and folders show their names.

You can write around a chip, select it, or delete it as one item. Deleting the
chip keeps the attachment in the tray, so it still goes to the Agent when you
send. Removing the tray item also removes its chips. An attachment chip whose
item is gone shows a removed state and is omitted from the sent text.

On web, dropping a file, image or folder into the text inserts its chip at the
drop caret. A folder is one tray item and one chip; its directory structure is
preserved when uploaded to the Session machine using the attachment storage
location below. In an existing Session the folder can upload before Send; a
New Session keeps the existing upload timing until a Session is available.
The chip stays pending during upload, with progress in the tray. A failed folder
upload shows the Files upload-failure message; its removed chip is omitted at send.
Folders cannot be attached to a Runner launch.

For a file or folder already in the workspace, or a Session, workflow, widget or
supported plugin item, use **Mention in composer** from its menu to insert at
the caret. These references do not upload another copy. Native OS drops from
other apps require a matching native build; their device validation is still
pending. Plain text pasted into the composer does not create reference chips.

In the **new-session flow**, those draft attachments are kept while you move around the same in-app flow, such as opening picker screens and returning to the composer.

That also includes the newer in-place browser surfaces used by session start, such as folder browsing and Resume ID browsing.

That includes path-sensitive setup flows such as choosing a different machine or directory before the session is created.

They are still treated as **temporary unsent draft state**, not durable stored content. A full page reload or app restart can still clear unsent attachments.

### Non-image files

Non-image files appear as attachment chips with the filename.

### Images

Image attachments appear as inline thumbnails instead of plain filename chips.

This makes it easier to confirm:

- you picked the correct image
- the image order looks right
- you are not about to send the wrong screenshot

### Remove before send

You can remove an attachment before sending it.

### Upload progress

When you send a message with attachments, Happier uploads each file first and shows **per-file progress** in the composer:

- image tiles show an upload overlay with a percentage
- non-image chips show percentage progress inline

This is especially useful when you send multiple files together, because you can see which file is still uploading and which one already finished.

## Previewing images before sending

Click an image thumbnail in the composer to open a larger preview.

The preview modal is designed for quick confirmation before send:

- the image takes the full modal body
- the filename stays in the header
- if multiple images are attached, you can move between them from the same modal
- opening the preview keeps you inside the current session or new-session flow instead of sending you to a separate screen

A shared Media stage is under integration for unreleased 0.3 and is not yet
mounted in the current attachment views. The intended shared preview for Files,
Review and Artifacts supports pinch, double-tap and
pointer zoom, pan, and drag-to-dismiss. The gallery stays fixed while it is open,
even if new transcript content arrives. Tap the image to toggle immersive
viewing; Close or Esc returns focus to the thumbnail. On web, arrow keys move
between items, `0` fits the image and `1` shows actual size. Staged and transcript
video tiles open the same stage with playback controls.

## What happens when you send attachments

Happier keeps the attachment flow provider-agnostic.

When you send a message with attachments:

1. Happier uploads each file first
2. Happier stores the files in the configured attachment upload location
3. the sent message records stable file paths for its attachments (with the default workspace location, these are relative to the session's working directory)
4. the message tells the agent to read those paths from disk before answering

In unreleased 0.3, the Agent receives readable markers such as **[Image #1]**,
**[File: report.pdf]** or **[Folder: samples]** where you placed the chips,
plus one reference context block with the file paths. An attachment kept in the
tray without a chip is still listed there. Older messages retain their existing
attachment-block reader.

This means attachments behave like real files in the session environment, not like provider-specific “inline binary parts”.

That has a few practical benefits:

- the same message history remains understandable across providers
- the agent can read the exact file path it was given
- image attachments and non-image attachments follow the same core workflow

If you start the session from a project worktree, the attachment storage path is resolved from that selected checkout, not from some unrelated global machine directory.

## How images behave after sending

Sent user messages keep their attachments in the transcript.

### Inline transcript images

If an attachment is an image, Happier shows it inline in the message instead of only listing the filename.

In unreleased 0.3, numbered thumbnails appear above the message text, and
reference chips appear within the text. Pressing an **Image #N** chip focuses
its thumbnail. Older messages keep their references row below the text.

This makes transcripts easier to scan when you shared:

- screenshots
- mockups
- diagrams
- exported charts

### Tool-result images in 0.3 development

Expand an individual tool call to load and view its image previews. Collapsed
tool calls keep the images hidden and do not fetch preview bytes.

In unreleased 0.3 development, Claude tool results containing inline image data,
including image reads, can display images in the transcript. The Session machine
saves these files through Happier's existing media storage, under the project's
`.happier/uploads/artifacts` directory by default. The transcript contains file
references and media metadata rather than inline image bytes.

New preview loads need access to the Session machine. Preview traffic may pass
through the relay; this feature stores the image files on the Session machine.

### Shared image preview modal

Clicking an inline image in the transcript opens the same preview modal used by the composer.

That gives you a consistent image-viewing flow before and after send.

### Non-image attachments

Non-image files still appear in the message attachments row and can be opened from there.

### Very large or unavailable previews

Happier does not try to force every image into an inline preview.

If an image is too large for the in-app preview budget, or the preview cannot be loaded cleanly:

- the attachment still remains attached to the message
- Happier falls back to a placeholder/open-file path instead of pretending the preview succeeded

This protects transcript performance while preserving access to the underlying file.

## Attachment storage location

You can control where Happier stores uploaded message attachments.

Open:

- **Settings**
- **Attachments**

### Workspace directory (default)

Default behavior stores attachments inside the current workspace.

By default, Happier uses this workspace-relative directory:

```text
.happier/uploads
```

This path is relative to the selected session/project root, which keeps attachments alongside the rest of the session’s project context.

If you start the session from a Git worktree, the upload directory is resolved inside that worktree.

### OS temp

You can also store attachments in the operating system temporary directory instead of the workspace.

This is useful when:

- you do not want attachment files written into the repo/worktree
- the attachment is only temporary session input
- you want the upload flow without adding extra workspace files

## Source-control ignore behavior

When workspace storage is enabled, Happier can also help keep attachment files out of normal source-control workflows.

Attachment settings let you choose the ignore strategy for workspace uploads.

This matters when you want the convenience of workspace-backed attachments without accidentally treating them as project files you intend to commit.

## Attachments together with review comments

The new-session flow can also discover saved review comments for the currently selected machine + directory.

If both are present:

- attachments still upload first
- the review-comments follow-up includes the attachment file references too

This lets you start a session with both:

- a structured review-comments handoff, and
- the local files that support those comments

Turning the **Review comments** chip off does not affect attachment drafts.

## Limits and important things to know

### Size limit

Attachment uploads still follow the normal **maximum attachment size** setting.

If a file is over that limit, Happier skips it and tells you why.

### No separate image-count cap

Happier does not add a special “only a few images” composer rule on top of the normal attachment settings.

The main practical limit is still your configured file-size policy.

### Images are still files

Image attachments get a better UI, but they still follow the same core attachment model as other files.

That means:

- the image is uploaded as a file
- the message stores a file-path reference
- the agent reads that file from the session environment

## Attachments vs Link file

Use **Attachments** when the file starts on your device and needs to be brought into the session.

Use **Link file** when the file already exists in the workspace and you only want to reference it in your prompt.

Examples:

- **Attachment:** “Here is the screenshot I just took on my desktop”
- **Link file:** “Look at `src/auth/login.ts` and explain this bug”
