This page is the runtime environment-variable reference for `apps/server`.

Notes:

- Legacy aliases prefixed with `HAPPY_` are still accepted where listed, but `HAPPIER_` is preferred.
- Billing/subscription provider secrets are intentionally not documented on this page.

## Getting started: required vs recommended

The server has many environment variables because it supports multiple storage/auth/networking topologies. Most deployments only need a small subset.

**Required for most production deployments**

- `HANDY_MASTER_SECRET`
  Required for `apps/server` to protect server-managed secrets. Use a long random value and keep it stable across restarts.
- `DATABASE_URL` (full flavor / external DB)
  Required when `HAPPIER_DB_PROVIDER=postgres|mysql`.
- `HAPPIER_DB_PROVIDER`
  Pick your DB backend (`postgres` is the default in `.env.example`).
- File storage settings for your chosen backend:
  - `HAPPIER_FILES_BACKEND=local`: no extra required env, or
  - `HAPPIER_FILES_BACKEND=s3`: requires `S3_*` credentials + `S3_PUBLIC_URL`

**Strongly recommended (keeps server identity and ingress explicit)**

- `HAPPIER_CANONICAL_SERVER_URL`
  Stable server identity and authentication audience. Keep this value stable across proxy, tunnel, and runtime-origin changes.
- `HAPPIER_PUBLIC_SERVER_URL`
  Optional ingress URL that phones, browsers, OAuth providers, and webhooks can actually reach. Prefer `https://...`.
- `HAPPIER_WEBAPP_URL` (when self-hosting the web UI, or for OAuth return-to)
  Base URL for the web client and OAuth redirects. Optional if you use the hosted web app at `https://cloud.happier.dev`.

**Recommended when behind a reverse proxy**

- `HAPPIER_SERVER_TRUST_PROXY=1` for typical single-proxy setups (Caddy/Nginx/Traefik), so the server can safely use `X-Forwarded-*` for `request.ip` and protocol detection.

**Nice-to-have**

- API rate limits: `HAPPIER_API_RATE_LIMITS_*` (recommended baseline is included below)
- Metrics: `METRICS_*`
- Iroh transport relays: `HAPPIER_IROH_RELAY_POLICY` / `HAPPIER_IROH_RELAY_URLS` (see
  [Iroh transport relay](/self-hosting/iroh-relay))

## Canonical template

Use `/apps/server/.env.example` as the canonical template.

Typical workflow:

```bash
cp apps/server/.env.example apps/server/.env
```

Then:

- local/dev: load values from `apps/server/.env`,
- Docker/Compose/platforms: copy the same key/value set into your deployment env/secret manager.

## Networking / reverse proxy

- `HAPPIER_SERVER_TRUST_PROXY` (optional)
  Controls whether the server trusts `X-Forwarded-*` headers for client IP / protocol when running behind a reverse proxy.
  - unset: use framework defaults (do not trust forwarded headers)
  - `true`: trust all proxy hops (only safe if the server is not directly reachable)
  - `false`: never trust forwarded headers
  - `<number>`: trust the last N hops (`0` is equivalent to `false`; recommended for typical single-proxy setups: `1`)

### WebSockets (required for realtime + “machine online”)

Happier’s realtime sync (and machine presence) uses Socket.IO at:

- `GET /v1/updates` (polling + websocket upgrade)

If you run **multiple API replicas**, configure **sticky sessions** at the reverse proxy or load balancer. Polling fallback is part of the supported realtime path, so requests from one logical Socket.IO client must keep reaching the same API process while that transport is active.

If your reverse proxy (or CDN) does not correctly forward **WebSocket upgrades** for `/v1/updates`, clients may appear to connect but machines will stay offline.

Common symptoms:

- The UI/phone shows **No online machines** / “action required”
- Server diagnostics includes `machine.none_online`
- A daemon log shows “Connecting to …” but `/v1/machines` reports `active: false`

#### Nginx (example)

If you terminate TLS on Nginx, make sure it forwards websocket upgrades (either for all paths, or at least `/v1/updates`):

```nginx
location /v1/updates/ {
  # Use the server's HTTP port (usually 3005; some managed/self-host flows use 53288).
  proxy_pass http://127.0.0.1:<port>;
  proxy_http_version 1.1;

  proxy_set_header Upgrade $http_upgrade;
  proxy_set_header Connection "upgrade";

  proxy_set_header Host $host;
  proxy_set_header X-Forwarded-Proto $scheme;
  proxy_set_header X-Forwarded-Host $host;
  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
```

#### Quick check (does the websocket upgrade work?)

From any machine that can reach your public HTTPS URL:

```bash
KEY="$(openssl rand -base64 16)"
curl -i -sS \
  -H "Connection: Upgrade" \
  -H "Upgrade: websocket" \
  -H "Sec-WebSocket-Version: 13" \
  -H "Sec-WebSocket-Key: $KEY" \
  "https://api.example.com/v1/updates/?EIO=4&transport=websocket" | head -n 5
```

Expected: `HTTP/1.1 101 Switching Protocols`.

#### Idle timeout guidance

Your reverse proxy idle timeout must be greater than the server’s Socket.IO `pingInterval + pingTimeout`.

The current Happier server defaults require **more than 60 seconds**. A higher timeout such as several minutes is safer for long-lived realtime connections.

#### Temporary workaround (daemon-side)

If you can’t fix the reverse proxy immediately, you can force the daemon to connect with polling first:

```bash
HAPPIER_SOCKET_TRANSPORTS=polling,websocket happier daemon restart --takeover
```

## Server identity and public ingress

- `HAPPIER_CANONICAL_SERVER_URL`
  Stable Home identity, profile URL, and key-challenge authentication audience. The server advertises it via `GET /v1/features` under `capabilities.server.canonicalServerUrl`.
  - Do not change it when a tunnel, reverse-proxy route, or client-local runtime origin changes.
  - For an ordinary public self-hosted deployment, it can be the same HTTPS URL as `HAPPIER_PUBLIC_SERVER_URL`.
- `HAPPIER_PUBLIC_SERVER_URL`
  Optional public ingress used for Home descriptor endpoints, OAuth target validation, webhooks, public previews, QR codes, and deep links.
  - Use the URL that works from your phone (prefer `https://...`).
  - If you intentionally run LAN-only, using `http://<lan-ip>:<your-port>` is fine (for example `http://<lan-ip>:3005`), but QR/deep links will only work on the same LAN/VPN.
  - In 0.3 development, Home descriptors accept explicit HTTPS ingress or HTTP ingress whose hostname is loopback (`localhost`, `*.localhost`, IPv4 loopback, or `::1`). LAN/public HTTP is not published in a Home descriptor. Loopback HTTP supports a browser on the same computer; it has no TLS confidentiality and does not make the Home reachable from a phone or another computer.
  - Leave it unset for a loopback-only Personal Home. Canonical loopback identity does not make public features available.
  - If this is unset, or if the active server URL resolves to loopback-only (`localhost`, `127.0.0.1`, `::1`, `*.localhost`), Happier may intentionally omit the server URL from mobile-oriented QR/deep links instead of embedding a broken address.
- `HAPPIER_WEBAPP_URL` (alias: `HAPPY_WEBAPP_URL`)
  Base URL for the web client. The server advertises it via `GET /v1/features` under `capabilities.server.webappUrl`.
  - For the hosted web app: keep default `https://cloud.happier.dev`.
  - For self-hosted UI: set this to your UI origin (often the same as `HAPPIER_PUBLIC_SERVER_URL`).

User impact:

- **Add your phone**
- **Restore account**
- **CLI/mobile auth QR links**
- **configure-server links**

all work best when the embedded server URL is reachable from the target phone/device.

If users see a hint telling them to configure the phone’s server manually, that usually means the current server URL is loopback-only and cannot safely be shared cross-device.

## Tailscale Serve inference (optional)

If `HAPPIER_PUBLIC_SERVER_URL` is unset and the server is exposed via `tailscale serve`, the server can best-effort infer the `https://<machine>.<tailnet>.ts.net` URL at boot.

Inference updates public ingress only. It never establishes or changes `HAPPIER_CANONICAL_SERVER_URL`. During the 0.3 transition, an explicitly configured historical `HAPPIER_PUBLIC_SERVER_URL` is used as canonical identity only when the canonical variable is absent; inferred values are excluded from that fallback.

- `HAPPIER_TAILSCALE_INFER_PUBLIC_URL` (default `true`)
  Set to `0` to disable inference.
- `HAPPIER_TAILSCALE_BIN` (default `tailscale`)
  Override the tailscale binary path/name.
- `HAPPIER_TAILSCALE_SERVE_STATUS_TIMEOUT_MS` (default `750`)
  Timeout for `tailscale serve status` probing (bounded to `1..10000`).

## Iroh connectivity (optional)

A Home server composes an Iroh endpoint (managed Personal Home composition) and can forward
through Iroh transport relays when no direct path works. Two variables select the relays; the
machine daemon reads the same variables for its own endpoint.

- `HAPPIER_IROH_RELAY_POLICY` (default `automatic`)
  Values: `automatic` | `disabled`. `automatic` uses the relay URLs below, prefers direct paths,
  and permits relayed forwarding as a fallback; `disabled` is direct-only and contacts no relay.
  `disabled` cannot be combined with `HAPPIER_IROH_RELAY_URLS`. Any other value, or an invalid
  URL list, fails the server's Iroh endpoint composition closed; the ordinary HTTPS Home keeps
  running.
- `HAPPIER_IROH_RELAY_URLS`
  Comma-separated, unique, absolute HTTP(S) relay URLs without credentials, query material, or
  fragments. There is no ambient or default relay set: `automatic` with no relay URLs stays
  direct-only. The Home advertises exactly these URLs in its connection descriptor, so clients,
  machines, and relay-only browser clients can find the Home through your relay.

The server's Iroh endpoint additionally requires a stable `HAPPIER_CANONICAL_SERVER_URL`. Run the
relay process itself with the managed profile in [Iroh transport relay](/self-hosting/iroh-relay).

## API rate limits

Rate limiting is implemented via `@fastify/rate-limit`. Each `*_WINDOW` value accepts human-readable durations like `30 seconds`, `1 minute`, `5 minutes`.

For hot endpoints, the server resolves per-route limits from a centralized catalog. Env var names follow a consistent pattern:

- `HAPPIER_<ID>_RATE_LIMIT_MAX`
- `HAPPIER_<ID>_RATE_LIMIT_WINDOW`

Where `<ID>` is the uppercase snake-case id (for example `account.profile` → `ACCOUNT_PROFILE`, `session.messages.byLocalId` → `SESSION_MESSAGES_BY_LOCAL_ID`).

Global controls:

- `HAPPIER_API_RATE_LIMITS_ENABLED` (default `true`)
  Set to `0`/`false` to disable all API rate limits.
- `HAPPIER_API_RATE_LIMITS_GLOBAL_MAX` (default `0`)
  Optional global limit applied to all routes. Set to `0` to disable.
- `HAPPIER_API_RATE_LIMITS_GLOBAL_WINDOW` (default `1 minute`)
- `HAPPIER_API_RATE_LIMITS_GLOBAL_KEY_STRATEGY` (default `ip-only`)
  Controls how the **global** rate limit is keyed:
  - `ip-only`: key by `request.ip` (recommended storm shield)
  - `user-or-ip`: key by verified user id when a valid Bearer token is present, otherwise fall back to IP
- `HAPPIER_API_RATE_LIMITS_ROUTE_KEY_STRATEGY` (default `user-or-ip`)
  Controls how authenticated hot endpoints are keyed (public endpoints remain IP-keyed):
  - `user-or-ip`: key by verified user id when a valid Bearer token is present, otherwise fall back to IP
  - `ip-only`: key by `request.ip` (coherent but can throttle shared IPs/NAT)

IP notes:

- All IP-based keying uses Fastify’s `request.ip`.
- Behind a reverse proxy, configure `HAPPIER_SERVER_TRUST_PROXY` so `request.ip` reflects the real client address.

Recommended baseline:

- Enable a global “storm shield” in production by setting:
  - `HAPPIER_API_RATE_LIMITS_GLOBAL_MAX=3000`
  - `HAPPIER_API_RATE_LIMITS_GLOBAL_WINDOW=1 minute`
  - `HAPPIER_API_RATE_LIMITS_GLOBAL_KEY_STRATEGY=ip-only`
- Keep route keying as:
  - `HAPPIER_API_RATE_LIMITS_ROUTE_KEY_STRATEGY=user-or-ip`

If you have many users behind a shared NAT/VPN egress IP, increase `HAPPIER_API_RATE_LIMITS_GLOBAL_MAX` to avoid throttling legitimate traffic.

### Built-in key-challenge login route

Happier’s default “device-key” signup/login flow uses `POST /v1/auth`.

Server operators can disable this built-in login route (for example when all access should go through a provider like GitHub/OIDC).

- `HAPPIER_FEATURE_AUTH_LOGIN__KEY_CHALLENGE_ENABLED` (default `1`)

- `HAPPIER_AUTH_REQUIRE_KEY_CHALLENGE_V2`
  When set to `1`, the ordinary built-in `/v1/auth` route rejects the legacy
  raw-challenge request and requires the server-issued, single-use v2
  challenge. When unset, ordinary Home login retains v1 compatibility. The
  dedicated Account Service key-login routes are always v2-only regardless of
  this setting. Set it to `1` only after every ordinary Home client for that
  server supports v2.

Note: if you disable the key-challenge route, ensure you have at least one viable provider configured (otherwise the server will fail fast at boot to prevent lockouts).

### Keyless OAuth login (optional)

Happier's target plaintext-account contract can use OAuth providers (GitHub/OIDC) as
**keyless login methods**. Keyless means a token-only credential with no recovery
secret, Account machine key, Account content key, or fabricated substitute.

Keyless OAuth is gated by feature env vars:

- `HAPPIER_FEATURE_E2EE__KEYLESS_ACCOUNTS_ENABLED` (default `0`)
- `HAPPIER_FEATURE_AUTH_OAUTH__KEYLESS_ENABLED` (default `0`)
- `HAPPIER_FEATURE_AUTH_OAUTH__KEYLESS_PROVIDERS` (CSV allowlist of provider ids, e.g. `github,okta`)
- `HAPPIER_FEATURE_AUTH_OAUTH__KEYLESS_AUTO_PROVISION` (default `0`)

Notes:

- `HAPPIER_FEATURE_AUTH_OAUTH__KEYLESS_AUTO_PROVISION=1` controls whether new keyless accounts can be created on first login.
- Keyless auto-provisioning requires keyless accounts and a storage policy that allows
  plaintext (see [Server Auth](/self-hosting/auth) for the current prerequisites).
- The complete token-only external-auth/UI/daemon flow is still activation-closed.
  Keep auto-provisioning disabled in production until the Server Auth guide removes
  that rollout warning; env-schema presence is not activation evidence.

  Values: `none` | `server_sealed`

no multi-key read or automatic re-seal rotation path, so do not replace
`HANDY_MASTER_SECRET` in place. A restore with a different secret, or a direct secret
change, can leave server-sealed values and other master-secret-derived auth/token
material unavailable. See [Server → Encryption & plaintext storage](/self-hosting/encryption).
