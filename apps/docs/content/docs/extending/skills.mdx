title: Skills

Keep a skill in your Happier library to use it across connected machines. A skill combines `SKILL.md` instructions with optional scripts, templates and reference files. **Where it's on** sets the defaults; each Session can choose its own set.

## Availability

This guide describes **unreleased 0.3 development behavior**. Skills uses the client Prompt library capability. Replacement surfaces and Session composer integration are still being validated. These instructions do not describe the stable 0.2 Export screen.

## Before you begin

Sign in to the same Happier Account on your clients and session machines. A reachable machine is needed to read a skill found there or to run a Session. Browse public catalogs from your client where supported; [registry sources](/extending/registries) explains when browsing needs a connected machine.

Skills are Account library items. Their storage follows your [Account encryption mode](/security/encryption), rather than becoming a public registry copy. Review unfamiliar instructions and scripts before adding them. Adding a bundle does not run its scripts; an Agent may run them later under the Session's permissions.

## Built-in Happier skills

In 0.3 development, Happier supplies read-only guides for using its Actions:

- **Happier** explains how to discover and use Actions.
- **Deploy** walks through preparing a deployment, deploying, reading receipts,
  checking health and logs, and diagnosing failures without exposing secrets.
- **Workflows** covers reusable and one-off Workflows, triggers, schedules,
  conditions, steps, placement, approvals, and recovering failed runs.

Built-in guides are on Everywhere unless you choose otherwise. Deploy and
Workflows are available only while their corresponding feature is enabled for
your Home and Account. Turning a feature off excludes its guide from Sessions,
including explicit Session includes. Turning it back on preserves your saved
Where-it's-on choices, including Off. Newly supplied guides also follow these
defaults in existing Accounts; reading the library does not save new rules.

## Add a skill to your library

Open **Settings → Skills**, then use **+**. The add dialog offers **Browse**, **From a link**, **Upload** and **Write**.

1. In **Browse**, choose a registry and open a skill's details. Happier picks appear first when that catalog supplies entries. **From a link** previews the skills in a repository, a skills.sh pack (`https://skills.sh/p/<pack-id>`) or an HTTPS `.well-known/skills/index.json` index; select the ones you want. You can paste `npx skills add <url>` as text into the same field. Happier reads the link without running that command. **Upload** accepts a skill folder or ZIP on the web, or a ZIP through the native document picker. **Write** opens a draft in the skill editor.
2. Review the instructions, files, source revision and whether the skill has scripts. Browse and link additions keep the reviewed revision, including supporting files and executable modes, even if the source branch advances before you press Add. Updates can offer the newer revision later. When a skill refers to another skill folder from the same repository or upload, for example `../prisma-orm-setup/SKILL.md`, the preview says "Also adds" that skill and includes it; untick it to leave it out. A skill you already added is not added twice. Other files outside the skill's own folder are not imported, and the preview says so. A folder or ZIP holding several skills lists each one to tick.
3. Choose **Where it's on**, or keep **Everywhere**. Add the skill to the library, or save your written draft.

The skill detail lets you edit instructions and supporting files, move the item to a library folder, duplicate it, or export an Agent Skills ZIP. A conflicting save keeps your draft for review. Removing a skill asks for confirmation.

Pack and well-known index links use the same checklist, including skills already in your library. Pack links need a reachable machine to fetch their files; other index links follow the [registry source fetch rules](/extending/registries). Each skill is pinned to the content reviewed in the preview. When an index publishes a digest, Happier verifies the downloaded artifact and shows **Verified by digest** with its source host. An index without one shows **No digest published**; Happier still records a content digest to pin the reviewed copy. These sources have no Git commit. Unreadable or unverifiable items are left out of the preview while valid items remain available. Happier fetches and verifies the selected content again when you add it: if a selected item changed since preview or fails verification, Add fails before saving any selected skills. Your preview stays open. Review a fresh preview or deselect the affected item before retrying.

If Happier saved the item but could not save its defaults, it reports that partial result. Use **Try again** to repair where it's on; the saved skill stays in the library and stays Off until a rule or Session selection enables it.

## Where it's on

Expand the sentence on a skill's detail to set Everywhere, Agent exceptions, machine rules or Account Project rules. A Project rule follows that Project across its machines. New additions by you default to Everywhere; existing library skills without rules stay Off until you choose.

Agent exceptions hold across places. For example, **Except Gemini** still applies inside a Project with a general On rule. A rule specifically for Gemini can override that exception. Within the same Agent scope, the more specific place wins.

A Session selection wins over these defaults. You can add a skill to one Session even if its rules are Off or name another machine or Agent. The selected Agent still needs a supported delivery path, readable content and a reachable machine; the Session shows a failure when those requirements cannot be met.

Happier normally delivers selected skills through a private Session folder. It does not install them into your own Agent skill folders by default. Agents with no Session-folder integration may receive an index and read a skill through Happier's `skills.read` Action. Agents without a usable Action channel cannot use that fallback. The Session's availability notice reports the selected Agent and launch path's actual skill delivery; the [Agent capability reference](/agents/capabilities) lists resume support for changes that need a restart.

In the development Auggie integration, native plugin catalogue names have a `happier:` prefix. This does not rename the item in your library. Native skill folders remain unchanged.

In 0.3 development, imported source folder names also survive delivery when they
differ from the skill's declared name or you rename the library item. Selected
sibling skills keep working through their relative references, including on
Windows copies. The declared name still identifies the skill in the library.

The built-in **happier** skill points the Agent to the installed CLI's current help. It starts Everywhere when the Account's skill-rules collection is created, follows Happier's version and has read-only content. You can turn it Off or make an editable copy. Removing its places does not seed it again.

## Found on your machines

Open **Found on your machines** in Skills to inspect skills already in your Agents' folders. Checking is read-only. **Add to library** copies a skill's instructions and files into your Account library; a plugin-owned skill offers **Make a copy**. The original stays on the machine. **Add all** excludes plugin-owned items and skills already in the library.

A skill in a native user or project folder with the same name takes precedence on that machine. Plugin-owned skills are separate discoveries and do not participate in this masking check. The page explains a collision and offers **Compare**. An unreadable native folder is reported as a failure, rather than an empty folder; Happier withholds library delivery when it cannot determine whether names would clash.

An offline machine can show dated last-known rows. Bring it online before adding a skill: the cached list does not contain its files. **Check again** retries the scan. A machine that cannot perform the scan needs an updated Happier daemon.

For use outside Happier, expand **Details** on an ordinary library skill and choose **Also install** for a machine. This explicit opt-in writes copies into that machine's native skill folders. Happier refuses to overwrite an unmanaged folder. Library edits refresh an unedited installed copy; a copy edited outside Happier is left alone. Removal confirms first and separately asks before removing an edited copy. The built-in skill has no outside-install control.

## Updates and local edits

Registry, link and well-known index additions track their source and reviewed revision. Pack and index checks compare the current content digest with the saved one and offer changed content through the same update review. Third-party skills default to manual updates. Open **Updates** or use **Check now** on a skill's source section.

- **Update available** means the source has a newer revision. Review the changes, then apply them.
- **Modified** means your library files differ from their imported content. Review **Yours** and **Theirs**, then choose **Keep mine** or **Take theirs** for each changed file. Keeping yours advances the checked upstream baseline while retaining your edits; the skill remains Modified.
- **Pinned** keeps the selected version. Automatic updates are an explicit choice and do not overwrite Modified content.

Updates affect later delivery of the skill. The update receipt does not offer Undo: the source might no longer supply the earlier revision. A failed source check keeps your library content and reports the failure.

**Not used recently** means Happier has recorded no use in more than 30 days, with enough observation to support that claim. Recorded uses include Claude's SDK skill invocations, Codex skill mentions, and successful Session reads through Happier. Other Agent or launch paths may not report use, so this is not a complete usage history.

## Existing library and Profile seeds

An upgraded library offers **Choose what's on** for your library skills that have no defaults. Those skills stay off until you choose; the built-in Happier guides follow the defaults above. Suggested selections come from recorded use; without recorded use, none are selected automatically.

Legacy enabled skill attachments migrate once: Account context becomes Everywhere rules, Project context becomes Project rules, Profile context becomes Profile seeds, and Session context becomes Session includes. Retained disabled inherited entries become Session excludes. Legacy records stay readable but no longer paste skill instructions; voice skill attachments stop contributing while the skill stays in the library.

A Profile's skill seeds add skills to Sessions started with that Profile, at the Session level. They do not create another Where-it's-on level. In the development Profile editor, use **Skills this Profile adds** to add or remove library skills, then save the Profile. A seed whose skill has left the library stays visible so you can remove it. Changing a Profile does not retroactively change an existing Session's selection.

## Choose skills for a Session

The development **This session gets** sheet groups Skills and MCP servers separately. Add, remove or reset a skill there without changing its saved defaults. Library `$` groups add skills to the Session instead of pasting their instructions; those composer groups are still being integrated. Native suggestions remain dependent on the selected Agent and machine.

Library-skill changes can reload live on supported Claude and Codex paths. Other changes, including native-skill On/Off, wait for the next settled turn and restart with resume when supported. A terminal-started Session or visible Windows console shows **Restart to apply**, with a restart control or terminal hint. A path without resume support shows **Applies to new sessions**. Follow the sheet's acknowledged status; a saved selection alone does not mean the Agent has received it.

## Ask an Agent or use the CLI

The same [Actions](/plugins/api/host-actions) back the library, rules, Found and update operations. Agent, CLI and MCP writes ask for approval by default; change that policy under **Settings → Actions**. Your own reversible taps act directly; deletion and outside-install removal confirm.

An Agent-created, installed, copied or adopted skill starts On for its creating Session only. Turning it on more widely is a separate rules Action.

```bash
happier skills list
happier skills show code-review
happier skills install https://github.com/example/skills --dry-run
happier skills found --machine <machine-id>
happier skills machine-install code-review --machine <machine-id>
```

`happier skills install` adds the same referenced skills; `--dry-run` lists them and `--path` limits what is added. For a Git link, pass the preview items' `provenance.ref` objects as an array through `--refs-json` to retain those reviewed commits in a later install. For pack or well-known index links, pass the items' `wellKnown` provenance objects instead to retain their reviewed content digests. An Agent can pass the same array as `source.refs` to `skills.install`. In 0.3 development, skills imported from a repository, a pack or well-known index, or a multi-skill upload keep their source folder names in the private Session folder, even if the declared skill name differs or you rename it later. Pack and index imports use the index item's name for that folder. This lets relative references between selected siblings resolve. Written skills, single-skill uploads and existing library items without a recorded source folder use their declared names.

When selected skills share a declared name or delivery folder, Happier delivers the most recently updated item; equal update times are settled by skill id. Folder comparisons ignore case so the choice is consistent across platforms. Other colliding items report a name conflict; Happier does not rename their folders.

Use `happier skills --help` and each subcommand's `--help` for current arguments. The generated [host Action catalog](/plugins/api/host-actions) owns the complete command and schema reference, including editing, rules, adoption, ZIP export and update choices.
