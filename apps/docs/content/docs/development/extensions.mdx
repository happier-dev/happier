## Current model

Happier plugins are manifest-first. The canonical manifest is schemaVersion 2:

```json
{
  "schemaVersion": 2,
  "id": "acme.sample",
  "version": "0.1.0",
  "displayName": "Acme Sample",
  "engines": {
    "happier": "^0.2.0"
  },
  "runtime": {
    "apiVersion": 1,
    "capabilities": ["lifecycle"]
  },
  "targets": {
    "daemon": {
      "entry": "./src/daemon.mjs"
    }
  },
  "capabilities": {
    "permissions": []
  },
  "contributes": {}
}
```

The local executable trust path is explicit: a local plugin directory, manifest path, or `.happier-plugin` directory resolves as a `path` source with `trustPolicy: "local_trusted"` and `installPolicy: "link"`. Treat that as machine-local executable trust for plugin daemon code, and only install local paths that you control.

The real local install and reload loop is:

```bash
happier plugins install /absolute/path/to/acme-sample
happier plugins reload acme.sample
```

During live local authoring, edit the installed path in place and run `happier plugins reload [pluginId]` after changes. Omit the plugin id to reload all plugin runtime contributions.

To start from the public SDK scaffold, run:

```bash
happier plugins scaffold /absolute/path/to/acme-sample --id acme.sample --name "Acme Sample"
happier plugins install /absolute/path/to/acme-sample
happier plugins reload acme.sample
```

To package a local plugin, validate and build an installable archive with the pack command:

```bash
happier plugins pack /absolute/path/to/acme-sample --out /absolute/path/to/acme-sample.happier-plugin.tgz
happier plugins install /absolute/path/to/acme-sample.happier-plugin.tgz
happier plugins reload acme.sample
```

The pack command validates through the same local plugin source resolver, writes the archive outside the plugin root, and emits a `.sha256` digest sidecar next to the archive.

The manifest-first runtime model is:

- `.happier-plugin/plugin.json` declares identity, capabilities, permissions, and projected contributions.
- `activate(api)` binds executable handlers and disposables for manifest-declared ids.
- invoked handlers and Agent runtimes receive `PluginContextV1` for host runtime capabilities.
- Agent runtimes expose `AgentRuntimeV1` through `RegisterAgentRuntimeV1`, including optional `runtimeCore`, facets, and Agent surfaces.

Older extension terminology and activation-time static provider/backend registration examples are not the recommended public authoring path.
