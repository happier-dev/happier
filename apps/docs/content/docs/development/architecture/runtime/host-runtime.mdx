The host runtime is the shared Happier layer that sits between product flows and
Agent-specific code. It is the reason every Agent behaves the same way in the
parts that belong to Happier, and differs only where the Agent's own CLI does.

This page is orientation. Each responsibility below has its own page or its own
file, and the code is the authority for detail.

## What the host owns, and where it lives

| Responsibility | Start here |
| --- | --- |
| Resolve backend engines | `agent/runtime/registry/engineRegistry.ts` — see [Agent runtime registry](/development/architecture/runtime/engine-registry) |
| Run session host loops | `agent/runtime/session/loop/runHostSessionRuntime.ts` — see [Session loop](/development/architecture/runtime/session-loop) |
| Run execution-run bridges | `agent/runtime/bridges/executionRun/ExecutionRunHostBridge.ts` — see [Execution-runs](/development/architecture/runtime/execution-runs) |
| Project transcript and session state | The durable outbox — see [Transcripts and state](/development/architecture/runtime/transcripts-state) |
| Build plugin runtime context | `plugins/runtime/resolveExecutablePluginRuntimeRegistry.ts` |

It also routes permission requests and responses, manages pending prompt
delivery, publishes runtime identity and facets, coordinates cleanup and
disposal, and emits lifecycle hook events.

## What an Agent leaf owns

Launching or connecting to the Agent's protocol client, encoding prompts and
structured input, decoding events, mapping permission requests, publishing
`AgentSessionRuntimeEvent` facts, exposing Agent-specific backend surfaces, and
disposing its own resources.

## Split-brain is the failure mode to watch for

Everything above is one list because the alternative is worse in a specific,
recurring way: a leaf that reimplements a host responsibility diverges from every
other Agent the moment the host changes, and the divergence shows up as "it works
for Claude but not Codex" rather than as an obvious bug.

A leaf must not own:

- **a duplicate host loop** — the boundary and reset semantics in
  [Session loop](/development/architecture/runtime/session-loop) are host rules,
  and a second loop will not have them;
- **direct transcript writes** — those bypass the durable outbox, so they are the
  writes that vanish when the connection drops;
- **direct session row mutation**;
- **UI status heuristics** — status is projected from typed events, not inferred
  from output;
- **execution-run public state**.

If a leaf appears to need one of these, the answer is a scoped host service, not
a local implementation.
