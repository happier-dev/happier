---
title: SDK boundaries
description: Public plugin contracts versus host implementation details.
---

The public SDK is the plugin authoring seam. Host implementation modules are
not public plugin dependencies.

## Public entrypoints

The package-owned generated API index is authoritative for public author paths
and symbols. Import each concept from its final capability domain, such as
`actions`, `agents/runtime`, `connected-accounts`, `managed-services`,
`providers`, `scm/hosting`, or `sessions/external`. Author code does not import
`experimental/*`, `internal/*`, undocumented source paths, or a compatibility
barrel.

Code-defined authoring imports `definePlugin` from the package root and
validator-neutral constructors such as `defineProtocolObject` from
`@happier-dev/plugin-sdk/protocol`. Cross-plugin contribution constructors are
owned by `@happier-dev/plugin-sdk/contributions`. Packing serializes that definition to the cold
`.happier-plugin/plugin.json` installed metadata; installed discovery does not
execute author code. Actions, hooks, events, MCP, SCM, and services remain in
their owning domain entrypoints. Agent runtime contracts belong to
`agents/runtime`. Generated UI build metadata belongs to `ui/build`; client-side
bridge contracts belong to `ui/client`.

## Invocation UI

Actions, hooks, and events receive `PluginInvocationContext`. Use
`context.services.interactions` for approvals, questions, and confirmations.
Use the presentation-only `context.ui` for notifications, status, widgets,
surface titles, and composer replacement. The SDK intentionally hides
interaction request IDs, operation IDs, idempotency/replay records,
presentation revisions, and raw host transport.

## Internal

- CLI Agent catalog implementation
- daemon activation and applied-state implementation
- invocation UI request and presentation bridge implementation
- interaction custody, request identity, replay, and revision mechanics
- server database models
- UI projection internals
- first-party plugin private modules

## Rule

Plugins should import from the public SDK entrypoint that owns the contract,
never from Happier source internals or an undocumented deep SDK path.
