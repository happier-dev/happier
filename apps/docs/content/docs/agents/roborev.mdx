---
title: roborev (development preview)
description: Run finite native panel reviews and preserve structured verdict evidence.
---

roborev runs a single native reviewer or a configured panel and returns
ordinary Happier findings with native verdict and member attribution.

## Availability

This optional plugin is available in unreleased 0.3 development source as
`happier.review.roborev`. Enable the bundled plugin on the reviewing Machine,
then explicitly install its native dependency through the plugin's setup flow.
See [plugin packaging and installation](/plugins/packaging). Its managed
dependency uses the vendor's published release archive and Happier's platform
and checksum handling. Enabling the plugin starts no daemon or review.

## Run a review

Select **roborev** for a supported change review. In unreleased 0.3 development
source, choose its Codex or Claude runner, model and account. For independently
selected accounts, add separate reviewers to the Review roster. Each receives
its own prepared runner credentials and native data directory.

Repository panel mode consumes the repository's native panel configuration and
shares one login environment. It cannot use independently selected accounts.
Claude Provider routes require the native bearer's proxy-token transport;
unsupported key or header transports fail visibly.

Native panel configurations can permit workspace edits. Select a
[background role](/agents/roles) with **Review** intent and **Hands-off** off
from the review's **Role** control in **Who**. The built-in Reviewer requires
Hands-off enforcement, which this integration cannot guarantee for native panels.

This integration cannot pass captured working-tree or session snapshots, or an
explicit selected-file list, to the native reviewer. Those subjects are refused
before the native process starts; choose another reviewer for them. Committed
comparisons and pull requests retain their captured base and head.

Each run starts its own native daemon with an isolated data directory beneath
the plugin's durable storage. The plugin submits one review, reads that selected
job's structured result, and stops the daemon when the run finishes. It does not
use the person's normal native daemon or data directory.

## Findings and Stop

Native pass, fail and unable-to-review verdicts are evidence separate from a
person's Happier decision. Substantive findings from a failed panel member remain
available. A missing or unsupported structured document is an error, never an
empty successful review.

Stop cancels the selected native job before stopping its daemon. There is no
always-on service, install-time daemon, hook installation or ambient review
import. Start a new Happier round to review again.
