**DeepSec** is a security review CLI rather than a general coding agent. Happier
runs it as local execution runs, not general coding Sessions. Session resume is
not supported.

## Requirements

- DeepSec CLI installed locally
- `deepsec` available on `PATH`, or `HAPPIER_DEEPSEC_PATH` set to its absolute path
- For development Runs, a selected compatible Provider connection, Claude Connected
  Account, or delivered `AI_GATEWAY_API_KEY`

The native investigation can edit the workspace. Create a [background role](/agents/roles)
with **Review** intent and **Hands-off** off, then select it from the review's
**Role** control in **Who**. The built-in Reviewer requires Hands-off enforcement,
which this native integration cannot provide.

## Install DeepSec

In unreleased 0.3 development source, the Machine setup install action uses
Happier's managed JavaScript package installer for `deepsec`. An existing system
installation remains preferred. You can also use the vendor's installation
instructions, then confirm Happier can see it:

```bash
deepsec --version
```

## Authentication

DeepSec has no login flow for Happier to launch. Happier reports it as signed in
when `AI_GATEWAY_API_KEY` is present in the environment the agent runs in.
Happier cannot verify the key works, only that it is set. This gateway status
does not validate a separate Provider connection. Development Provider-bound
Runs use that connection's selected key instead of requiring a gateway key.

## Provider models

DeepSec itself supports model selection and configurable model routes through
its Claude, Codex, and Pi harnesses. See its
[model configuration](https://github.com/vercel-labs/deepsec/blob/main/docs/models.md)
for native setup.

In unreleased 0.3 development source, a DeepSec review Run can use a selected
Provider model through the **Codex harness with OpenAI Responses**. The endpoint
must end in `/v1`, with no query or fragment. An API key is required; no-auth
connections and additional public headers are unsupported. Chat Completions
and Anthropic routes are refused by this integration, even though DeepSec has
other native harnesses.

The selected key is passed only to the review process, not saved into shared
native configuration. If you explicitly choose a conflicting harness, Happier
refuses the Run with `deepsec_provider_harness_mismatch`; choose Codex or leave
the harness automatic. With no Provider selected, a selected Claude Connected
Account takes precedence over an admitted gateway key. An unavailable selected
account fails visibly instead of falling back to another account.
Real Provider-key acceptance remains release validation.

Development Runs blank competing credential and endpoint environment variables
on every selected route, so repository dotenv files cannot replace the selected
credentials. Native Machine-login selection still requires its admitted host
selection to reach the adapter; the absence of a linked account does not grant
access to the Machine owner's login.

Gateway Runs use an available Claude or Codex harness and keep the selected
Gateway route for that Run. Saved DeepSec model configuration cannot replace it
with a native local login.

The selected Run model is passed to DeepSec's investigation on Provider,
Gateway, Claude subscription and admitted Machine-login routes. Without an
explicit model selection, the native harness keeps its own default.

The per-engine `thinkingLevel` option selects DeepSec's reasoning effort. Every
paid DeepSec review requires cost acknowledgement before it starts, including
small changes and repository audits. Happier does not calculate a dollar
estimate. `confirmedCostWarning` carries consent for that start, never a saved
preference; a new review or round asks again.

For direct reviews, DeepSec exits with status 1 when it produces findings.
Happier preserves those findings as completed only when the requested findings
report was written. A failed scan, failed investigation, or cancellation remains
unsuccessful.

Repository audits scan and investigate the selected workspace, then export native
JSON findings into the Run's temporary workspace for normalization. A missing or
invalid export fails visibly; only an explicit valid empty result establishes
zero findings. Standard investigation does not produce the direct-review Markdown
report.

DeepSec 2.3.12 receives selected files as a line-separated list and trims each
entry. Happier refuses filenames containing line breaks or leading or trailing
whitespace before launching it, so the review cannot silently select a different
file. Embedded spaces and Unicode filenames remain supported.
On Linux and macOS, filenames containing a literal backslash are also refused:
the native tool treats that character as a directory separator.

In unreleased 0.3 development source, captured comparisons run only when DeepSec
can read their selected files from the live checkout. A whole working-tree
comparison must belong to the same repository and start at its current HEAD.
A committed comparison must end at current HEAD and have no tracked checkout
changes; unrelated untracked files are allowed. Happier passes the captured
file selection to DeepSec. Partial working-tree comparisons, other captured
checkpoints, mismatched checkouts and dirty committed comparisons fail visibly;
choose another reviewer for those subjects. Repository audits require a
repository subject rather than a captured comparison.

DeepSec 2.3.12's native `--diff` selects filenames and then reads current root
files, so that flag alone cannot review arbitrary captured endpoint bytes.

## What Happier can drive

- **Provider model selection** is available for development review Runs under the restrictions above, not as a general DeepSec Session model picker.
- **Resume**, **handoff**, **listing** and **forking** are not supported.
- **Session modes** are not exposed to Happier.

## Troubleshooting

### Status shows signed out with a key set

Happier reads the environment of the process the agent runs in, so a key
exported only in an interactive shell is invisible to a daemon started at login.
Set it where the service runs, then use **Check now**.
