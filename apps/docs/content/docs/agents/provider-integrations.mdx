title: Provider Integrations
description: Connect third-party model routers and compatible model APIs to Happier Agents.

Happier runs **Agents** such as Claude Code, Codex, and OpenCode. A **Provider** is a model source that an Agent can use, such as OpenRouter, DeepSeek, a company gateway, Ollama, or LM Studio.

Configure model routing under **Settings → Providers**. Profiles remain optional launch presets and are not the owner of provider endpoints, API keys, or model catalogs.

For MCP servers, including detected Agent-native MCP configuration and per-session selection, see [MCP servers](/extending/mcp-servers).

## Account setup in 0.3 development

The unreleased 0.3 integration lets you manage Provider connections, Account-level
endpoint and Saved Secret bindings, and manual model entries without selecting
a machine. These changes belong to your Account; saving them does not test an
endpoint or authorize a particular machine to use it.

The Providers root stays on its connection home instead of opening the first
connection automatically. Open an existing connection for its details, or use
Add to start setup; the column's All entry returns to the home. Account choices
remain available without a selected machine. Local discovery, starting a local
service and testing still use the machine you explicitly select.

An Agent's Models settings can show compatible static and manual Provider models
from the available declarations. With no machine selected, these models remain
unverified: health is unchecked, load state is unknown, and no live model list
has been fetched. Refreshing this Account-only view rereads its catalog rather
than contacting a model API. A missing Agent or Provider declaration remains
unavailable instead of implying compatibility or choosing another model source.

Select the machine that will run the Agent before testing, fetching live models,
loading local models or confirming a runtime pairing. Account-only browsing
does not replace those checks. See [Account-only model browsing](/agents/model-and-engine-selection#account-only-browsing-in-03-development).

## Muse Agent in 0.3 development

The unreleased Muse Agent integration runs the native Muse executable on the
machine you select. Choose Muse as the Agent and use its installation action if
that machine needs the executable. For login or API-key setup, see
[Muse accounts](/accounts/connected-services#muse-accounts-in-03-development).
The selected account is also used when fetching Muse's native model list.

Muse's model picker preserves the models returned for that account, including
contributor variants and their native descriptions. Availability can differ
between login and API-key accounts. Choosing a Muse model for a native Session
is separate from using that account through a managed gateway in another Agent.

For native conversation UUIDs, source selection and fork limitations, see
[Muse native history](/sessions/resume-provider-sessions#muse-native-history-in-03-development).

## Connect a third-party model API

For the unreleased 0.3 Gateway integration and its current availability, see
[Vercel AI Gateway](/agents/vercel-ai-gateway).

If the service is a built-in Provider:

1. Open **Settings → Providers**.
2. Select the Provider and add a connection. You may add more than one connection for separate accounts or deployments.
3. Add the requested API key through Saved Secrets.
4. Test the connection on the machine that will run the Agent.
5. Start a session and choose a model from that Provider's section of the model picker.

In unreleased 0.3 development, saving a key with a selected Machine tests the
connection once. A rejected key stays saved and shows that it needs attention.
Without a Machine, or when the network cannot verify it, the connection shows
**Not verified**. You can use **Test connection** when a Machine is available.
Turning a connection on does not mean its key has been verified.

For an unlisted service, choose **Add custom provider** and select the compatibility contract the service actually implements. Enter its base URL, add an API key if required, and fetch or manually add its model ids.

The model appears only for Agents whose protocol and required capabilities are compatible. An unverified pairing may be shown as **Experimental** and require explicit confirmation; an incompatible pairing is not selectable.

For unreleased [Team credential pairings](/accounts/team-credentials#experimental-model-pairings),
**Experimental** is informational: neither the source owner nor the recipient
needs to confirm the pairing. Incompatible pairings still refuse. Cloud-provider delivery is
still being integrated and does not inherit personal-connection readiness merely
because the same model is listed.

## Credits and account usage in 0.3 development

The unreleased connection detail includes a **Usage** section when the Provider
supports account observations. Vercel AI Gateway reports remaining USD credits
and lifetime spend. OpenRouter reports spending for **This key**; account credits
require its separate management key, selected through Saved Secrets. Missing that
key leaves account credits unconfigured and does not change the inference key.

DeepSeek reports each balance in the currency returned by its
[balance API](https://api-docs.deepseek.com/api/get-user-balance/), CNY or USD.
Currencies are displayed separately without conversion. Unknown caps stay
unknown, and a reported negative balance is preserved. Account balances are
observations across the vendor account, not money reserved for one Session.

Opening a supported connection's Usage section requests a reading from the
selected machine through the existing approval policy. Overlapping visible
readers share a request. Hidden surfaces do not refresh; a completed turn
refreshes only its exact connection while a relevant surface is open. There is
no background polling. Check the displayed observation date and use Refresh
when you want a new reading. Ordinary refresh failures retain dated figures;
changing credentials or account authority clears them. These
observations are separate from the Session usage page's reported and estimated
request costs. Real tenant and visual acceptance remain release validation.

Reported per-request charges in 0.3 development are available only for OpenRouter
Chat Completions traffic through the external Team credential broker. Happier records the vendor's terminal
[`usage.cost`](https://openrouter.ai/docs/cookbook/administration/usage-accounting)
as reported USD cost. It uses the existing Team request attribution and does
not add the upstream inference charge or an estimate to that same charge.
Vercel AI Gateway requests and native Claude Code, Codex and OpenCode requests do
not supply reported per-request charges through this integration. Missing or
aborted terminal usage remains unknown.

## Additional Agents in 0.3 development

The unreleased development integration extends per-session Provider bindings to
[Gemini CLI](/agents/gemini), [Kilo](/agents/kilo),
[Droid](/agents/droid), [Copilot CLI](/agents/copilot), [Pi](/agents/pi)
and [Oh My Pi](/agents/oh-my-pi). Pi and Oh My Pi require credentialed OpenAI
Responses endpoints. Oh My Pi cannot represent an empty custom-header value;
remove that header or choose another compatible Agent. Each Agent
still requires its native API protocol: Gemini CLI needs a Gemini-compatible
endpoint, for example, while Copilot accepts OpenAI Chat Completions or
Anthropic Messages. Selecting a router does not translate between protocols.

[DeepSec review Runs](/agents/deepsec) also support a development-only binding
for credentialed OpenAI Responses through the Codex harness. They are review
Runs, not general coding sessions. The endpoint must end in `/v1` with no query
or fragment; no-auth connections and additional public headers are unsupported.

Gemini endpoints currently require an advanced integration: a Provider plugin
must declare Gemini support, or an Action caller must supply a manual Gemini
connection template. The standard **Add custom provider** form still offers
OpenAI and Anthropic presets; selecting one does not make it Gemini-compatible.

Happier gives the selected Agent process its endpoint, model and credentials
without changing shared native Agent configuration. Private configuration files
contain credential references rather than key values. Changing a binding uses
the Agent's restart path. Agent-specific native configuration limits are
described on the linked pages; authenticated CLI acceptance remains release
validation.

Native custom-model settings in another Agent do not automatically enable a
Happier binding. Qwen, Kimi, Grok and FX still require their native
configuration in the current integration, as does CodeBuddy where managed
configuration can override routing. Cursor's editor API-key support does
not apply to its CLI. Custom ACP definitions use the authentication and model
configuration of the executable they declare.

## Manual reasoning effort in 0.3 development

In unreleased 0.3 development, you can declare the reasoning-effort tiers supported
by a manually added model when its endpoint does not report them. Use the CLI:

```sh
happier providers add-model <connection-id> --models custom-model --reasoning-effort-levels low,medium,high
```

Running the command again for the same model id replaces its manual metadata;
omitting `--reasoning-effort-levels` clears a previous declaration. Action
callers can instead supply `reasoningEffortLevels` in each model entry of
`providers.models.manual.add`. Tier declaration is currently authored through
the Action or CLI. Effort controls appear only when the selected Agent can apply
the selected model's declared tiers. Anthropic API compatibility alone does not
enable Claude Code's Ultracode control. Declaring tiers does not verify the
endpoint or make an incompatible Agent pairing available.

In the same 0.3 development flow, starting a Session or Run with an explicit
effort outside that model's declared tiers is refused before the runner starts
(`provider_model_config_option_unsupported`). Choose a declared tier or clear
the option. An explicit unsupported capability is also refused. When the catalog
has no effort facts, admission passes the requested effort to the Agent.
Retained and default effort follows the Agent's normalization;
for example, Codex omits unsupported inherited effort at startup. Changing the
model alone does not make its retained effort an explicit request.

For an Anthropic-compatible endpoint, its `/v1/models` response can report effort
support directly on each model, for example:

```json
{
  "id": "custom-model",
  "capabilities": {
    "effort": {
      "supported": true,
      "low": { "supported": true },
      "high": { "supported": true }
    }
  }
}
```

Endpoint-reported and curated/static reasoning facts take precedence over a
manual declaration, including explicit unsupported or unknown controls. The declaration
fills missing facts even if the endpoint lists the model without effort
capabilities. With neither a declaration nor reported or curated support,
Happier leaves reasoning-effort controls unavailable.

## Local routers and model servers

Local endpoints are scoped to the target machine. Happier may detect a running process, but it confirms availability by probing the Provider's model API before showing it as connected.

For a local router such as Claude Code Router:

1. Install and start the router on the machine that runs the Happier daemon.
2. Open **Settings → Providers → Add custom provider**.
3. Choose the router's documented API compatibility and enter its loopback URL.
4. Add its token through Saved Secrets if it requires one.
5. Enable the connection for that specific machine and test it.

The per-machine confirmation is deliberate. `localhost` and private-network addresses can identify a different service on every machine, so Happier does not send credentials to them from another machine without an endpoint-bound machine grant.

If a supported local Provider such as Ollama or LM Studio is discovered, it appears under **On this machine**. Enabling it uses the same connection and machine-grant path as a manually configured local endpoint.

## Managed gateways in development

The unreleased 0.3 gateway integration uses the same managed Provider connection
from Providers and Connected services. A gateway combines one account or pool
per vendor; each pool remains single-vendor. Choosing another pool replaces that
vendor's slot. Clearing a pool's use removes only the slot it still owns, and
does not change the other vendor selections.

The development declaration includes **Muse account or pool** alongside ChatGPT
and Claude. Muse uses the connected account's Meta inference key through the same
Chat Completions, Responses and Anthropic Messages endpoints. Static model rows
describe SDK compatibility; they do not prove that your account can use a model.
This remains unreleased development behavior.

The **Gemini API key account or pool** slot uses a Gemini AI Studio API key
through those same three endpoints. Service-account and Vertex credentials are
unsupported by this slot; native Gemini Interactions is outside this gateway
family. The connected account supplies the raw API-key header, with no OAuth
fallback.

To start, open **Connected services** and choose **Add gateway** in **Gateways**.
This opens an unsaved draft. On a pool, choosing **Use in other agents** before
any gateway exists opens the same draft with that pool selected for its vendor.
Choose the vendor slots and placement, then select **Create** to save through the
existing approval policy. Opening or discarding the draft creates no connection.
Neither entry needs a computer to be online.

If a saved slot's account or pool becomes unavailable, its chooser retains the
selection and shows why it needs attention. Choose an available target or clear
the slot; Happier does not silently choose another credential. Saving a slot
does not prove it can be used at runtime.

Gateway configuration distinguishes the session's machine from an explicitly
chosen hub machine. Saving a hub does not prove it is online, and describes where
gateway requests run rather than where a model performs inference. Shared hub
execution and the settings controls are still undergoing integration validation.

Development gateway details read **Running** or **Idle** from the daemon that
owns the saved placement. If that observation is unavailable, the process status
is **Not checked**. Peer reachability is separately **Not checked**; an online hub
or healthy endpoint does not prove that another computer can use it. Opening the
detail does not start the gateway.

The development runtime shares a subscription gateway between admitted sessions
on the same connection and execution machine, while giving each session its own
scoped access. Closing or canceling one session does not retire another session's
access. After the last consumer and its active requests settle, the gateway
stops unless an explicit Start still retains it. A chosen hub becoming
unavailable reports a failure; it does not silently start a local gateway or
replay an inference request. This is not yet a released or live-certified flow.

Claude Code helper-model configuration offers fast, default and strongest pins.
Unset pins use the session's selected model; explicit full model ids in native
agent definitions retain Claude's own choice. These settings apply to subsequent
session materialization. Subscription-backed routing is experimental: upstream
authentication or policy failures stay visible, and Happier does not silently
switch credentials or model sources.

## Attached children in 0.3 development

The unreleased attached-child integration inherits the parent's applied Provider
connection and model when no explicit child choice is supplied. Pending changes
and Account defaults do not replace that route. An explicit native or Provider
choice wins. A different Agent must support the inherited pairing; an unavailable
or incompatible pairing asks for a choice rather than silently switching sources.

The child obtains its own authorized configuration at launch. Parent credentials
and gateway access tokens are not copied into a draft or summary. See
[child model choices](/agents/model-and-engine-selection#child-choices-in-03-development)
for detached work, Workflow choices, Voice and resume behavior.

## Environment switchers

Tools such as shell-based Claude endpoint switchers commonly print `ANTHROPIC_BASE_URL` and token exports or launch `claude` themselves. Those exports may still affect a Happier process started from the same terminal, but they are not the durable configuration path for remotely started sessions.

Use a Provider connection instead:

- the endpoint is typed and validated;
- the key stays in Saved Secrets;
- model discovery and compatibility are visible before launch;
- the exact connection is persisted with the session;
- child-process configuration is scoped to that Agent session rather than mutating the daemon environment.

Do not use wrapper commands that launch an Agent directly (for example a router's `... code` command) when you need Happier session syncing. Start the Agent through Happier and select the configured Provider model.

## Agent-native config-file integrations

Some integrations install plugins or write configuration files that an Agent reads directly. For example, an OpenCode plugin may modify files in OpenCode's configuration directory.

These are Agent-local customizations rather than Happier Provider connections. They work when:

- the Agent and integration are installed on the target machine;
- the same machine-local configuration is visible to the Agent process Happier starts;
- the integration does not bypass Happier by launching a separate Agent process.

If the integration changes where models come from and exposes a compatible model API, prefer a first-class Provider connection so Happier can validate credentials, catalog models, preserve exact selection identity, and apply machine safety rules.

## Troubleshooting

- **Provider is missing from the picker:** verify it is enabled on the target machine and that the selected Agent is compatible.
- **Needs API key:** bind a Saved Secret on the Provider connection; do not put a bearer token in the URL.
- **Local Provider is unreachable:** confirm the service is running and its server API is enabled, then test the connection again.
- **Machine confirmation required:** the endpoint is loopback/private or resolved to private space; enable the exact endpoint on that machine.
- **Model disappeared:** refresh the catalog or add the model id manually. Existing favorites and sessions retain a visible stale reference rather than silently switching models.
- **Provider was deleted:** choose another connection or recreate it. Happier never falls back silently to an Agent's native provider.
