Happier does not replace your coding agent. It runs the one you already use — on
your own machine, in your own checkout — and gives you a way to watch it, steer
it, approve its work and reply to it from anywhere.

The bundled agents include a generic family for anything else
that speaks ACP. Whichever you pick, the parts that belong to Happier work the
same way: the transcript, the pending queue, permissions and approvals, session
settings, notifications, and the tools an agent can call. What differs is what
each agent's own CLI exposes — which models it offers, whether it can resume a
session, whether Happier can list or fork its sessions.

Those differences are real and worth checking before you commit to a workflow.

## Getting an agent running

Each agent's page covers the same three things: installing its CLI,
authenticating it, and the limits that will actually affect you. The shape is
deliberately identical so you can move between them.

Three things are true for all of them:

- **You install the agent's CLI yourself.** Happier detects what is already on
  the machine; it does not bundle any agent. Some agents have a best-effort
  managed install Happier can run against the selected machine, from the
  agent's own settings page under **CLI & Connection**.
- **The unreleased 0.3 CLI can guide installation.** Run `happier agents setup`
  to choose several catalog-backed agents or skip for now. Skipping is valid,
  but a machine with no installed agent is connected rather than coding-ready.
- **Authentication belongs to the agent.** Happier reads its login state and,
  for some agents, can hold the credentials for you through
  [Connected Services](/accounts/connected-services) so you do not have to sign
  in separately on every machine.

Installing an agent and authenticating it are separate steps. After a managed
install, follow that agent's page to complete its own sign-in before starting a
session.

### Install and update jobs in 0.3 development

<Callout>
  This flow is in unreleased 0.3 development builds. It requires a matching 0.3
  daemon on the selected machine.
</Callout>

From the agent's settings page, select the online machine and confirm its install
or reinstall action. You can do this from the browser or phone: the machine's
daemon runs the install. Closing the settings page or disconnecting the client
does not cancel it, and reopening the app reconnects to the daemon's job.

The job includes the agent's CLI and its declared managed dependencies, followed
by a check that the CLI runs. Download progress is available when the download
source supplies it; some installers have no known download size. Vendor install
scripts require your confirmation. If automatic installation is unavailable,
follow the installation instructions on that agent's page.

Agent updates on the Updates page use the same job. Happier can check the latest
version only where the agent declares an npm or managed GitHub release source;
an unknown latest version does not mean the installed version is current.

From a shell on the machine, use the same development flow:

```bash
happier agents install codex --dry-run
happier agents install codex
happier agents update codex
```

`--dry-run` previews the local plan without starting an install job. Real installs
and updates need the local daemon to be running; if it is unavailable, run
`happier daemon start` and retry. Vendor install or update recipes require
`--yes`, `--allow-vendor-recipe`, or confirmation in an interactive terminal.
Use `--force` with `agents install` when you intend to reinstall an existing CLI.
Ctrl+C requests cancellation and waits for the daemon's final outcome.

Cancellation stops the current operation and removes partial download or staging
files. It can leave software installed by an earlier completed step, and it does
not undo every change a vendor script made. Jobs are kept only while the daemon
process runs. If that daemon restarts, refresh detection and check what is
installed before retrying.
If cancellation reports that process cleanup failed, stop that process manually
before restarting the daemon; a restart alone does not prove the installer stopped.

Agent settings live with each agent's plugin rather than in one hardcoded
screen, so an agent's page in the app can show two different auth surfaces: its
**Authentication** state on the selected machine, and the **Connected service**
it can consume when one is supported.

## Anything else that speaks ACP

For a CLI that is not on that list, Happier ships a generic **Custom ACP**
family. You define selectable ACP backends once, and they then appear as
ordinary agent choices everywhere in the app — the new-session picker, session
settings, the lot.

In unreleased 0.3 development builds, the shared integration is declared as
**Custom ACP Agent**. Each configured definition remains a separate choice;
saved drafts retain that exact choice rather than just the Agent family.
