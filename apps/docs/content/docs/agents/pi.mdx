Happier can run **Pi Coding Agent** through the local `pi` CLI.

## Install Pi

If you use hstack, you can install Pi with its legacy-named `providers` installer:

```bash
hstack providers install pi
pi --version
```

Or install manually:

```bash
npm install -g @mariozechner/pi-coding-agent
pi --version
```

## Start Pi with Happier

```bash
happier pi
```

## Permissions

Use the shared permission vocabulary when starting Pi:

```bash
happier pi --permission-mode read_only
happier pi --permission-mode auto
```

Read-only limits Pi to Happier's read-tool allowlist. Auto, Default, and YOLO do
not pass Pi's `--tools` option, so Pi keeps its full native catalog, including
the platform shell and installed extension/custom tools such as subagents. Auto
is not a workspace-confinement guarantee. Older spellings such as `safe-yolo`
and `workspace_write` remain accepted for compatibility. Unknown permission
values fail closed to the read-tool allowlist.

For the cross-Agent vocabulary and aliases, see [Permissions](/sessions/permissions).

## Local authentication in Happier

Pi does not currently expose a native interactive login flow through Happier Agent settings.

Instead, Happier shows the machine-local auth state for Pi in:

- **Settings → Agents → Pi**

Today that status is based on supported environment-backed credentials on the selected machine.

For the shared user guide, see [Agent authentication](/agents/provider-authentication).

## Authentication (connected services)

Pi can reuse connected services profiles when spawned by Happier:

- `openai-codex` (subscription OAuth)
- `openai` (API key)
- `claude-subscription` (setup-token only) for Claude subscription auth (materialized as `ANTHROPIC_OAUTH_TOKEN`)
- `anthropic` for Anthropic API key auth (`ANTHROPIC_API_KEY`)

If multiple compatible profiles exist, Happier will let you pick one when starting a new session.

Important limitation:

- Pi does not currently accept Claude OAuth profiles from `claude-subscription`; use a Claude setup-token profile instead.

See: [Connected services](/accounts/connected-services)

## Permission changes

In the current development runtime, Pi's tool permissions are set when its
process starts. Changing permission mode during a running session is unsupported;
the running permissions stay unchanged. Start a new Pi runtime with the desired
mode instead. Model and thinking-level updates remain available without changing
the permission mode.

## Troubleshooting

If Pi is not detected:

1. Verify `pi --version` works.
2. Restart Happier.
3. Set `HAPPIER_PI_PATH` if your binary is not in `PATH`.

[Pi's vendor installer](https://pi.dev/install.sh) can put its launcher at
`~/.pi/agent/bin/pi`, or under `PI_CODING_AGENT_DIR/bin/pi` when that directory is
configured. An already running daemon may retain a `PATH` from before installation.
Point `HAPPIER_PI_PATH` at the launcher and restart the daemon if terminal launches
work but daemon launches fail.

The current 0.3 development source adds discovery of these locations when `PATH`
has no Pi executable. An invalid `HAPPIER_PI_PATH` must be corrected or unset; it does not
fall back to another installation.

In current 0.3 development builds, an unavailable Pi CLI is reported as a startup
prerequisite failure. Install Pi or correct its configured path, then restart the
daemon before starting another session.
