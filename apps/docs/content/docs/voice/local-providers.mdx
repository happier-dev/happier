**Local voice** is Happier’s configurable speech pipeline.

It lets you mix and match:

- **speech-to-text (STT)**
- **text-to-speech (TTS)**
- **direct-to-session** or **voice-agent** conversation flow

Open **Settings → Voice → Voice conversations → Local voice** to configure it.

The pipeline and settings layout described here target 0.3 development source.
Conversation controls require the Voice feature; a dedicated Voice agent also needs
the Voice agent feature and Subagents. In 0.3 development, the Voice agent and
Machine speech preferences, along with Subagents, default on independently of
Experiments; stored choices are preserved in **Settings → Features**.
Dictation has independent settings and remains available
with the conversation service Off. Opening these pages does not start recording.

## Where "local" actually runs

Local voice is named for how you assemble it, not for a promise that audio never leaves
the machine. Each provider processes speech somewhere different, and it is worth knowing
which before you choose one.

| Provider | Where speech is processed |
| --- | --- |
| **Device STT (experimental)** / **Device TTS (experimental)** | The browser or operating system speech service. Depending on the platform and the configured service, that can be off-device. |
| **OpenAI-compatible endpoint** | Whatever endpoint you configured — your own server, or a remote one. |
| Google Gemini STT / Google Cloud TTS | Google, reached through the selected execution machine using that machine's Google credential. |
| **Local neural (beta)** | On web, the daemon, which needs the **Machine speech** feature. On native, downloadable on-device model packs. |

Happier shows the exact processing disclosure for whatever you have selected under
**Settings → Voice → Privacy & data**. Genuinely on-device speech means a native build
running local-neural model packs; everything else involves another process or another
company's service.

## What Local voice supports

### STT providers

You can choose one of these speech-to-text providers:

- **Device STT (experimental)**: browser or platform speech recognition
- **OpenAI-compatible endpoint**: your own `/v1/audio/transcriptions` endpoint
- **Google Gemini Speech-to-Text**: Google Gemini audio transcription
- **Local neural (beta)**: daemon-backed on web; native Sherpa streaming packs where supported

### TTS providers

You can choose one of these text-to-speech providers:

- **Device TTS (experimental)**: browser or platform speech synthesis
- **OpenAI-compatible endpoint**: your own `/v1/audio/speech` endpoint
- **Google Cloud Text-to-Speech**
- **Local neural (beta)**: Kokoro — daemon-backed on web, native model packs on device

You can mix providers freely. For example:

- device STT + device TTS
- device STT + Kokoro TTS
- OpenAI-compatible STT + Google Cloud TTS
- Gemini STT + Kokoro TTS

## Conversation modes

Local voice supports two conversation modes.

### Direct to session

In **Direct to session**, your speech is transcribed and sent directly into the active session.

Use this when you want:

- dictation-like behavior
- simple speech input into a session
- fewer moving parts

TTS can still stay enabled here, so Happier can read replies back to you.

In 0.3 development, automatic playback waits for the final reply of the turn
that accepted your message, including when it steers a turn already running.
Progress narration and thinking text are not spoken as the answer. A slow
session reply has no fixed sixty-second cutoff; **End** or interruption cancels
the wait.

### Agent

In **Agent** mode, your speech first goes through a dedicated voice agent.

Use this when you want the voice layer to:

- ask follow-up questions
- summarize before acting
- use structured actions
- avoid writing every utterance into the target session

This mode is useful when you want voice to feel like a colleague instead of a dictation layer.

## Voice agent runtime

In the current development pipeline, a Voice agent runs through Happier's daemon on
the selected Voice computer. Choose an Agent and its model configuration through the
same Agent/Provider selection used for sessions. A configured model provider is a
model source for that Agent, not a second Voice-owned chat-completions runtime.

Following a session's model requires an exact current model selection. In 0.3
development, a dedicated Voice agent cannot inherit a Team credential model and
reports a setup error before starting. Choose an explicit supported model for
Voice, or use **Direct to session** to speak into the Team-backed session.

Older direct-chat settings are retained inputs to the existing compatibility path;
they are not an additional backend choice in the current interface.

## Machine targeting

For machine-backed speech and Voice agent work, you can choose where it runs:

- **Automatic**: pick a stable machine for this account
- **Fixed machine**: always use the machine you selected

### What “Automatic” means

Auto does **not** mean “follow whichever machine became active most recently.”

In 0.3 development, the initial choice uses the newest registration among reachable
Machines, with the Machine ID breaking ties. Recent session activity and inventory order do
not change that choice. Once Voice selects a Machine for use, this client remembers
it for the current Account; this remembered choice is not an Account preference
shared across clients.
An offline selected machine is reported as unavailable; Happier does not silently
substitute another machine. Selecting Automatic again clears the sticky selection;
selecting a particular machine makes it fixed.

The goal is stability:

- Happier resolves a machine automatically when it starts the voice agent
- the running voice agent stays anchored there instead of roaming every time your active session changes

This avoids unnecessary stop/restart churn while you move around the app.

If you want predictable placement, choose a **fixed machine** instead.

## Voice home vs session project root

Daemon-backed local voice agent mode uses two kinds of working directories:

### Voice home

A stable non-project directory used for global/sidebar-started voice sessions.

Use this when you want the voice agent to have a neutral workspace instead of starting inside a project automatically.

### Session project root

When you start voice directly from a session, Happier can start the voice agent in that session’s project root.

Use this when you want the voice agent to behave more like a coding colleague inside the current project.

## Stay in voice home

If you enable **Stay in voice home**, the voice agent always stays in voice home.

That means:

- session-started voice does not start in the session project root
- teleporting into a session root is blocked

Use this when you want a safer, more neutral default working directory.

## Teleport to current session

For daemon-backed local voice agent sessions, the session voice surface can show a **teleport** action.

Teleport lets you move the running voice agent to the current session’s project root.

Important rules:

- teleport uses the existing daemon-backed Agent path
- it is hidden/blocked when **Allow teleport** is off
- it is hidden/blocked when **Stay in voice home** is on
- it fails closed when the runtime is not eligible

This is useful when you started globally from voice home and later want the agent to inspect the current project more deeply.

## Warm roots

The local voice agent can either keep a single working-root runtime or keep multiple roots warm:

- **Single**: keep one root active
- **Keep warm**: retain several recent roots for faster return/resume

When using **Keep warm**, you can choose the maximum number of warm roots to retain.

Use **Single** for the simplest behavior. Use **Keep warm** when you regularly bounce between a small number of projects and want faster reuse.

## Persistence and resumability

Voice agent mode separates two related choices:

### Transcript persistence

- **Ephemeral**: voice agent transcript state is temporary
- **Persistent**: keep voice agent conversation state across app reloads / restarts

### Resumability mode

When persistence is enabled, you can choose how the agent resumes:

- **Replay**: rebuild context from saved transcript/replay inputs
- **Provider resume**: use provider-native resume when supported

Provider resume is capability-driven. When it is not available for the current backend/agent combination, Happier disables it instead of pretending it will work.

You can also enable **fallback to replay** so provider-resume setups still recover when native resume is unavailable in practice.

## Agent source and model source

Local voice agent mode also separates:

### Agent source

- **Follow session**: use the session’s agent/backend context
- **Fixed agent**: choose a specific executable Agent

### Model source

For replies and messages the Voice agent sends, model selection can come from:

- the session
- the chat model
- a custom model selection

When a backend exposes a dynamic model list, Happier uses that live list in the dropdown instead of forcing manual text entry.

In 0.3 development, the advanced idle-agent setting accepts any positive whole
number of seconds, including durations longer than six hours. Speech-request
timeouts also accept values longer than sixty seconds, up to the JavaScript
timer maximum of 2,147,483,647 milliseconds. A 0.2 client reading settings outside
its former ranges (60–21,600 seconds for idle agents and 1,000–60,000 milliseconds
for speech requests) falls back to its Local voice adapter defaults.
Stopping an idle Voice agent does not delete an ordinary working session. A model
for messages it sends controls instruction generation; it does not create Git commits.

## Shared Local voice settings

### Preferred STT and TTS providers

Use the **STT provider** and **TTS provider** dropdowns to choose the speech backends for the current Local voice configuration.

### Test TTS

Use **Test TTS** to verify the currently selected TTS provider end-to-end.

This is the main output test for:

- device TTS
- OpenAI-compatible TTS
- Google Cloud TTS
- Kokoro local neural TTS

### Auto-speak replies

If enabled, Happier speaks replies automatically after a turn completes.

### Barge-in

If enabled, starting a new turn can interrupt current speech playback so you do not need to wait for the previous spoken reply to finish.

### Network timeout

Use **Network timeout** to control how long Happier waits for STT or TTS network operations before failing.

This matters most when you use:

- self-hosted OpenAI-compatible endpoints
- Google Gemini STT
- Google Cloud TTS

## Device STT and Device TTS

In 0.3 development builds, fresh Local voice settings select device speech for
input and output. If recognition is unavailable on your platform, complete the
setup shown by Happier or select another configured provider. Existing provider
selections are preserved.

Device providers are the least setup: no servers, no keys, no model downloads. They are
labelled **Device STT (experimental)** and **Device TTS (experimental)** in the pickers,
and both hand your speech to the browser or operating system service rather than
processing it inside Happier.

### Device STT (experimental)

This uses the browser's or the platform's built-in speech recognition where available.
On web that is the Web Speech API using the browser's default recognizer. The browser
or operating system decides where recognition runs, and may process audio off-device.
Happier does not automatically select or verify on-device browser recognition. Treat
device speech-to-text as "someone else handles the audio" unless you have independently
confirmed how that browser or operating system processes it.

When the selected engine supports endpoint-driven capture, Happier exposes
**hands-free** controls such as:

- **silence timeout**
- **minimum speech duration**

These settings control when a spoken turn should be considered finished.
Supported Happier speech-model capture uses the same timing owner. Engines without
that capture capability explain why the controls are unavailable.

In 0.3 development, leave the microphone unmuted through the silence timeout to
finish a hands-free turn. For an explicit turn, open the live Voice controls and
choose **Send** after speaking. **Mute** pauses microphone input without sending;
you can still send the buffered turn explicitly. **End** discards input you have
not submitted and ends the conversation. Previously submitted messages remain.

### Device TTS (experimental)

This uses the browser's or the operating system's speech synthesizer. It is the easiest
option, but audio quality, available voices, and whether synthesis happens on-device all
depend on the platform.

## OpenAI-compatible STT and TTS

Use these providers when you already run your own OpenAI-style speech endpoints.

### STT

OpenAI-compatible STT expects:

- `POST /v1/audio/transcriptions`

You can configure:

- base URL
- API key
- model

### TTS

OpenAI-compatible TTS expects:

- `POST /v1/audio/speech`

You can configure:

- base URL
- API key
- model
- voice
- output format (`mp3` or `wav`)

This path works well with self-hosted speech servers that intentionally match OpenAI’s API shape.

In 0.3 development builds, **Endpoint input limit (characters)** belongs to the
selected TTS endpoint configuration. It defaults to the
[OpenAI speech API's 4,096-character limit](https://developers.openai.com/api/reference/resources/audio/subresources/speech/methods/create).
For a custom server, enter its documented limit. Happier splits long replies
into ordered synthesis requests, including replies arriving incrementally.
Google Cloud TTS is batched separately by its
[5,000-byte UTF-8 limit](https://docs.cloud.google.com/text-to-speech/quotas), so
multibyte text is measured in bytes rather than estimated from character count.

## Google providers

### Google Gemini STT

Google Gemini STT is available as an STT provider for Local voice.

You can configure:

- API key
- model
- optional language hint

Use this when you want Google transcription quality without changing the rest of your Local voice pipeline.

### Google Cloud TTS

Google Cloud Text-to-Speech is available as a TTS provider.

You can configure:

- API key
- optional Android certificate SHA-1
- language
- voice
- output format
- speaking rate
- pitch

The Google Cloud voice picker is searchable and lets you choose from the voices supported by your current API key and selected language.

## Local neural TTS: Kokoro

Happier’s **Local neural (beta)** TTS currently uses **Kokoro**. Where it runs depends
on the platform, and the two paths do not offer the same controls.

### On web and desktop web

There is no browser Kokoro runtime. On web, local-neural speech runs on the daemon,
which means it needs **Settings → Features → Machine speech** and a reachable
machine. In 0.3 development this preference defaults on; its switch lets you turn it
off. It also needs Voice agent and its Subagents prerequisite. Without the required
features, selecting the provider fails rather than falling back.

In 0.3 development, the daemon permits Machine speech by default. An operator can
disable it by setting `HAPPIER_FEATURE_VOICE_DAEMON_INFERENCE__ENABLED=false` (or `0`)
in the daemon environment. The Account preference above is separate from this
daemon policy, and both honor explicit opt-outs.
Starting the daemon does not download speech models or start an inference process;
models are installed explicitly and loaded when used.

You can configure:

- **Execution** (Machine; device is not selectable on web)
- **Model pack** (the pack on your machine)
- **Voice**
- **Speed**

### On native

On native builds, Kokoro can run on the device from downloadable native model packs,
and that is what **Auto** picks. An explicit daemon selection remains on the daemon;
latency does not change the selected execution authority.

You can configure:

- **Kokoro model pack**
- **Download model**
- **Remove downloaded assets**
- **Check for updates**
- **Voice**
- **Speed**

Model downloads happen on demand and can be removed later to free storage.

### Voice previews

The Kokoro voice dropdown includes inline preview playback so you can audition a voice before selecting it.

## Local neural STT: Sherpa streaming STT

**Local neural (beta)** speech-to-text uses **Sherpa** streaming packs. On a native
build these download to the device, where you can configure:

- **Model pack**
- **Download model**
- **Remove downloaded assets**
- **Check for updates**
- **Language hint**

That is Local voice's genuinely on-device speech-to-text option: no external server, and
no audio leaving the device. On web the same provider runs on the daemon instead, under
the **Machine speech** feature, with an execution choice, model picker and
daemon-side download controls.

In 0.3 development, choosing Local neural for a new daemon Dictation setup selects
Parakeet v3 (0.6B, int8). It supports 25 languages including French, with a
487.2 MB archive and about 670.5 MB of model files. Models download only when you
choose to install them through the existing download controls.

Streaming Voice conversations and native-device recognition retain June 2023
English Zipformer (chunk-16/left-128, int8), about 72.7 MB including notices.
June stays selectable as the smaller Dictation option. Existing June setups,
including those without an explicit model choice, and other saved model choices
stay selected; this change does not replace or download an installed model.

## Model downloads, updates, and storage

Both Kokoro native TTS packs and Sherpa native STT packs are downloaded on demand from Happier’s model-pack manifests.

From settings, users can:

- download missing packs
- see download progress
- stop an in-progress download
- check whether a newer model-pack build is available
- remove downloaded assets to free storage

In 0.3 development builds, native downloads show transferred bytes and verified
file counts. Once all bytes have arrived, any remaining integrity checks appear
as **Verifying** with checked-byte progress. Stopping or interrupting a download keeps resumable files; retry to
continue, or use the remove action to discard the unfinished download and free
storage. Updates reuse unchanged files after verifying them and keep the
installed pack in place while downloading.

An admitted download continues when you leave its settings page. Return to the
same pack to see its progress or stop it. Before downloading, Happier checks
available space against the model files still needed. A pack published for a
different speech role is rejected. On iOS, downloaded model directories are
excluded from device backups, including after removal and reinstallation.

Native model packs are stored on the device. Web has no browser-side model cache, because local-neural speech runs on the daemon there.

## Recommended setups

### Simplest setup, no servers to run

- **STT**: Device STT (experimental)
- **TTS**: Device TTS (experimental)
- **Conversation mode**: Direct to session

Simplest, but not the most private: device speech may be processed off-device. For a
setup where the audio really does stay put, use native local-neural packs.

### Better spoken output with minimal complexity

- **STT**: Device STT
- **TTS**: Local neural TTS (Kokoro)
- **Conversation mode**: Agent

### Fully self-hosted speech stack

- **STT**: OpenAI-compatible STT
- **TTS**: OpenAI-compatible TTS
- **Conversation mode**: Agent

### Hybrid cloud/local setup

- **STT**: Google Gemini STT
- **TTS**: Kokoro or Google Cloud TTS
- **Conversation mode**: Agent

## Networking notes

### Mobile and localhost

On phones, `localhost` and `127.0.0.1` usually point to the phone itself, not your computer.

If your speech server runs on your computer, use:

- your computer’s LAN IP, or
- a tunnel

### Web and CORS

For web builds, your STT or TTS server may need CORS configured correctly.

### Exposing services outside your LAN

If you expose a speech server beyond your local network, add proper authentication and HTTPS.

## Troubleshooting

### Local voice hears me, but nothing is spoken back

Check:

- that a TTS provider is selected
- that **Auto-speak replies** is enabled if you expect automatic playback
- that **Test TTS** works

### Kokoro is unavailable

Check:

- on web, that **Machine speech** is enabled and a machine is reachable — there
  is no browser Kokoro runtime to fall back to
- on native, that the model pack downloaded successfully
- that the selected Kokoro pack is ready

### Sherpa STT is unavailable

Check:

- on native, that the Sherpa model pack has been downloaded
- on web, that **Machine speech** is enabled and a machine is reachable
- that the selected language or pack matches your use case

### Nothing is written into the target session

If you are in **Agent** mode, this can be expected. The voice agent does not need to
write every utterance into the target session — it keeps that part of the conversation
in its own run session and sends only explicit actions back. **Direct to session** has
no separate conversation at all, so anything you say there does reach the session.
