Happier includes a built-in bug report flow from app settings.

When enabled by your server, users can submit:

- a short issue description,
- optional diagnostic payloads (for example logs),
- metadata that helps support reproduce and triage issues.

## Server controls

Use these env vars on the Happier server:

- `HAPPIER_FEATURE_BUG_REPORTS__ENABLED` (default `1`)
- `HAPPIER_FEATURE_BUG_REPORTS__PROVIDER_URL` (default `https://reports.happier.dev`)
  - If set to an invalid URL, provider submission is disabled instead of falling back to a central default.
- `HAPPIER_FEATURE_BUG_REPORTS__DEFAULT_INCLUDE_DIAGNOSTICS` (default `1`)
- `HAPPIER_FEATURE_BUG_REPORTS__MAX_ARTIFACT_BYTES` (default `10485760`)
- `HAPPIER_FEATURE_BUG_REPORTS__UPLOAD_TIMEOUT_MS` (default `120000`)
- `HAPPIER_FEATURE_BUG_REPORTS__CONTEXT_WINDOW_MS` (default `1800000`; min `1000`, max `86400000`)
- `HAPPIER_FEATURE_BUG_REPORTS__ACCEPTED_ARTIFACT_KINDS` (comma-separated allowlist)
- `HAPPIER_BUG_REPORTS_SERVER_DIAGNOSTICS_ENABLED` (default `0`)
- `HAPPIER_BUG_REPORTS_SERVER_DIAGNOSTICS_ACCESS_MODE` (default `owner`, allowed: `authenticated`, `owner`)
- `HAPPIER_SERVER_OWNER_USER_IDS` (comma-separated server owner account ids for owner-gated features)
- `HAPPIER_BUG_REPORTS_SERVER_LOG_PATH` (optional explicit server log path)
- `HAPPIER_BUG_REPORTS_SERVER_LOG_MAX_BYTES` (default `262144`, max tail bytes read from server log snapshot)
- `HAPPIER_DIAGNOSTICS_BUG_REPORT_SNAPSHOT_RATE_LIMIT_MAX` (default `30`)
- `HAPPIER_DIAGNOSTICS_BUG_REPORT_SNAPSHOT_RATE_LIMIT_WINDOW` (default `1 minute`)

To hard-disable server log exfiltration, keep `HAPPIER_BUG_REPORTS_SERVER_DIAGNOSTICS_ENABLED=0` and/or remove `server` from `HAPPIER_FEATURE_BUG_REPORTS__ACCEPTED_ARTIFACT_KINDS`.

For shared servers, keep `HAPPIER_BUG_REPORTS_SERVER_DIAGNOSTICS_ACCESS_MODE=owner` (or leave it unset) and define `HAPPIER_SERVER_OWNER_USER_IDS` so only configured owners can fetch server diagnostics snapshots.

`HAPPIER_SERVER_OWNER_USER_IDS` uses Happier account ids (not usernames). Owners can copy their id from Settings → Account in the app.

## Privacy and control

- Diagnostic upload is optional at submit time.
- Server operators can disable automated provider submission for restricted environments.
- User-facing UI follows server capability flags.
- Clients remain backward-compatible with older servers that do not expose `features.bugReports` (treated as disabled).
- When provider submission is unavailable, clients can still offer a prefilled public GitHub issue fallback (without private artifacts).

## Similar issues (duplicates)

To reduce duplicate reports, Happier can search GitHub for potentially similar issues while you fill the report.

- In the app, you can select one of the suggested issues to post your report as a comment instead of opening a new issue.
- In the CLI, you can:
  - pass `--existing-issue-number <number>` to post the report as a comment on an existing issue
  - pass `--no-similar-issues` to skip duplicate searching in interactive mode

## Session reports and diagnostic controls (development)

The following flow is being developed in source and is not yet established as available in a released app. Report submission still depends on your server enabling bug reports.

Open the session header menu and choose **Report an issue with this session** to start a report about that session. You can also open the existing report composer from app settings and use **Choose a session**. Both entry points use the same **Related session** picker when choosing or changing a session. A related session is optional: leave it empty for an app issue, or remove a selected session before sending. Without a related session, the app collects app diagnostics only, including local app logs when **App and daemon logs** is selected, with no machine or server logs. Select a session to attach logs from its own daemon and Happier session; the app does not choose another online machine automatically.

Only a title and **What happened?** are required text fields. **Add more details** holds optional information such as reproduction steps and expected behavior; **Technical information** lets you review environment details.

When diagnostics are included and the server accepts the relevant attachments, **App and daemon logs** and **Happier session logs** are selected by default. **Provider transcript** is off by default. Happier session logs can contain conversation excerpts. Automatic transcript attachment currently supports Claude Code and Codex, using matching files in their configured local homes; other agents or separate homes may have no transcript available.

Choose **Technical information only** to exclude all raw logs, including the agent transcript. This keeps limited technical context, such as versions and collection status, rather than attaching whole settings, session metadata or runtime dumps. It does not add stack logs as a substitute for a missing selected log.

Use **Preview diagnostics** to inspect the attachments and their collection status. Missing files, offline machines and older CLIs remain visible as unavailable or needing an update; they do not prevent sending the report text. Happier does not substitute a different session's logs. With the same session and collection settings, submission reuses the attachment contents prepared for the preview. Preview again after changing those settings.

Report text is public in the GitHub issue or comment. Diagnostic attachments are sent privately to Happier maintainers. Collection redacts recognized secrets, but this does not remove all personal, project or conversation content. Review both your report text and attachments before sharing them.

## Crash recovery (development)

Development source captures the latest UI exception, React component stack, timestamp, app/OTA metadata, loaded browser asset URLs, desktop wrapper version when available, OS details and recent action trail before either recovery restart action. Browser asset URLs can identify production bundles; a development Metro URL does not establish an exact source revision. **Restart and open bug report** also opens the report composer after restarting. These changes are not yet established as available in a released app.

The composer fills the title, summary, current behavior and available environment fields from the saved crash. Review and edit those fields before submitting, including removing any remaining private information. Crash-prefilled drafts do not run automatic similar-issue searches. Optional logs and action-trail diagnostics still use the existing preview and consent controls; the original stack is not attached again behind your edited fields.

The saved crash survives opening, leaving and reopening the composer. A successful submission or **Discard saved crash** removes it; a newer crash replaces it. Long stacks are visibly shortened to fit the report field. **Copy error details** copies the full saved stack so you can review the omitted portion locally.

**Save diagnostics** downloads or shares a redacted local diagnostics file without restarting or submitting a report. If that export fails, the error stays visible and the action can be retried.

If saving the crash for restart fails, the recovery screen keeps the error visible and offers copying, retrying the report action, or **Restart without saving**. Browser and desktop persistence depend on the app's local storage remaining available. Native apps use durable app storage and can also read crashes saved in the earlier cache location.

## CLI reporting

You can submit reports from CLI too:

```bash
happier bug-report \
  --title "CLI crash while starting daemon" \
  --github-username "@octocat" \
  --summary "Daemon start exits immediately" \
  --current-behavior "happier daemon start exits with unknown error" \
  --expected-behavior "daemon starts successfully" \
  --repro-step "Run happier daemon start" \
  --accept-privacy-notice
```

If required fields are missing in an interactive terminal, the CLI prompts for them. In non-interactive mode, pass all required flags.

### Session selection and local export (development)

These CLI options are under development and are not yet established as available in a released CLI. Use `--session-id <id>` to select the Happier session the report concerns. Omit it for a report without a related session.

Control each log source with `--include-daemon-logs` / `--no-include-daemon-logs`, `--include-session-logs` / `--no-include-session-logs`, and `--include-provider-transcript` / `--no-include-provider-transcript`. Daemon and Happier session logs default to included; the agent transcript defaults to excluded. These selections apply when diagnostics are enabled and the server accepts those attachment kinds. The automatic transcript availability limits above also apply to the CLI.

For technical context without raw logs, turn all three sources off. This example writes a local diagnostics bundle:

```bash
happier bug-report \
  --title "Session connection issue" \
  --summary "The session stopped receiving updates" \
  --session-id "<happier-session-id>" \
  --include-diagnostics \
  --no-include-daemon-logs \
  --no-include-session-logs \
  --no-include-provider-transcript \
  --accept-privacy-notice \
  --export ./bug-report.json
```

`--export <path>` and `--dry-run --output <path>` collect and save the report locally, without uploading it or searching for similar issues. Collection may still contact the selected server for configuration or diagnostic information. The bundle includes your report text and the collected attachments; recognized secrets are redacted from collected diagnostic content, but your text and remaining log content still need review before sharing. Do not add `--attach`, `--attach-session-log` or `--attach-provider-transcript` when you want a report without raw logs or other file contents.

### Reporter GitHub username (optional)

If you want maintainers to be able to reach you, provide your GitHub username via `--github-username`. Happier appends a `Reporter GitHub: \`...\`` line to the report summary (sanitized to avoid accidental formatting/pings).

## When to use

- UI rendering issues,
- session sync mismatches,
- auth/connection problems,
- tool timeline or diff rendering regressions.
