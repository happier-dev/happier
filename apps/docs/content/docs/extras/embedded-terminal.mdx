Happier can show a live terminal for the current session directly inside the app UI.

This is useful when you want to run quick shell commands, inspect project state, follow logs, or open detected local URLs without leaving the session.

The same terminal foundation is also reused for **provider login flows** from provider settings.

## What it does

- Opens a live shell backed by your connected Happier daemon.
- Treats the terminal as part of the current session, not as a separate detached tool.
- Keeps each terminal running when you hide the panel or show it somewhere else.
- Preserves the terminal across normal navigation and page refresh for that session.

## Where the terminal appears

<Callout type="info">
  This section describes the current development build (unreleased). Released builds use a
  single terminal and a location setting (bottom panel, sidebar or details panel).
</Callout>

On web, desktop and tablets the session's terminals live in the **bottom panel**, under the
chat and the side panes. On phones they live on the session's **Terminal** page.

To give one terminal a wide view beside the chat, use **Open in Details** from its tab menu.

## How to open it

1. Open a session.
2. Use **Terminal** in the session header or the desktop [session action rail](/apps/app#desktop-session-action-rail).
3. The bottom panel opens with the session's terminals. Hiding it keeps them running.

## Tabs, splits and the list view

The bottom panel has one strip:

- **Tabs** — every terminal of the session is a tab. A tab is named after its own title (or the
  script it runs) and shows a dot when something is going on: green while it serves a local
  address or runs a script, amber when it needs you, grey once its process has exited.
- **+** opens a shell in the session's folder. The **▾** next to it opens the agent's own
  terminal, runs a package script **in a new terminal tab**, or opens a shell on another online
  machine.
- **Split** puts a second shell beside the focused one in the same tab. A split is refused when
  either side would be too narrow to read.
- **⋯** offers **Jump to a terminal**, **Show list** and **Hide the bottom pane**. **Show list**
  (remembered per session) replaces the tabs with a column that says what each terminal is doing;
  in a narrow window the panel keeps the tabs.
- Right-click a tab (long-press on touch) for **Rename**, **Split right**, **Move to its own tab**,
  **Open in Details**, **Copy selection**, **Paste**, **Clear**, **Restart** and **Close**. Closing
  a shell stops what runs in it; closing the agent's terminal or another session's terminal only
  removes the view.

### The agent's own terminal

Sessions that run in tmux, zellij or Herdr have the agent's own terminal. It is a tab beside your
shells, marked with the agent. When the agent shows a dialog in its terminal, its tab turns amber
(and so does the rail's Terminal while the panel is hidden), and the chat card offers to show it.

### Local addresses

When a terminal prints a local address, the strip shows it as a pill — for example
`localhost:5173 · Open`. **Local services** lists the same address. Package scripts from Local
services run in a new terminal tab.

### Find in terminal output

In the unreleased development build, use **Find…** from the focused terminal's tab menu,
or use your configured [Find shortcut](/apps/keyboard-shortcuts) while that terminal is focused.
Find searches the rendered output the terminal still retains, not earlier process output.
The bar shows the retained line count and marks results as limited when scrollback or
highlight capacity has been exhausted.

This is available in the web terminal and the native xterm WebView fallback. Native
Ghostty and Termux views do not offer Find. On phones, the Find bar replaces the terminal
key rail; **Done** restores the keys and terminal focus. Closing Find keeps the current
terminal selection.

### Jump to a terminal

**⌘J** (⌥J on the web) opens the command palette in its **Terminals** scope: this session's
terminals first, then terminals other sessions left running on the same machine (read-only), then
**New**. Typing filters them and offers matching package scripts.

In the development phone Terminal page, long-press a terminal chip to open this
grouped Jump directly. The **⋯** beside the chips keeps the active tab's verbs;
**Split right** is unavailable there because the phone uses a pager rather than
a measured side-by-side split layout.

## Bottom panel behavior

The bottom panel is a real panel region in the session layout, not a one-off terminal overlay.

### Resize behavior

- Drag the top edge of the bottom panel to resize it.
- If the screen still has enough height for both the main content and the bottom panel, the panel stays **docked**.
- If the panel becomes too tall to fit beside the main content, Happier automatically switches it to an **overlay**.
- If you shrink it again, it returns to the docked layout.

### Overlay behavior

When the bottom panel is shown as an overlay:

- it appears above the session content,
- tapping the scrim closes it,
- pressing **Escape** closes it when focus is outside terminal text input.

## Session continuity

The embedded terminal is meant to feel like one session-owned terminal, even if you move it around.

What to expect:

- Hiding the bottom panel, switching tabs or opening a terminal in Details keeps its process running; it replays when shown again.
- In the development build, closing a terminal also removes its retained Details view; reopening Details does not restart a closed terminal.
- Refreshing the page with the terminal open restores the open panel and reconnects to the same terminal for that session.
- Returning to a session restores that session’s terminal state.
- A different session does **not** automatically inherit another session’s terminal state.

## Mobile behavior

On mobile/native clients, Happier renders the terminal through an embedded WebView terminal surface.

That gives you:

- live terminal input and output,
- resize handling,
- restart and clear actions,
- a key rail above the keyboard (Esc, Tab, sticky Ctrl and ⌥, ⌃C, ⌃D and common symbols) and
  floating arrow keys you can move or tuck away (development build).

On phone layouts using the default **Cockpit** session layout, Terminal appears as a bottom session tab when all of these are true:

- the Embedded terminal feature is enabled,
- the current session resolves to a reachable machine target.

If the terminal tab is not available, Happier hides it instead of showing a broken empty tab. In that case, use the session header terminal action.

In Cockpit, the terminal keeps the normal session header and safe-area spacing, and switching between Terminal, Files, Git, Tabs, and the agent chat does not add every tab switch to the back stack.

In the **Classic** mobile layout, the terminal still behaves more like a focused terminal screen than a multi-pane desktop layout.

## Requirements

The embedded terminal depends on all of the following:

- the **Embedded terminal** feature toggle is enabled in **Settings → Features**,
- your **daemon is running and connected** for the machine you want to control,
- the current session resolves to a reachable machine target.

If the machine goes offline, the terminal keeps its last output and says so with **Check again**. If a terminal cannot start, it names the cause and offers **Try again**.

## Important things to know

- Commands run on the connected machine for the current session.
- The embedded terminal is best for session-adjacent work: quick shell commands, local scripts, logs, git inspection, and following links emitted by tools or dev servers.
- The terminal surface can reconnect automatically after short-lived daemon/RPC hiccups.
- Detected local URLs appear as a pill in the strip so you can open them quickly.

## Common use cases

- Run `git status`, `git diff`, or project scripts while reading the transcript.
- Start a local dev server and open its address from the strip.
- Follow logs while keeping the main transcript visible.
- Keep one session’s shell history open while moving between panel layouts.
- Open a provider login flow from settings without leaving Happier.

## Provider login terminal

When a provider supports native CLI login from Happier, the app opens that login flow with the same terminal transport and pane system used for session terminals.

What stays consistent:

- the shared connected-machine terminal session model
- detected URL banners with copy/open actions
- restart, clear, and close actions
- bottom-pane presentation on larger layouts
- focused presentation on smaller layouts

Provider login flows are documented in [Provider authentication](/agents/provider-authentication).

## Troubleshooting

### I enabled the feature but the terminal still does not open

Check:

- the **Embedded terminal** toggle is enabled,
- the daemon is running,
- the session is attached to a reachable machine,
- you are on the same server profile as the daemon you connected.

For daemon setup and lifecycle commands, see [Daemon](/apps/daemon).

### The terminal opens, but I want it somewhere else

In the development build, use **Open in Details** from the terminal's tab menu for a wide view
beside the chat. Released builds choose a location in **Settings → Features → Embedded terminal
location**.

### The bottom terminal covers the session

That should happen only when the panel no longer fits in a docked layout.
Shrink it again and it returns to the docked bottom-panel layout.
