---
title: Provider Integrations
description: Connect third-party model routers and compatible model APIs to Happier Agents.
---

Happier runs **Agents** such as Claude Code, Codex, and OpenCode. A **Provider** is a model source that an Agent can use, such as OpenRouter, DeepSeek, a company gateway, Ollama, or LM Studio.

Configure model routing under **Settings → Providers**. Profiles remain optional launch presets and are not the owner of provider endpoints, API keys, or model catalogs.

For MCP servers, including detected Agent-native MCP configuration and per-session selection, see [MCP servers](/features/mcp-servers).

## Connect a third-party model API

If the service is a built-in Provider:

1. Open **Settings → Providers**.
2. Select the Provider and add a connection. You may add more than one connection for separate accounts or deployments.
3. Add the requested API key through Saved Secrets.
4. Test the connection on the machine that will run the Agent.
5. Start a session and choose a model from that Provider's section of the model picker.

For an unlisted service, choose **Add custom provider** and select the compatibility contract the service actually implements. Enter its base URL, add an API key if required, and fetch or manually add its model ids.

The model appears only for Agents whose protocol and required capabilities are compatible. An unverified pairing may be shown as **Experimental** and require explicit confirmation; an incompatible pairing is not selectable.

## Local routers and model servers

Local endpoints are scoped to the target machine. Happier may detect a running process, but it confirms availability by probing the Provider's model API before showing it as connected.

For a local router such as Claude Code Router:

1. Install and start the router on the machine that runs the Happier daemon.
2. Open **Settings → Providers → Add custom provider**.
3. Choose the router's documented API compatibility and enter its loopback URL.
4. Add its token through Saved Secrets if it requires one.
5. Enable the connection for that specific machine and test it.

The per-machine confirmation is deliberate. `localhost` and private-network addresses can identify a different service on every machine, so Happier does not send credentials to them from another machine without an endpoint-bound machine grant.

If a supported local Provider such as Ollama or LM Studio is discovered, it appears under **On this machine**. Enabling it uses the same connection and machine-grant path as a manually configured local endpoint.

## Environment switchers

Tools such as shell-based Claude endpoint switchers commonly print `ANTHROPIC_BASE_URL` and token exports or launch `claude` themselves. Those exports may still affect a Happier process started from the same terminal, but they are not the durable configuration path for remotely started sessions.

Use a Provider connection instead:

- the endpoint is typed and validated;
- the key stays in Saved Secrets;
- model discovery and compatibility are visible before launch;
- the exact connection is persisted with the session;
- child-process configuration is scoped to that Agent session rather than mutating the daemon environment.

Do not use wrapper commands that launch an Agent directly (for example a router's `... code` command) when you need Happier session syncing. Start the Agent through Happier and select the configured Provider model.

## Agent-native config-file integrations

Some integrations install plugins or write configuration files that an Agent reads directly. For example, an OpenCode plugin may modify files in OpenCode's configuration directory.

These are Agent-local customizations rather than Happier Provider connections. They work when:

- the Agent and integration are installed on the target machine;
- the same machine-local configuration is visible to the Agent process Happier starts;
- the integration does not bypass Happier by launching a separate Agent process.

If the integration changes where models come from and exposes a compatible model API, prefer a first-class Provider connection so Happier can validate credentials, catalog models, preserve exact selection identity, and apply machine safety rules.

## Troubleshooting

- **Provider is missing from the picker:** verify it is enabled on the target machine and that the selected Agent is compatible.
- **Needs API key:** bind a Saved Secret on the Provider connection; do not put a bearer token in the URL.
- **Local Provider is unreachable:** confirm the service is running and its server API is enabled, then test the connection again.
- **Machine confirmation required:** the endpoint is loopback/private or resolved to private space; enable the exact endpoint on that machine.
- **Model disappeared:** refresh the catalog or add the model id manually. Existing favorites and sessions retain a visible stale reference rather than silently switching models.
- **Provider was deleted:** choose another connection or recreate it. Happier never falls back silently to an Agent's native provider.
