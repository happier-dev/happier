---
title: Resume an agent's own session
description: Start a Happier session by resuming a Codex, Claude, or OpenCode session you already have, either by pasting its session ID or by browsing for it.
---

If you already started a session in your terminal and want to carry on with it from your phone, Happier can pick it up. You give it the agent's own session ID, and Happier opens a new Happier session that resumes that existing conversation rather than starting a fresh one.

This is one of several things that sound similar. It is not:

- [Resume inactive sessions](/features/session-resume) — waking a Happier session that has gone quiet
- [Browse and import provider sessions](/features/browse-and-import-sessions) — opening an agent's sessions as direct sessions and optionally syncing them

## What you are pasting

The value is the agent's own session identifier — the key its CLI uses to reopen a conversation. Happier creates a new Happier session, asks the agent to resume that conversation, and connects to the result.

You can find these identifiers on the Session Info screen, which is where Happier's own help text points.

## Where to enter it

In the new-session flow:

1. Open the new session screen.
2. Choose the AI backend (Codex, Claude, OpenCode, …).
3. Open the input controls and find **Resume session**.
4. Paste the session ID, or use **Browse sessions** when it is offered.

## Browsing instead of pasting

For some agents, Happier can list the sessions already on the machine and let you pick one, which fills the field for you. **Browse sessions** appears next to the input when that is possible.

What the list contains:

- It is only offered when the selected backend supports session browsing.
- It is scoped to the agent and machine you already chose in the new-session screen.
- For Codex, it is scoped further — to the Codex home implied by your auth choice.

Picking a session fills the field and closes the control.

### Codex homes and connected services

Codex can have more than one home in Happier:

- the standard user Codex home on the machine
- a Connected Services home, when you start Codex with a connected-service profile

The browse list is deliberately locked to the home implied by your current selection. Without that, it would be easy to pick a session from a different home that then fails to resume under the auth you actually selected.

To browse a different Codex home, change the Codex auth choice in the new-session flow first, then reopen the picker.

## When it goes wrong

**No Browse sessions button.** Either the selected backend does not support session browsing, or no machine is selected yet. You can still paste the ID by hand.

**The browse list is empty.** Check that the selected machine is online and reachable, and that you are browsing the right agent and auth context — for Codex, the right home or profile.

**"This resume ID can't be applied right now."** Happier will start a new session instead. Confirm the agent is configured for resume — for Codex, that its routing mode is App Server, ACP, or MCP with resume — and that the machine has the dependencies that mode needs.
