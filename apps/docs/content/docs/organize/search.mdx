Twenty sessions, four worktrees, and a half-remembered decision from last
Tuesday: Happier's Search exists so none of that requires remembering where
something lives. Open one surface, type a few words, and jump straight to the
command, message, or file you meant.

<Callout type="info">
  Search replaces the old commands-only palette in the **Happier 0.3
  development channel**, which is the channel this page describes. It is not
  yet part of a released stable version. On earlier releases the same shortcut
  opens a commands-only list and `/search` can still be transcript-only.
</Callout>

## Opening Search

There is one Search and several ways in, all reaching the same surface:

- **Shortcut** — <kbd>Alt</kbd>+<kbd>K</kbd> on web, or
  <kbd>Mod</kbd>+<kbd>K</kbd> elsewhere (<kbd>⌘</kbd>+<kbd>K</kbd> on Apple
  devices, <kbd>Ctrl</kbd>+<kbd>K</kbd> on other platforms), opens Search
  when app focus permits. The
  command is called **Open Search** and its shortcut can be rebound or disabled
  under [Keyboard shortcuts](/apps/keyboard-shortcuts). Disabling the shortcut
  does not disable the sidebar, native action, deep link, or session-list entry.
- **Sidebar** — the **Search** row in the session list's sidebar, directly
  above **Browse Existing Sessions**.
- **Native** — the Search action in the phone and tablet apps opens Search as a
  full-screen overlay; on devices with a hardware keyboard the same shortcut
  works.
- **Deep link** — `happier:///search` opens the same Search surface directly,
  so a bookmark or history entry lands in the same place.
- **From the session list** — when you have typed into the session list's own
  search field, a quiet **Search everything for …** action escalates the same
  query into Search.

## What you can find

Results are grouped by what they are, and each group answers at its own pace —
local groups are instant while remote ones fill in as they arrive:

- **Commands** — built-in commands and Actions contributed by trusted plugins.
- **Sessions** — your sessions, including archived or not-currently-loaded ones
  when their owning source permits. Session IDs, visible titles, workspace or
  project names, paths, tags, and machine details match immediately. Transcript
  bodies are searched only by the message source below. If a Session has no
  explicit title and Happier has already made its first user message the visible
  Session title, that bounded title remains searchable like any other title.
- **Projects** — projects and workspaces from your account's synced
  projections.
- **Messages** — matches inside session transcripts, from the transcript
  source described [below](#where-message-results-come-from).
- **Settings** — settings pages, matched on their titles and keywords.
- **Files** — files in the exact workspace you currently have open.
- **Text in files** — text matches in that same workspace, grouped by file
  with line numbers and matching-line snippets. The machine must be online and running
  a Happier build that supports content search.
- **Commits** — commits reachable from the current Git branch or the current
  Sapling parent set in that workspace.
- **Plugin results** — entities from trusted plugins that provide a search
  provider, such as [PRs & Issues](/code/prs-and-issues).

## Nothing typed yet? Start from what you had open

Opening Search and hovering over the results before you type costs nothing
remote: an empty query shows recent sessions, recent projects, and suggested
commands from what is already on the device. Not a ranking system — just the
things you had open. The moment you type, the wider groups join in.

## Search inside workspace files

Choose **Text in files** to search file contents rather than filenames, or
press <kbd>⌘</kbd>+<kbd>Shift</kbd>+<kbd>F</kbd> on Apple devices
(<kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>F</kbd> elsewhere) with app focus to
open that scope directly. Searches treat your text literally and ignore case
by default; use **Match case** or **Regular expression** when you need them.
Results come in one page. **Refine your search** means more matches remain;
make the query more specific to narrow the results. Partial coverage means the
answer is not exhaustive, including when the search stops early or a file
cannot be represented as searchable text.

You can also paste a file link or enter `path:line` to open a particular line.
Windows drive prefixes and colons inside filenames remain part of the path.
An older machine build shows an update hint; an invalid regular expression
shows a pattern error rather than pretending there were no matches.

Opening a text hit takes you to its matching line in the session or project
file pane and opens Find with the same query. Monaco seeds its own Find
widget. The query travels in memory; it is not saved in the file URL. This
search reads files on the selected machine without creating a content index.

## Find inside the current surface

Use <kbd>⌘</kbd>+<kbd>F</kbd> (<kbd>Ctrl</kbd>+<kbd>F</kbd> elsewhere)
inside chat, a text file, a diff, a review, or a supported terminal to open
Find there. In a session, composer focus opens chat Find. On touch, use
**Find in chat** in the session menu or the surface's Find control.

Find highlights matches and shows your position. <kbd>⌘</kbd>+<kbd>G</kbd>
steps forward and <kbd>⌘</kbd>+<kbd>Shift</kbd>+<kbd>G</kbd> steps back
(use Ctrl instead of ⌘ on other platforms). In the Find input,
<kbd>Enter</kbd> and <kbd>Shift</kbd>+<kbd>Enter</kbd> do the same.
<kbd>Esc</kbd> closes Find and restores focus. **Match case** and
**Regular expression** change how the query matches.

Chat Find searches decrypted display text on your device, including text
inside collapsed groups and tool output. Loaded messages are searched first;
search older messages on demand and use **Stop** to pause that work. Incomplete
or unreadable history stays identified as incomplete, so zero matches in the
loaded range does not mean zero in the whole conversation. E2EE text is never
sent to a server search by Find.

On web, the browser's Find remains available outside a findable surface.
Press the Find shortcut again from the open Find input to use browser Find.
See [files, review and terminal Find](/code/files-and-editor#find-in-files-diffs-and-review)
for editor and terminal limits.

## Search conversations outside Happier

In **0.3 development/preview**, conversation search has two modes. **Memory
search** reads a machine's local index and can return matches as you type.
**Search on demand** scans Agent conversation history when you explicitly
start it. Choose which modes run under **Settings → Search**, after selecting
the machine. Search on demand is on by default; indexing conversations started
outside Happier is off by default.

To include those conversations in the index, turn on Memory search, then enable
**Index these conversations** under **Conversations outside Happier** and select
the Agents to include.
Choose **How far back** and whether to **Include tool output**. An empty Agent
selection indexes none. The history choice also respects the machine's memory
backfill and coverage settings. The local index contains **plaintext on that
machine**, including text read from encrypted Happier sessions. Read
[local memory search](/organize/local-memory-search#privacy-and-cleanup) before
enabling it on a shared computer.

Typing in Search reads eligible indexes. To scan sources that are unindexed
or still catching up, activate the conversation-search row. A source whose
index is ready can answer without a scan; other sources fall back to Search on
demand when it is enabled. The machine must be online and advertise support.

You can also open **Browse Existing Sessions**, select the machine and
Agent source, switch from **Titles** to **Conversations**, enter a phrase,
and choose **Search**. Results show matching text. A scan can yield an incomplete
page before it finds a hit; an empty partial page does not mean no matches.
Choose **Search more conversations** when offered to continue from that page.
**Stop** leaves coverage incomplete. A very large conversation may remain
incomplete on repeated attempts; continuation does not guarantee a full scan.

Standard search supports Claude Code, Codex, Pi, OhMyPi, Antigravity and
OpenCode in this development channel. File-based sources search decoded
transcript text; OpenCode reads messages through its native client. Codex
app-server-only threads without a searchable local transcript remain a
coverage gap. Indexed search uses the selected Agents' existing transcript
readers, including those six where their configured source can be read; an
Agent being installed does not guarantee readable history. Older daemons show
an update hint. Partial coverage or an unsupported source is not a claim that
no conversation matched. A standard scan creates no persistent content index.

The standalone **Browse Existing Sessions** conversation view currently runs
its own explicit source-local scan; it does not yet select indexed results.

Choose **Open in Happier** to link and open a result, with Find on the query
at the mapped message when available. **Show in External sessions** keeps the
same machine and source in the browser. Opening a search hit does not take
over the Agent conversation.

## Go to the next session waiting on you

Next takes you to the oldest pending question, permission or user action you
can answer in another session. On desktop, use
<kbd>⌘</kbd>+<kbd>Shift</kbd>+<kbd>J</kbd>
(<kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>J</kbd> on Windows/Linux).
In a web browser, use <kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>J</kbd>
(<kbd>⌥</kbd>+<kbd>Shift</kbd>+<kbd>J</kbd> on macOS).

The header's **N need you** pill counts other answerable sessions, not
individual requests. On phone, use the amber count capsule in session
navigation. After you answer, a **Next** pill above the composer offers the
next session. Next lands on the request and focuses its answer control;
you still choose the answer yourself.

Next uses request creation time, with unknown times after known times.
Unavailable details are reported rather than counted as no pending work.
If someone answers while you are opening the request, the settled state lets
you continue to the next one. Unread messages and failed delivery belong to
the Inbox, rather than this pending-request order.

Some Action approvals in sessions hosted by a shared editor only surface
after you open the session; Next cannot discover those approvals from a cold
session summary yet.

## Let an Agent use Search and Find

In this development channel, an Agent or MCP caller can use
`workspace.files.search` for workspace text and `sessions.external.candidates.list`
with `searchTarget: 'content'` for conversations on a selected machine. The
conversation Action returns coverage and a cursor for continuing incomplete
scans; it also works through standalone MCP.

`search.conversations` searches one or several machines with indexed, standard
or best-available mode through a connected app. `search.settings.get` and
`search.settings.set` read and change the machine's Search choices;
`memory.status` reports index readiness and source states. `memory.clear_index`
clears the derived index and **requires approval by default**, according to
the configured Action policy. It keeps the saved settings; enabled indexing
can rebuild it. [Local memory search](/organize/local-memory-search) explains
clearing and fetching the context around an indexed hit.

With an app connected to the addressed machine, `ui.find` controls Find in a
mounted surface and `session.pending.next` opens the next answerable request.
Find returns status and counts where available, never the searched text.
Without a connected app, Find returns **unavailable** with reason `noClient`,
and Next returns **unavailable**. A connected app with no findable surface
returns `noMountedSurface`, which is different from zero matches.

The app runs delivered Actions through the same controls you use. If an Action
requires approval, it waits for the required decision before execution;
rejecting or canceling it prevents execution. If the connection is lost after
dispatch, an uncertain outcome is reported rather than a claimed success.
The [generated Actions catalog](/plugins/api/host-actions) describes each
Action's inputs, results and supported surfaces.

## Where message results come from

Happier chooses the source for Happier-session results and can add indexed
conversations from the machines in scope:

- **Personal Home search**. If you use a
  [Personal Home](/self-hosting/self-host-runtime), its plaintext transcripts
  are searchable as soon as the Home has finished building its search index.
  This is on by default; a server operator can turn it off. Each match points
  to one message and shows text centered around the match. A short message may
  fit in full, but the result is not guaranteed to contain the complete
  verbatim message.
- **Local memory search**. Otherwise, machines where you have turned on
  [local memory search](/organize/local-memory-search) answer from their own
  machine-local index. Results can be message chunks or short generated
  summaries. Opted-in conversations outside Happier use the machine's index
  alongside these results. Summaries need not be verbatim transcript text.

Each source follows its own controls above, and both are
**your** data on machines you control. Personal Home search keeps its derived
index on that Home and serves it through an authenticated, visibility-filtered
Home endpoint; local memory search keeps its derived index on the selected
machine. Happier does not copy every Home and machine into one central index or
offer a server-side endpoint that aggregates every Search domain.

## Scope is deliberate

Search starts from the context you opened it from:

- conversation search can use one machine or **All machines** within the
  selected Home. This queries online machines in parallel; each keeps its own
  index, and offline machines cannot answer. E2EE conversation search runs
  locally on those machines rather than indexing encrypted text on the server;
- files search **the exact workspace you have open** — no other repository, no
  other machine. Commit search stays within that workspace's current Git branch
  or current Sapling parent set.

Search starts with the exact context you opened it from. If another reachable
Home or workspace is available, use the compact scope control to search that
target explicitly. This changes only the open Search surface—not the Home or
session focused elsewhere in Happier. **Search everything for …** preserves
the Home selected in the session list.

In All machines scope, merged conversation results are newest first.
Indexed hits use the matching message's time; scanned hits use the
conversation's update time. Scores from different indexes are not compared.
Duplicate Happier-session results are collapsed.

The coverage line names machines that are **Offline**, **Needs an update**,
disabled, or returning **Partial results**. Full coverage has no warning line.
Partial results may mean more pages remain, a source is still indexing, or
some history could not be read. Changing the query cancels the previous search.
All machines stays within the selected Home; it does not merge every Home.

## When a group can't answer

Groups fail independently, and each states its own situation while the rest of
Search keeps working:

- **Indexing** — while a Personal Home builds its index, Search uses an
  otherwise eligible explicitly selected local-memory machine. If there is no
  such machine, the Messages group reports the Home's indexing state.
- **Offline** — a machine or Home that cannot be reached reports that instead
  of pretending to have no matches.
- **Disabled** — if transcript search is unavailable for your context (the
  feature is off, or no machine has local memory enabled), the group explains
  what to enable rather than showing an empty result.
- **Partial coverage** — local memory search keeps its index within a disk
  budget, so the oldest indexed content can be evicted. Coverage under a
  budget is honest, not complete.

## Archived sessions

Local memory search **excludes archived sessions by default**. Turning on
**Search archived sessions** for a machine makes its archived sessions
eligible, and turning it off removes them from that machine's search index.
The control lives with the machine's memory settings under
**Settings → Local memory search**.

Two honest details about that switch. First, enabling it does not
retroactively index everything: what gets indexed still follows the machine's
backfill choice (**New only**, **Last 30 days**, or **All history**).
Second, the switch only applies where a machine's Happier build supports it —
if a machine has not reported support, Happier says an update is needed there
instead of letting you believe a setting was applied that was not.

## Opening a result

A result remembers exactly where it came from: which Home, which machine,
which session, which workspace. Opening it takes you to *that* target — search
messages while thinking about Home A, tap a result, and Home A opens even if
your focus moved to Home B while results were loading. If the target has since
disappeared or gone offline, Search tells you that rather than opening
something else that happens to look similar.

## Plugin-provided results

Trusted plugins can contribute search providers, and their results render as
ordinary Search rows: the plugin supplies typed data and a declared target,
while Happier draws the rows and handles selection, keyboard, and
accessibility. A plugin's rows disappear safely when the plugin is disabled,
updated, or removed. Results are bounded, and when a plugin's answer was
truncated it says so instead of posing as the complete list.

## Settings configures, Search searches

Settings pages are a search *result*, not a search *entry*. Choose conversation
modes and native indexing under **Settings → Search**; follow **Memory search**
there for indexing options under **Settings → Local memory search**. The
`memory.search` feature switch lives under **Settings → Features**. Personal Home
search is separate: the Home operator controls its availability, and there is
no app setting that turns it on for an individual machine. Then search from
Search, the sidebar, or the session list like everywhere else.

## When it goes wrong

- **The shortcut does nothing** — check that **Open Search** is enabled and
  bound under [Keyboard shortcuts](/apps/keyboard-shortcuts). Disabling that
  command disables only the keyboard shortcut; Search remains available from
  the sidebar, native action, deep link, and session-list entry.
- **No message results anywhere** — see
  [Where message results come from](#where-message-results-come-from): enable
  local memory search on a machine, or check with your server operator that
  Personal Home search is available.
- **A machine finds nothing it used to** — confirm that machine is online and
  still has memory search enabled, and check whether its archived or backfill
  settings changed; disk-budget eviction can also retire the oldest content.
- **A file or commit result is missing** — files only search the workspace you
  currently have open. Commits also stay within its current Git branch or
  current Sapling parent set. Open the intended workspace and branch or parent,
  then search.
