Once you are running more than a handful of sessions, the list becomes the
problem. Happier gives you four ways to impose order on it, and all four are
stored on the server, so the arrangement you build on your laptop is the one you
see on your phone.

Folder-based clients have folders on by default, unless their server operator
has disabled `sessions.folders`. The 0.3 development section model below uses
the server's ordinary Sessions availability, with no separate folder switch.

## Sections in 0.3 development

The unreleased 0.3 organization model uses named, icon-bearing sections across
an Account on one Home. A section can hold sessions from different projects and
machines. Filing a session changes your arrangement, not its directory or where
it runs. Two Homes keep separate sections even when their names match.

Existing folder identities, names and assignments carry into sections. Nested
folder data remains readable without rewriting private content. A locked name
stays unavailable with its membership intact; it does not turn into an empty
section you can overwrite.

Removing a section keeps every session and every child section. Its own sessions
and direct legacy children move to its parent; removing a root section returns
its own sessions to their projects. Archive all uses exact section membership,
including sessions outside the loaded list, and reports failed or unknown
outcomes separately. These are different operations: removal changes your
organization, while archive changes the member sessions.

An acknowledged move can offer Undo. Undo checks the current assignment first,
so it preserves a move made since that acknowledgement. A write with an unknown
outcome offers no Undo. A section chosen before a new session starts remains
selected when you change machine or directory within the same Account; changing
Home or Account requires that selection to be checked again.

This describes 0.3 development source, not a released-client availability claim.
A 0.3 client connected to an older 0.2 Home still encounters that Home's recursive
folder removal, which can remove nested folder definitions too. Upgrade the Home
to obtain nonrecursive section removal.

## Saved spaces in 0.3 development

The unreleased 0.3 list work uses a **space** for a saved view and a **section**
for filing sessions. A Session space includes sessions that match its saved
filter or were added by hand; a manual-only space includes only hand-added
sessions. **Add to space** adds membership without changing the session's
section. Move and Remove change only hand-added membership, so a session that
still matches the saved filter can remain visible.

Switching a space does not move sessions, start work, change access or change
who you follow. Temporary filter changes narrow the displayed membership;
Reset returns to the saved filter. Find text remains temporary and is not saved
with the filter; Updated conditions use absolute dates, not a moving time window.

Space definitions belong to your Account. The selected space belongs to this
device and Account, so another device can receive a definition without being
switched away from its current list. Sessions and their Runs share spaces;
Workflow definitions and Discussions keep their own selections.

Spaces have an Account-wide master switch and a switch for each list. Turning
them off retains definitions, hand-added membership and this device's selection,
so turning them back on restores the saved view.

Local conditions use already-held rows. Changing a structural scope, such as
the selected Homes or a positive Section selection, uses the ordinary list
request. Counts describe the available corpus: missing or locked filter facts
remain unavailable rather than becoming an authoritative zero or a match.
These interfaces are still being integrated in development source; this is not
a released-client availability claim.

## Folders

Folders group sessions the way directories group files, and they nest.

- Create, rename, move and delete them, and nest one inside another.
- Assign a session by dragging it onto a folder, or through the session's
  context menu.
- Drag a session onto the workspace root to take it out of a folder without
  putting it in another.
- Focus a folder to see only its contents, with breadcrumbs back out.
- Collapse folders you are not working in.

**Deleting a folder does not delete its sessions.** They move up to the parent
folder, or to the workspace root if the folder was top level. There is no
variant that discards the contents, which is deliberate — a mis-click on a
folder should never lose work.

Drag and drop works the same way on web, iOS and Android, including
drag-scrolling when the target is off screen. If the server rejects a change
you made while offline, the move rolls back rather than silently diverging.

## Tags

Tags cut across folders. A session lives in exactly one folder but can carry
several tags, so tags are the right tool for a state or a theme that spans
projects — `needs-review`, `flaky`, `customer-x`.

Filter by one tag or several at once. Deleting a tag removes it from every
session that carried it and leaves the sessions alone.

## Pins

Pin the few sessions you keep coming back to and they stay at the top of the
list, above everything else, regardless of folder.

In development-only 0.3, the open session's three-dot menu also offers **Pin
Session**, or **Unpin Session** when it is already pinned. It changes the same
Session-list pin; Bot rail pins remain separate.

Pins sit outside the Active and Inactive sections, so a pinned row says for
itself when its session is no longer live: like any offline row, it says
**Offline** under the title, and its avatar or agent logo is dimmed.

Pinned sessions appear during the first paint of a long list rather than after
you scroll, which is the point of pinning them. Archiving a session removes it
from the pinned list and gives the pin quota back.

Development-only 0.3 keeps Session-list pins and Bot rail pins separate. Only a
Session already marked as a Bot can be added to the rail; pinning never turns
an ordinary session into a Bot. Each pin is your personal choice, not a change
to another person's arrangement.

Adding or removing one pin leaves the other alone. Both use one shared order
and count the session once against the pin limit. Existing pins stay list-only
after upgrading. Demoting a Bot hides its rail entry but retains the saved
choice, so promoting it again restores the entry.

In development-only 0.3 the rail has one **Bots** entry. It opens a list of all
your bots, including inactive ones, with what each is doing now, **Talk** and
**More** on each row, then **New bot** and **Ask Happier**. A dot signals that
a bot needs you; Inbox keeps the global attention count. Bots you pin to the
rail sit just under that entry;
when the rail is too short, they move into the rail's More menu. On a phone, or
when there's no rail, the same list opens as a sheet from the app's
destinations and the command palette.

## Bot readiness in 0.3 development

A configured Bot is not necessarily ready to answer. Development Action callers
can request `session.status.get` with `{sessionId, readiness: true}` to inspect
the selected Machine, Agent and current permission to submit input. The result
reports ready, unavailable or unknown and its cause. Missing or stale evidence
stays unknown.

The default checks conversation readiness. A caller can also request a credential
operation with `operation: 'credential'` and its qualified `credentialPurpose`.
That checks the operation's selected personal connection through its setup owner.
A Team operation also supplies that owner's exact `credentialTeamSelection`.
The diagnostic checks the purpose, service and resource binding against current
admitted facts, retaining the resource owner's reason and recovery when unavailable.
Another Account's private setup remains unknown when
the reader cannot inspect it; Happier does not substitute the viewer's connection.
An optional integration does not block ordinary conversation.

The diagnostic grants no permission to write or repair. A reported repair opens
the normal setup flow for its exact target and still needs its own authority.
People and Bot readiness rendering is still being built; this section describes
the unreleased diagnostic contract.

## Referencing another session

In development-only 0.3, **Copy information** is available from a session's
three-dot menu, list menu and Info screen without developer mode. Paste the
text into another session to provide its Happier session ID, agent session ID
and log paths when available. Review those paths before pasting outside your
own sessions. Copying information does not grant access to the session.

You can also type `@` in the composer and choose a session from the suggestions;
`@session:` narrows the suggestions to sessions.

## Selecting several at once

Open a row's menu (right-click on desktop or long-press on touch) and choose
**Select** to start a selection. Then archive, delete,
move, mark read, or change attention handling for all of them together. The
selection survives the list updating underneath you and survives scrolling.

In development-only 0.3, Shift-click selects a range, `x` toggles the focused
row, and Shift+Up/Down extends the range. Once selecting, tap or click rows to
toggle them; Escape or Done exits. Checkboxes do not appear merely on hover,
and long-press continues to open the row menu. Command-click on macOS or
Ctrl-click on Windows/Linux opens an openable row in a new kept workspace tab,
as do Alt-click and middle-click; it does not change the selection.

## Ordering

Within a scope — pinned, a folder, a tag, a workspace, a group — you can set
your own order rather than accepting the default sort. That order is stored per
scope, so the arrangement inside one folder does not disturb another.

## Limits

Generous, but not unbounded. Each is per account:

| Thing                                   | Limit |
| --------------------------------------- | ----- |
| Folders                                 | 500   |
| Tags                                    | 500   |
| Pinned sessions                         | 1000  |
| Session attention choices and reminders | 500   |
| Workspace and group labels              | 1000  |
| Sessions changed in one bulk action     | 500   |
| Custom order entries per scope          | 1000  |

These bound the snapshot every client parses on first paint, which is why they
exist at all. A write past the limit is refused with an explanation rather than
being accepted and silently dropped.
