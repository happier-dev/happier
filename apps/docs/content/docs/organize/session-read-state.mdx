title: Session read and unread state

Happier tracks which sessions still need your attention.

<Callout type="info" title="Per-Account read state is in development">
The current 0.3 development path keeps read state separate for each Account:
reading a shared Session changes your progress without clearing another
person's unread state. Session owners are tracked automatically; other readers
become tracked through an active Follow. A tracked view-only reader can mark
their own Session read or unread. This path still needs its upgrade, loaded
web/native, and multi-device validation, so it is not a released availability
claim.
</Callout>

For normal Happier sessions, unread state means:

- the session has committed transcript activity after your last viewed position
- or you manually chose **Mark as unread**

For linked **Direct** sessions, Happier can also use provider-observed direct-session progress. When that direct-session attention says the provider session changed, the session is treated as unread even if the Happier transcript cursor would otherwise look current.

Unread state appears in the session list, Inbox, and other attention surfaces.

## Where to find the actions

You can change a session's read state from the same places you manage other session actions:

- the session row **...** menu in the session list
- the session row long-press/context menu on mobile
- the session header action menu
- the Session info screen quick actions

When the session is currently read, Happier shows **Mark as unread**.

When the session is currently unread, Happier shows **Mark as read**.

## What Mark as unread does

Use **Mark as unread** when you want a session to stay in your attention flow.

For example:

- you opened a session but want to come back later
- you read enough to know it still needs follow-up
- you want the session to remain visible in unread-focused surfaces after triage

For normal Happier sessions, marking unread moves your read position to just before the latest committed transcript activity. The transcript itself does not change.

For Direct sessions, the same action also updates the direct-session attention marker so the linked provider session can still appear as needing review.

Marking a session unread is not a good way to keep a session in front of you after you have read it, because opening it again clears the unread state and the session drops back down the list. Use [Keep in Needs attention](#keeping-a-session-in-needs-attention) for that.

## What Mark as read does

Use **Mark as read** when the session no longer needs unread attention.

For normal Happier sessions, Happier moves your read position to the latest committed transcript activity.

For Direct sessions, Happier also records the currently observed provider progress as viewed. The unread badge clears unless newer transcript or provider activity appears afterwards.

## Keeping a session in Needs attention

Read state tracks whether you have seen a session yet. It is a poor fit for a session you have already read and still want near the top, because reading it is exactly what clears the signal.

**Keep in Needs attention** covers that case directly. A session you keep stays in the attention area of the session list whatever its read state, until you remove it.

- **Keep in Needs attention** holds the session there after you read it.
- **Remove from Needs attention** lets it move back down the list again.

You will find it with the other session actions, alongside **Mark as unread**. Session-list multi-select offers the same choice for several sessions at once.

A kept session shows **kept in attention** as its status line, so it stays distinguishable from a session that is in the attention area because it is unread, ready, or waiting on you. Kept sessions also sort after those, so a session that genuinely needs you still comes first.

Your choice is stored per session on the server, so it follows you across devices and browser windows for the same account.

### Turning the attention area on

The attention area itself comes from **Settings → Session → Sessions needing attention**, which is **Leave in normal position** by default. Set it to **Group at top** or **Move to top of current group** first; until then nothing is placed there and keeping a session has nothing to hold it in.

### Choosing the default

**Settings → Session → Keep sessions in Needs attention** decides what happens to sessions you have not made a choice about:

- **off** (the default): sessions leave the attention area as soon as they no longer need you, and you keep the ones you care about one at a time
- **on**: every session stays in the attention area until you remove it, which turns the area into a list you clear by hand

A per-session choice always wins over the default, in both directions: a session you removed stays out of the attention area even when the default is on.

## Reminding yourself later

Use **Remind me** when you have read a session but want it to return to **Needs attention** at a
specific time. Choose one of the suggested times, pick **Choose date and time…**, or select a saved
preset. The session row shows a small clock, and reopening **Remind me** shows the scheduled time and
the currently selected choice.

Setting a reminder marks the session's current content read. With no stronger attention reason, a
future reminder temporarily moves the session out of **Needs attention**. When the time arrives, the
session returns there without becoming unread, even when no new message has arrived. By default,
opening the session clears a due reminder; future reminders stay scheduled. The clock clears, while
the session keeps its list position until you leave. It then leaves **Needs attention** unless you
kept it there or another attention reason still applies.

Turn off **Settings → Session → Clear reminders on open** to remove due reminders manually with
**Remove reminder** or choose another time.

A reminder and **Keep in Needs attention** are separate choices. If you set a reminder on a kept
session, the future reminder temporarily hides it from **Needs attention** without forgetting the
Keep choice. Removing the reminder restores that choice. Choosing **Keep in Needs attention** or
**Remove from Needs attention** while a reminder is set clears the reminder and makes that attention
choice the new lasting state.

When choosing a custom date and time, **Add to presets** saves a reusable calendar rule rather than
one fixed date. For example, a preset shown as `Friday · 2:00 PM` continues to mean the next Friday at
2:00 PM. Use **Manage presets** to rename, reorder, or remove saved choices. Presets and scheduled
reminders sync through the Relay for the same Account.

Session reminders currently affect Happier's in-app attention state. They do not schedule a push or
device-local notification. An open client wakes at the next reminder time; a client that was closed
or disconnected shows the due reminder when it reconnects or returns to the foreground.

## When the session is already open

Opening a session normally marks it read because viewing the transcript is treated as read intent.

Manual **Mark as unread** is different. If you mark the session unread while you are already inside it, Happier keeps it unread for that current focused view instead of immediately marking it read again.

That means this flow works as expected:

1. Open a session.
2. Choose **Mark as unread** from the header, list, or Session info action.
3. Stay on that session.
4. The session remains unread until you explicitly mark it read, close/reopen it, or another focused view marks it read.

This avoids the common problem where marking the current item unread is instantly undone by the fact that it is still visible.

## Split views and multiple panes

On layouts that support split session canvases, each visible pane has its own viewing activation.

The read state is still global for the session. If one pane marks a session unread, that pane keeps its own focused unread hold. A different focused pane for the same session can still count as a new read intent and mark the session read.

This matches the product model: panes can have separate focus, but a session has one shared read state.

## Closing, reopening, and direct links

Closing the session view ends that viewing activation.

If you later reopen the same session directly, from the session list, from a notification, from a deep link, or by refreshing a browser tab, Happier treats that as a new viewing activation. If the session is visible and focused, it can be marked read again.

This is deliberate: reopening a session is a new read intent.

## New activity after marking unread

Unread state is based on committed transcript activity and, for Direct sessions, observed direct-session progress.

If new activity arrives after you marked a session unread, the session remains unread. Marking it read later advances to the newest committed or observed activity at that time.

Pending queued messages do not by themselves make a session unread. They use their own pending count badge instead.

## Multi-device and multi-Relay behavior

Read state belongs to the session on the Relay, so it syncs across devices and browser windows for the same account and Relay.

If you mark a session unread on one device, other connected views receive that update. If another active device then opens or views the same session, that device may mark the session read again because read state is session-wide, not per-device.

In multi-Relay setups, read state is scoped to the Relay/account that owns the session. Changing read state on one Relay does not affect an unrelated account on another Relay.

## Shared sessions, access, and personal attention

Shared sessions can be visible to a broad Team or Group audience without
creating personal attention. Access answers whether your Account may read or
act on the Session; Follow, assignment, and read state answer whether it belongs
in your personal work flow.

In the current development path, merely receiving Team/Group access does not
create a read-state row or produce unread, Activity, Inbox, badge, local
notification, or push pressure. Open the Session and follow it when you want
future activity to become part of your personal attention flow.

Changing read state requires `readTranscript` access and personal tracking.
View-only shared access can read the transcript and, once tracked, update that
Account's own read cursor. No read-state mutation updates another Account's
cursor.

If a shared session cannot be changed because of access, Happier shows the failure instead of silently changing local state.

## Sessions where the action is hidden

Happier hides manual read-state actions when they would not make sense:

- empty sessions
- archived sessions

Archived sessions do not contribute to the normal unread activity badge, so showing read-state actions there would be misleading.

**Keep in Needs attention** is hidden in the same cases, and also when the session is shared with you as view-only or when **Sessions needing attention** is left in normal position.
