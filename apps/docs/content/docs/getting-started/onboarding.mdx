> **Availability:** This Home-aware setup and Personal Home journey is in the current unreleased 0.3 checkout. Stable 0.2 keeps its released Relay-oriented onboarding.

Happier follows this high-level flow:

1. **Choose a Home** where your Account, credentials, sessions, settings, and data live.
2. **Sign in to that Home directly.** Optional account sign-in can help you find linked Homes; it does not replace the Home's own authentication.
3. **Use the desktop app or web client as your control panel.** Both can start
   and drive sessions; desktop can also install and manage the local background
   service.
4. **Get a machine ready**:
   - **This computer**: configure the local background service from the app.
   - **Remote machine**: bootstrap it over SSH from the app, and optionally save the SSH target as a reusable Remote host.
5. **Optionally configure public ingress** for an operator-managed server. Personal Homes can use Iroh without a public address.

The Home hosts the Account and synchronized session state. Coding Agents still
run on the computer that owns each session; choosing Happier Cloud for sign-in
or discovery does not move that execution into the cloud.

User guide: [Relay access](/apps/relay-access).

## Choose your setup

### Option A — Find an existing Home (recommended to start)
Use your account to find linked Homes, or connect directly to a Home whose
address or pairing link you already have. Account-based discovery does not run
your coding Agents.

1. Open the desktop app (recommended) or the web app.
2. On a supported desktop, Personal Home setup is local-first; a named account is optional. Later, choose **Find your Homes** from the connection controls to discover Homes linked to your account.
3. Sign in using an offered method. An explicit Home remains the destination; without one, a preferred or sole linked Home opens automatically, and multiple Homes without a preference require a choice.
4. Open the **Setup wizard** and choose **Set up this computer**.
   - This configures the local background service against the Home you selected.
   - If the app detects Home drift later, it shows a repair action instead of silently leaving the background service on another Home.
   - To restore access with a recovery key, choose **Use a key** on Welcome.

Optional CLI path:

```bash
# Node-free (recommended): install the CLI binary via the official installer
curl -fsSL https://happier.dev/install | bash
# The interactive installer starts setup automatically. Resume it if needed:
happier setup
```

The app-first setup is the recommended control-panel flow. The CLI is the
terminal equivalent. With no usable active Home, `happier setup` first offers
to find linked Homes through the selected sign-in service (recommended),
connect to an existing Home, create a Personal Home on this computer, or exit.
The existing-Home path then accepts a saved Home, HTTPS address, or Home
descriptor file. Passing `--home`, `--home-url`, or
`--home-descriptor-file <path|->` skips the Home-selection menus. A Home that
recommends account sign-in still lets you choose direct authentication before
contacting the optional service. Setup performs any required
interactive approval, registers the machine, and reconciles the service;
`happier setup plan` only previews the steps.

If account sign-in connects an encrypted Home but this computer still needs its
encryption material, setup continues through device pairing. To resume that
recovery for a saved Home without discarding its stored credential:

```bash
happier --server <saved-home> auth login --recover-account-material
```

This development-only option rechecks that Home's encryption mode. Plaintext
Homes do not require recovery keys; an unavailable mode check is not treated as
plaintext. Do not use `--force` for this recovery: it clears authentication state.

Notes:
- The desktop app and the installer-installed CLI are self-contained; you do not need system Node/Yarn installed.
- If you prefer an npm workflow, see [CLI install](/apps/cli) (requires Node).

### Add another computer with a link

In the unreleased 0.3 app, open **Add a machine → Another computer** on Home
to generate a temporary Home-pairing link. Install the desktop app on the other
computer and open the link there. Share this link only with your own device.

After sign-in, the desktop app continues with **Set up this computer** for that
exact Home and Account. It registers the machine and installs, starts and checks
its service. Follow any CLI or service consent prompts. The sending app notices
the machine when it comes online; redeeming the link alone is not completion.

If service setup fails or you cancel it, the Home stays saved. **Retry** repeats
setup without redeeming another link. The same pane offers a terminal-command
alternative if you do not want to install the desktop app. Opening the link in a
browser or phone signs in that client without starting a local daemon.

### Option B — Personal Home on your own computer or VPS

Create a Personal Home locally or over SSH, while keeping agent machines separate if you prefer:

1. Install the CLI, then create the Home:

   ```bash
   happier home create
   # or
   happier home create --ssh user@host
   ```

2. Follow the printed pairing guidance. Use `happier home pair-device` later to start a new short-lived QR/link session.

3. Optionally run `happier home link-account` so your selected sign-in service can discover the Home later. The sign-in service never carries normal Home traffic.

4. In the desktop app, decide which machine should run the background service:
   - **This computer**: use the **Setup wizard** → **Set up this computer**.
   - **Another machine**: use **Add machine over SSH** from the Machines settings screen or save a reusable Remote host first.

If you need a CLI fallback for a background-service host, connect it to the existing Home:

```bash
happier setup --home <saved-home> --skip-providers
```

This is the terminal guided executor for the same outcome as the app wizard.
If the machine was already set up and later drifted, run `happier doctor repair` instead of repeating first-time setup.

If you want to bootstrap a *remote machine* over SSH instead, use:

```bash
happier machine enroll --ssh user@host
```
If you want to use a strict Iroh-only descriptor on a fresh machine, pass `--home-descriptor-file <path|->`. Manual HTTPS remains available through `--home-url`.

### Option C — Generic/operator server runtime

Operators can still deploy the generic server runtime with `happier relay host install`, Docker, or the runner. This is an advanced hosting path: it does not create an account, close signup, enroll a device, or convert the runtime into a Personal Home. Optional LAN, Tailscale, Cloudflare, and public HTTPS ingress remain documented under [Relay access](/apps/relay-access).

Every client must be able to reach an operator-managed server. Tailscale
requires both devices on the same tailnet and a server actually published with
Tailscale Serve or listening on a reachable Tailscale address. LAN access
requires a non-loopback listener and firewall access. A server bound to
`localhost` inside a VM is local to that VM, not to the Mac or PC hosting it.

### One box that hosts a Home and runs Agents

Compose the two canonical commands rather than asking machine setup to create a Home:

```bash
happier home create --ssh user@host
happier --server <saved-home> machine enroll --ssh user@host
```

The older `--install-relay-runtime` machine option remains an advanced compatibility path for generic runtime installation. It does not bootstrap a Personal Home.

Recommended for first setup:

- Check the Home identity before approving a new machine or device.
- Use the desktop app as the main control panel for background-service setup and repair actions.

## Multiple Homes (personal + company)

- The app and CLI support **multiple saved Home profiles**.
- Credentials/state are **scoped per Home**, so switching does not overwrite other accounts.
- Switching Homes selects the Account stored on that Home; it does not migrate an Account, sessions, or settings between Homes.
- Stable Home identity, not a mutable URL, keeps routing changes attached to the same saved Home.
- Web: you can switch the Home **for this tab** or **make it the device default**.

### CLI: target a server per invocation

```bash
happier --server company auth login
happier --server company service start
```

### CLI: run multiple background services on one machine (one per Home)

```bash
happier --server personal service install --instance personal
happier --server company service install --instance company
```

Then verify (cross-platform):

```bash
happier service list
happier --server personal service status --instance personal
happier --server company service status --instance company
```
