title: Onboarding

Happier always follows the same high-level flow:

1. **Choose a Relay** (Happier Cloud by default; self-hosting is optional).
2. **Sign in / create an account** on that Relay.
3. **Use the desktop app as your control panel** (recommended; the web UI is best for status/management).
4. **Get a machine ready**:
   - **This computer**: configure the local background service from the app.
   - **Remote machine**: bootstrap it over SSH from the app, and optionally save the SSH target as a reusable Remote host.
5. **Optionally enable private access** (for example Tailscale) for self-hosted/local Relay access from other devices.

User guide: [Relay access](/apps/relay-access).

## Choose your setup

### Option A — Hosted (recommended to start)
You use Happier Cloud as your Relay.

1. Open the desktop app (recommended) or the web app.
2. Choose **Happier Cloud** when the app asks you which Relay to use.
3. Sign in.
4. Open the **Setup wizard** and choose **Set up this computer**.
   - This configures the local background service against the Relay you just selected.
   - If the app detects Relay drift later, it shows a repair action instead of silently leaving the background service on another Relay.
   - If you are restoring an already-signed-in device, use **Login with secret key instead** on the mobile login screen.

Optional CLI path:

```bash
# Node-free (recommended): install the CLI binary via the official installer
curl -fsSL https://happier.dev/install | bash
# The interactive installer starts setup automatically. Resume it if needed:
happier setup
```

The app-first setup is the recommended control-panel flow. The CLI is a great fallback when you want one-command setup from a terminal. Both settle the Relay before sign-in; the CLI delegates each step to the existing Relay, auth, service, Agent, and Relay-access commands. `happier setup plan` only previews the steps.

Notes:
- The desktop app and the installer-installed CLI are self-contained; you do not need system Node/Yarn installed.
- If you prefer an npm workflow, see [CLI install](/apps/cli) (requires Node).

### Option B — Self-host Relay only (background service on your laptop)
You run your own Relay (remote machine, LAN box, or even your own computer), but keep the background service on another machine.

1. Install your Relay (examples):
   - Proxmox: see [Proxmox deployment](/self-hosting/proxmox).
   - Any machine (managed service): install the CLI, then run `happier relay host install` (or remote: `happier relay host install --ssh user@host`). To install as a system-wide service, use `--mode system` (requires root/sudo). For a local Relay, use `--lan`, `--expose`, or `--host <ip>` when it should listen beyond loopback.
   - Docker: see [Deployment → Docker](/self-hosting/docker).

2. Open the desktop app (recommended) or web UI (status/management only) and choose that Relay.
   - Some installers print one-click links/QRs that prefill the Relay URL.
   - Otherwise, open the app and add/select it in **Relay settings**.

3. Create an account / sign in on that Relay.

4. In the desktop app, decide which machine should run the background service:
   - **This computer**: use the **Setup wizard** → **Set up this computer**.
   - **Another machine**: use **Add machine over SSH** from the Machines settings screen or save a reusable Remote host first.

If you need a CLI fallback for the background-service host:

```bash
happier setup --relay-url https://YOUR_SERVER_URL --skip-providers
```

This is the terminal guided executor for the same outcome as the app wizard.
If the machine was already set up and later drifted, run `happier doctor repair` instead of repeating first-time setup.

If you want to bootstrap a *remote machine* over SSH instead, use:

```bash
happier machine setup --ssh user@host
```
If you want to save a reusable Relay profile for future CLI commands, see [CLI → Server profiles](/apps/cli#server-profiles).

### Option C — Devbox (Relay + background service on the same machine)
You install both the Relay and the background service on one box.

1. Install the stack (for example via `hstack setup-from-source --profile=selfhost` or the Proxmox “devbox” option).
2. Open the desktop app (recommended) or web UI (status/management only) and choose that Relay (use the printed configure-server link/QR if available).
3. Sign in / create an account.
4. In the app, use the **Setup wizard** → **Set up this computer** if you are on that machine, or set up the box over SSH if you are operating it remotely.
5. If the Relay is local/self-hosted, optionally enable private access so phones and other devices can reach it without exposing it publicly.

Recommended for first setup:

- Use the same Relay on every device before linking more machines.
- Use the desktop app as the main control panel for background-service setup, Relay runtime control, and repair actions.

## Multiple Relays (personal + company)

- The app and CLI support **multiple saved Relay profiles**.
- Credentials/state are **scoped per Relay**, so switching does not overwrite other accounts.
- Accounts are per Relay. Using the same login provider on two Relays still creates two independent server-side account contexts.
- Web: you can switch the Relay **for this tab** or **make it the device default**.

### CLI: target a server per invocation

```bash
happier --server company auth login
happier --server company service start
```

### CLI: run multiple background services on one machine (one per Relay)

```bash
happier --server personal service install
happier --server company service install
```

Then verify (cross-platform):

```bash
happier service list
happier --server personal service status
happier --server company service status
```

For complete profile/switching behavior and CLI reference, see [Features → Multi-server](/accounts/multi-server).
