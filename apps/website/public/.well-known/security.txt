# WHAT IS DELIBERATELY NOT HERE
# ---------------------------------------------------------------------------
#
# `Encryption:` is absent, and the release key must NOT be put there.
#
#   https://happier.dev/happier-release.pub is a MINISIGN key
#   (untrusted comment: minisign public key 91AE28177BF6E43C). RFC 9116's
#   Encryption field is for a key a researcher can ENCRYPT A REPORT TO.
#   minisign only signs and verifies — it has no encryption operation at all.
#   Listing it would advertise a capability that does not exist and send
#   researchers into a dead end. If encrypted reports are wanted, publish a real
#   OpenPGP or age key and reference that instead.
#
#   The minisign key's actual job is release-artifact verification: install.sh
#   fetches it from HAPPIER_MINISIGN_PUBKEY_URL (default
#   https://happier.dev/happier-release.pub) and verifies every downloaded
#   artifact with it — see apps/website/public/install.sh:26-32 and the
#   ensure_minisign() bootstrap at :2118. RFC 9116 has no field for a release
#   signing key, so it is documented here in prose rather than mislabelled.
#
# `Contact: mailto:` is absent because no security mailbox has been verified to
# exist for this domain. A security.txt that names an address which bounces is
# worse than one that names none — the report is lost silently and the reporter
# assumes it landed. GitHub's private vulnerability reporting is used instead:
# it is authenticated, private, gives the reporter a receipt, and is already
# enabled on the repository (verified: /security/policy returns 200).
#

# Contact line (RFC 9116 orders by preference) and drop this paragraph:
