## Primeros pasos

### 1. Instálalo en tu ordenador

La forma recomendada de empezar es la app de escritorio: configura la CLI y el daemon por ti.

<details>
<summary><b>¿Prefieres la terminal?</b> Instala la CLI y el daemon sin la app de escritorio</summary>

macOS/Linux:

```bash
curl -fsSL https://happier.dev/install | bash
```

Windows:

```powershell
iwr https://happier.dev/install.ps1 -useb | iex
```

Si prefieres el paquete de npm: `npm install -g @happier-dev/cli` ([documentación de la CLI](https://docs.happier.dev/apps/cli)).

</details>

<details>
<summary><b>¿Lo instalas en un ordenador remoto o en un devbox?</b> Configúralo por SSH desde tu máquina</summary>

Un solo comando instala la CLI y el daemon en el host remoto (con la firma de la versión verificada) y lo registra como una de tus máquinas:

```bash
happier machine setup --ssh user@host
```

Para iniciar sesión en la máquina remota sin usar un navegador en ella, ejecuta esto desde una máquina en la que ya hayas iniciado sesión:

```bash
happier auth pair-remote --ssh user@host
```

Alternativa headless en el propio host remoto: `happier auth login --no-open --method web` muestra una URL de autorización que puedes aprobar desde cualquier navegador. [Máquinas y el daemon](https://docs.happier.dev/apps/daemon)

</details>

Inicias sesión desde la app o la primera vez que lo ejecutas.

### 3. Inicia una sesión

**En la app →** Pulsa **Nueva sesión** y elige la máquina, la carpeta y el agente. No hace falta terminal.

**O en la terminal**, desde cualquier carpeta de proyecto:

```bash
happier            # Claude Code
happier codex      # Codex
happier opencode   # OpenCode
```

En ambos casos, la sesión aparece a la vez en todas partes: sigue escribiendo en la terminal, sigue el progreso y aprueba desde tu móvil, y revisa en el navegador. `happier --help` muestra los demás agentes y comandos.

## Cómo funciona Happier

```
      Phone           Desktop          Browser
        │                │                │
        └────────────────┼────────────────┘
                         │
                         ▼
          Happier relay (hosted or yours)
        syncs end-to-end encrypted sessions
          between your devices and machines
                         │
                         ▼
      Your machines (laptop, desktop, VPS, dev box)
        the Happier daemon starts and manages
          agent processes where your code lives
                         │
                         ▼
      Claude Code · Codex · OpenCode · Pi · ...
        each agent talks to its own model
                provider directly
```

El relay almacena y reenvía contenido que no puede leer: el contenido de las sesiones se cifra en tus dispositivos antes de llegar al servidor. El servidor solo procesa lo que necesita el enrutamiento, como los ids de sesión, las marcas de tiempo, el estado de los turnos y los metadatos de uso. Tus agentes siguen comunicándose directamente con sus proveedores de modelos.

<a id="self-hosting"></a>
## Autoalojamiento

Ejecuta tu propio relay con un solo comando:

```bash
happier relay host install --mode system
```

Esto instala y mantiene actualizado un servicio de relay gestionado en la máquina actual. Para un host remoto: `happier relay host install --ssh user@host --mode system`.

La [documentación de autoalojamiento](https://docs.happier.dev/self-hosting/self-host-runtime) (también accesible en [happier.dev/self-host](https://happier.dev/self-host)) cubre los detalles, con [Docker](https://docs.happier.dev/self-hosting/docker) y [Proxmox](https://docs.happier.dev/self-hosting/proxmox) como alternativas.

<a id="security"></a>
## Seguridad

- **El contenido está cifrado de extremo a extremo por defecto.** El código, los prompts, los mensajes y las transcripciones se cifran en tus dispositivos antes de llegar a cualquier servidor. [Cifrado](https://docs.happier.dev/security/encryption)
- **El servidor procesa los metadatos de enrutamiento.** Los ids de sesión, las marcas de tiempo, el estado de los turnos y los metadatos de uso son visibles para el relay, para que pueda sincronizar tus dispositivos.
- **Quien opera un servidor autoalojado elige su política de almacenamiento.** Un servidor autoalojado se puede configurar con otras políticas de almacenamiento para su despliegue. [Ajustes de cifrado del servidor](https://docs.happier.dev/self-hosting/encryption)
- **El tráfico con los modelos se queda en tus agentes.** Cada agente se comunica directamente con su propio proveedor de modelos.

Más información en la [documentación de seguridad](https://docs.happier.dev/security).

### Canales de versiones y builds nightly

Todo lo anterior instala el canal **stable**. Hay dos canales más rápidos que van por delante, y se instalan uno al lado del otro (`happier`, `hprev`, `hdev`), así que probar uno nunca rompe tu instalación stable:

- **preview**: las novedades llegan aquí primero, antes que a stable.
- **dev**: builds nightly con los últimos cambios. Pueden contener commits parciales y romperse en cualquier momento.

<details>
<summary><b>Instalar builds preview o dev</b></summary>

Preview (macOS/Linux y, después, Windows):

```bash
curl -fsSL https://happier.dev/install-preview | bash
```

```powershell
iwr https://happier.dev/install-preview.ps1 -useb | iex
```

Dev:

```bash
curl -fsSL https://happier.dev/install-dev | bash
```

```powershell
iwr https://happier.dev/install-dev.ps1 -useb | iex
```

Después ejecuta **`hprev`** o **`hdev`** en lugar de `happier`. Si quieres que `happier` apunte a tu canal dev, añade `alias happier='hdev'` a tu `.bashrc`/`.zshrc`.

En `dev` tienes que usar todo de las versiones dev (CLI, app, daemon y servidor): la nube alojada (cloud.happier.dev) ejecuta `stable`, así que las funciones de `preview` y `dev` pueden no funcionar con ella, y `dev` no tiene app web alojada (autoaloja el servidor dev para usar la interfaz web dev).

## ¿Por qué “Happier”?

Empezamos como contribuidores de [Happy](https://github.com/slopus/happy), enviando correcciones, mejoras y nuevas funciones upstream.

Lo usábamos a diario en el trabajo y nos encantaba la idea.
Con el tiempo, nos dimos cuenta de que nuestras propias necesidades pedían iterar más rápido de lo que podíamos explorar cómodamente dentro del proyecto principal.

Así que empezamos a construirlas para nosotros.

Tras semanas puliendo, corrigiendo y ampliando la base, decidimos compartir Happier para que otras personas pudieran probarlo, usarlo y ayudar a decidir lo que viene.

Happier busca explorar una dirección más ágil y colaborativa, sin dejar de estar profundamente agradecidos por la base que nos dio Happy. Nos encantaba Happy y nos sigue encantando. ❤️ Happier no existiría sin él.
