# Coder Machines (development only, unreleased)

This plugin creates Coder workspaces and enrolls them through Happier’s shared native Machine bootstrap. Lifecycle requests use the selected deployment’s REST API; private guest IO uses the controller’s `coder` executable through Happier’s managed-dependency owner. The implementation is characterized against Coder v2.39.0.

Install the Coder CLI matching your Coder deployment on the Happier controller and make `coder` available on its PATH. Follow the [official CLI installation instructions](https://coder.com/docs/install/cli); your deployment also provides its matching installer at `<deployment>/install.sh`. Happier checks the existing installation and reports an actionable refusal when it is missing. This version does not download or update the CLI automatically.

To host a Coder server on a Linux Machine with APT and systemd, select the **Coder** software recipe in Machine setup. Install Docker Engine first for Docker-based workspaces. The recipe installs Coder v2.39.0, writes the supplied external HTTPS URL, and starts the service on loopback port 3000; configure your HTTPS reverse proxy separately. Removing the recipe stops the service and retains the package and workspace data. Hosting the server on this Machine does not establish where a template provisions its workspaces.

Connect **Coder account** with your deployment’s root HTTP(S) URL and a per-user token. Changing the URL requires reconnecting. Connecting validates the deployment URL locally and stores your token. The selected controller authenticates against Coder when access is checked or used; a rejected token requires reconnecting. Credentials remain in host-managed Account storage, request headers and private process environment; the plugin does not run `coder login` or place the token in arguments or launch parameters.

For a new deployment, **Create first administrator** in Coder account accepts an HTTPS origin, username, email and password. It creates the first Coder user and signs in through Coder v2.39.0’s native API. The password is used only for this invocation; Happier retains the returned session token through the connected-service owner. Coder’s configured session lifetime applies. If a reply is lost, retry with the same credentials or connect with a Coder user token. This mode never changes an existing administrator’s password. Browser clients use the selected Machine for this private-deployment request.

Choose your organization, template and exact agent name in the existing workspace options editor. A blank template version selects the current active version when options are fetched; the selected version is retained in the launch. Enter rich parameter values as JSON, for example `[{"name":"project","value":"my-project"}]`. An optional template-version preset supplies values; explicit values override preset values, which override template defaults. Required parameters without defaults remain unavailable until supplied. Terraform’s dynamic and conditional forms remain Coder-owned. Template images are the only native option dimension; resize is unsupported in this first version.

The optional **Where this template runs workspaces** setting declares the selected template’s workspace host. Select **This Machine** only after checking where its Terraform creates compute. A local Coder server or a private deployment URL does not establish workspace locality. **Another Machine or cloud** and an unspecified host do not qualify for a local Sandbox; add remote workspaces as Machines instead. Choosing another template clears the host declaration. This template configuration does not qualify guest kernel capabilities, so the plugin does not advertise nested Agent-native sandbox support.

The launch contains `organizationId`, `templateId`, `templateVersionId`, `agentName`, `parameterValues`, and optional `presetId` and `workspaceHost`. The shared placement owner reads `workspaceHost`; billing remains a separate fact. Resource records retain workspace, owner, organization, template and agent identity. Acquisition waits for an accepted native create build to settle before binding the workspace. Cancellation or an unavailable observation retains the pending acquisition for the existing recovery action. Recovery uses the retained workspace ID or exact owner-qualified managed workspace name and never blindly creates another workspace after a lost response. If Coder cannot establish whether creation happened, Happier preserves the uncertainty instead of claiming absence.

Coder v2.39.0 supports [prebuilt workspace pools](https://coder.com/docs/admin/templates/extending-templates/prebuilt-workspaces/) with a Premium license and `coder/coder` Terraform provider `>= 2.4.1`. Configure prebuilds on your template in Coder, then select that template-version preset in Happier. Workspace creation passes its ID to Coder, which claims an eligible prebuild or creates a fresh workspace when none is eligible. A configured target count is not evidence of ready capacity; a zero base target can still have scheduled capacity. Only unsatisfied setup runs afterward; choosing **No Setup** skips CLI installation. If the preset has no prebuild configuration, set prebuilds in Coder to use this capability. Happier does not author or rewrite Terraform, clone signed-in workspaces, or delete Coder's shared prebuild pool. Deleting an acquired workspace uses the existing owner-qualified workspace lifecycle. This native selection is distinct from Happier-managed image baking through Prepare.

Start and stop use native builds. Stop settles only after both its build and workspace report the intended power state. A stopped workspace remains present; an agent disconnect does not change its native running power state. Template policies own autostop, dormancy, retention and billing. This plugin never bumps activity or automatically clears dormancy, and does not claim that stopped compute or storage is free or retained. Delete submits a native delete build; accepted or lost responses retain a cleanup operation until native absence is observed.

This first version requires a Linux guest with POSIX `sh` and an absolute guest home. The controller platform list does not promise Windows or macOS guest support. The plugin chooses the explicitly named agent, uses non-PTY SSH, and disables autostart whenever the host disallows wake. Binary stdin, stdout and stderr and native exits pass through the host ExecService. Files travel through private stdin. Shared bootstrap owns installation, pairing and daemon startup; Coder’s agent environment overrides are handled through private `CODER_SSH_ENV` and a static guest wrapper. Cancellation terminates the local Coder invocation and cannot become successful process configuration. Coder may leave remote descendants running; native workspace Stop remains the owner of that lifecycle.

New workspaces enroll under the account supplied by the Coder agent. The daemon runs as a native process in that account's home. Dedicated enrollment requires a guest with a running Linux user-service manager and an administrator that can prepare the dedicated account.

The controller is declared for Linux, macOS and Windows. Focused HTTP and fake executable tests run on Linux; the live deployment journey and other controller platforms require their own validation. Browser clients delegate to the selected controller through the existing host options and Machine paths.
